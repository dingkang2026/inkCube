# 2.11 定时任务设计 — 订阅式情报采集与阅读

> 周期性自动执行任务模板（企业舆情 / 竞品动态 / 产业情报），产出**可查看、可阅读、可沉淀**。
> 本文按 [0.5 §8](0.5product-redesign.md) E3 立项，覆盖 §2.8 三要素：表结构（§3）、数据流（§7）、前端交互（§8/§9）。
> 关联：[1.1](1.1task-agent-design-unified.md) 任务执行链（复用，零双轨）、[0.4](0.4lifecycle-design.md) 长时活动与通知、[0.5 §4.4](0.5product-redesign.md) 任务模板体系。

---

## 1. 概述

### 1.1 目标

| # | 目标 | 衡量 |
|---|------|------|
| G1 | 周期性自动执行：订阅创建后无需人工干预按时产出 | 到点触发率（应用运行期）= 100% |
| G2 | 产出便于阅读：每次产出 3 秒内可看到「本期要点」，一次点击读全文 | 阅读动线 ≤ 2 步（通知/速览 → 全文） |
| G3 | 产出自动沉淀：报告落入项目素材/基础库，可检索 | 导入后素材 Tab 可检索到 |
| G4 | 失败可见：连续失败自动暂停并明确告知，禁止静默失败 | 失败 3 次内必有通知与暂停 |
| G5 | 资源友好：定时执行不影响用户电脑正常使用（让路人工任务与下载、单并发、静默通知） | §5.6 四项约束全部生效；人工任务/模型下载运行期间无定时 run 新启动 |

### 1.2 非目标

- 不做应用未运行时的后台采集（墨方是桌面应用，调度仅在前端应用运行期生效；补偿策略见 §5.4）。
- 不做秒级/分钟级高频调度（情报场景最小粒度为「每天一次」，tick 精度 60s 足够）。
- 不做新执行引擎——定时执行 = 「到点自动发送 prompt 的任务」，全链复用 [1.1](1.1task-agent-design-unified.md)。

### 1.3 核心裁决

| 裁决 | 内容 | 理由 |
|------|------|------|
| D1 | 不引入 APScheduler 等第三方调度库，主进程内自研 asyncio 循环（60s tick） | 依赖评估（规范 §三）：PyInstaller 打包兼容性风险与体积；自研循环 ≈ 百行内，需求仅「分钟级 + 持久化下次执行时间」 |
| D2 | 引擎同链、交互分离：执行锚点 = 一条后台影子 `tasks` 行（`schedule_id` 关联），复用 chat 执行链；**但任务列表默认排除影子任务**（同 PPT origin 任务不入列的既有先例，[1.1 §10.2](1.1task-agent-design-unified.md)）。定时执行在 UI 上是「档案」（只读回放），人工任务是「工作台」（可对话） | 引擎零双轨（准入/闸门/SSE/断点/活动注册现成）；避免周期 run 淹没人工任务列表（3 订阅×周 = 年 150+ 行）；管理/查看以订阅为唯一主体（用户裁决 2026-10-18） |
| D3 | 订阅运行期不新增活动 kind——活跃反馈沿用 `useActivity('task')` | 执行就是任务；运行中卡片/角标/Toast 全部现成；任务 Tab 运行角标计入影子任务（真实占用并发闸门，需可见） |
| D4 | 产出报告结构约定（摘要前置 + 来源清单）写入订阅 prompt（用户可改），阅读视图据此解析摘要卡 | 阅读体验的根因在产出结构，不在渲染端兜底解析 |
| D5 | 报告完成时在 `data/schedules/{run_id}.md` 存**报告副本**，阅读视图优先读副本；影子任务 workspace 按「保留最近 N 期」自动清理 | 阅读生命周期与 workspace 清理解耦：workspace 是执行资源（可清），报告是档案（长期可读，一年数百个 md 仅数百 KB）。「长期可读」指与 workspace 清理解耦而非永久保存——副本随 run 行保留期清理（§6 报告副本，B5 2026-10-20 补） |

## 2. 概念模型

```
订阅 Schedule（周期 + prompt + 产出去向）
   │ 到点触发
   ▼
执行 Run（= 一条 tasks 行 + 一条 run 历史）
   │ chat 执行链（general 模式，browser-fetch/web_search 采集）
   ▼
产出报告（workspace 内 md：摘要 + 正文 + 来源）
   │ 终态回调：解析摘要 → 写 run 行
   ▼
阅读层（四条动线，§8）：通知 Toast / 首页情报速览 / 任务列表定时分组 / 项目素材沉淀
```

- **订阅**：一次配置、周期执行。字段见 §3。
- **执行（Run）**：每次触发创建一个**后台影子任务**（标题「{订阅名} · M/D」，schedule_id 关联，不入人工任务列表，D2），`task_schedule_runs` 记一行历史。用户视角的执行记录 = 订阅中心里的 run 历史，任务列表不出现定时执行。
- **阅读层**：Run 完成后可被四条动线触达，最终都落到**阅读视图**（§8.2）。

## 3. 表结构

> 项目未上线无存量数据（规范 §一）；`tasks.schedule_id` 为迁移列，规范同 [1.1 §10.1](1.1task-agent-design-unified.md)（建表后 ALTER，对不存在静默跳过）。

```sql
-- 订阅表（python/db/database.py）
CREATE TABLE task_schedules (
    id          TEXT PRIMARY KEY,            -- 'sch_<uuid>'
    name        TEXT NOT NULL,               -- 用户可读名（默认「{模板标题}·{对象}」可改）
    prompt      TEXT NOT NULL,               -- 填好占位符的完整 prompt（含产出结构约定，§8.3）
    mode        TEXT NOT NULL DEFAULT 'general',  -- 固定 general（情报采集无编码需求）
    category    TEXT NOT NULL DEFAULT 'general',  -- 分类（管理台筛选）：模板创建时由模板带出（industry/corporate/...），自由输入可选
    interval_type  TEXT NOT NULL,            -- daily | weekly | monthly
    interval_value TEXT NOT NULL,            -- daily: "09:00"；weekly: "MON,THU 09:00"；monthly: "1,15 09:00"
    target_type TEXT,                        -- 'project' | 'baselib' | NULL（不自动沉淀）
    target_id   TEXT,                        -- 项目/基础库 id（target_type 非空时必填）
    archive_file_id TEXT,                    -- 情报档案在目标容器的 file id 锚点（§6 合并时清旧传新；未绑定去向为 NULL）
    archive_last_run_id TEXT,                -- 档案已合并到的最近 run id（失败补并锚点；LLM 合并成功后回填）
    auto_import INTEGER NOT NULL DEFAULT 1,  -- 期次完成后自动合并入档案（§6）
    enabled     INTEGER NOT NULL DEFAULT 1,  -- 0 = 已暂停（含连续失败自动暂停）
    next_run_at TEXT,                        -- ISO 时间；enabled=0 时为 NULL
    last_run_at TEXT,
    consecutive_failures INTEGER NOT NULL DEFAULT 0,  -- ≥3 自动暂停（§5.5）
    created_at  TEXT NOT NULL,
    updated_at  TEXT NOT NULL
);

-- 执行历史（阅读视图的数据源）
CREATE TABLE task_schedule_runs (
    id          TEXT PRIMARY KEY,            -- 'run_<uuid>'
    schedule_id TEXT NOT NULL REFERENCES task_schedules(id) ON DELETE CASCADE,
    task_id     TEXT REFERENCES tasks(id) ON DELETE SET NULL,  -- 任务被删后历史仍可读（task_id 空）
    status      TEXT NOT NULL,               -- running | done | failed | skipped | missed
    report_path TEXT,                        -- 报告副本路径（data/schedules/{run_id}.md，done 时回填；与 workspace 生命周期解耦，D5）
    summary     TEXT,                        -- 摘要要点 JSON 数组（解析自报告「## 摘要」节，done 时回填）
    read_at     TEXT,                        -- 已读时间（NULL=未读；ReadView 打开即回填；收件箱/红点/摘要行计数数据源）
    started_at  TEXT,
    finished_at TEXT
);
CREATE INDEX idx_runs_schedule ON task_schedule_runs(schedule_id, started_at DESC);
CREATE INDEX idx_schedules_next ON task_schedules(enabled, next_run_at);
CREATE INDEX idx_runs_inbox ON task_schedule_runs(status, finished_at DESC);  -- 跨订阅收件箱流

-- tasks 扩展（迁移列）
ALTER TABLE tasks ADD COLUMN schedule_id TEXT REFERENCES task_schedules(id) ON DELETE SET NULL;
```

**读写定位**：

| 表 | 写 | 读 |
|----|----|----|
| task_schedules | 订阅 CRUD（UI）；调度器 tick 后更新 next_run_at / last_run_at / consecutive_failures / enabled | 调度器扫描；管理台左列（category/enabled/q 服务端过滤）；首页情报速览（分组名） |
| task_schedule_runs | 触发时插 running 行；终态回调更新 status/report_path/summary/finished_at；ReadView 打开回填 read_at | 阅读视图摘要卡；管理台期次面板/收件箱；情报速览最新一条 |
| tasks | 复用现有（chat 链路创建），额外写 schedule_id | 任务列表「定时」分组（WHERE schedule_id IS NOT NULL） |

## 5. 调度器（python/scheduler.py，主进程内）

### 5.1 生命周期

FastAPI startup 创建 asyncio task（`scheduler_loop`），shutdown 时 cancel。循环体：60s 间隔 tick → 扫描 `enabled=1 AND next_run_at <= now` → 逐个触发（串行派发，不阻塞 tick；**单项隔离**（review P2-2）：单个订阅触发异常 try/except 不阻塞其余订阅与循环）。启动时先做错过补偿（含崩溃残留清扫，见 §5.4；**整体兜底**（R2-P1-1）：补偿阶段意外不在单项隔离内的异常同样捕获记日志——`_task` 非 None 时 start() 不重建，loop 死亡即全部订阅停摆且重启复现，不得因脏数据发生）。

### 5.2 触发判定

| 条件 | 行为 |
|------|------|
| 上一次 run 仍 `running` | 本次记 `skipped`（防重入），next_run_at 正常推进 |
| 全局任务闸门满（MAX_CONCURRENT，[1.1 §7.4](1.1task-agent-design-unified.md)） | 延迟到下个 tick 重试（next_run_at 暂不推进，避免跳过） |
| 正常 | 创建任务（POST chat 同链路）→ 插 running 行 → 推进 next_run_at |

### 5.3 执行链（复用 D2）

触发 = 调度器进程内直调 agent 执行链（与 POST /tasks/{id}/chat 同链等价，不走 HTTP 自调用）：任务创建（title = 「{订阅名} · M/D」，mode=general，schedule_id 落列）→ try_acquire 准入（含 dispatch 检查与执行间闸门被人工任务抢占的竞态分支，被占按失败终态）→ 闸门 → 事件流（无前端会话消费，仅落库）→ 终态。**运行期反馈全部现成**：项目无关任务入运行名单 → 任务 Tab 角标 +1、完成 Toast（[0.4 §5.5](0.4lifecycle-design.md)）。

**确认直行（2026-10-22）**：影子任务（schedule_id 非空）五类确认（shell / code_executor / skill_runner / git commit / 外部 skill 首用）全部静默直行，覆盖用户三档确认设置——无人值守无应答方，逐条确认只会空等 120/180s 后按拒绝跳过，每期白耗等待预算；语义与 ppt 任务静默链同构，机制与超时回归详见 [1.1 §7.1](1.1task-agent-design-unified.md)。

### 5.4 错过补偿（应用未运行期间）

启动时扫描 `next_run_at < now` 的 enabled 订阅（**单项隔离**（R2-P1-1）：逐条处理均 try/except——一条脏数据（如 next_run_at 非法日期、坏 interval 使 compute_next_run 报 KeyError）只跳过自身记日志，不饿死同批其余订阅，更不杀死 _loop）：

| 过期时长 | 行为 |
|----------|------|
| ≤ 24h | 补跑一次（串行，间隔 30s，防开机并发轰炸） |
| > 24h | 跳过：run 行记 `missed`，直接推进 next_run_at；同 tick 内多条 missed 合并一条通知（「3 个订阅因长期未运行已跳过」） |

理由：情报价值随时间衰减，24h 前的「周报」已无意义；但静默跳过违反 G4，必须留痕留通知。

**崩溃残留清扫**（review P0-1）：启动扫描时一并处理 `status=running` 的孤儿 run 行（应用上次未正常退出遗留——无后台任务在跑，R1 闸门被占则全部订阅停摆）：就地置 `failed`（error 注明应用中断）；同订阅多条合并为一条 `interrupted` 汇总通知（区别于 missed：非跳过而是中断），避免逐条刷屏。

### 5.5 终态回调与失败熔断

任务终态（done/error）→ 回调调度器：

| 终态 | 行为 |
|------|------|
| done | run 行更新 status/report_path/summary（解析报告「## 摘要」节，§8.3）；consecutive_failures 归零；target 非空且 auto_import=1 → 档案合并（§6，持档案互斥锁，每批上限 10 期 ARCHIVE_MERGE_BATCH，失败补并多期时分周期补完）；完成通知按 R4 分级（默认静默：通知中心记录 + 速览更新，不弹 Toast；设置项开启后照弹） |
| failed | consecutive_failures + 1；**≥3 → enabled=0（自动暂停）+ 弹 Toast「订阅「{名}」连续 3 次失败已暂停，请检查网络或模型配置」**；next_run_at 保留；手动恢复（PATCH enabled 0→1，含 toggle 批量恢复）时计数归零（R2-P2-4，否则恢复后首次失败立即再熔断）——恢复后从下个周期继续 |

> **终态回调保护**（review P0-2）：_on_finish 异常不得逃逸（后台任务无人 retrieve → run 永卡 running → R1 闸门被占 → 全部订阅停摆）：捕获后按失败终态收场（行仍 running 时置 failed「终态回调异常」，幂等不覆写已终态行），双层防御防兜底自身抛。

### 5.6 资源友好性（G5，不影响用户正常使用）

| # | 约束 | 实现 | 验收 |
|---|------|------|------|
| R1 | 定时单并发：全局同时最多 1 个定时 run 在跑（与人工任务并发闸门独立收紧） | 调度器内部互斥锁：持有者未释放则后续触发记 deferred，下个 tick 重查 | 人工任务 ×3 并发 + 定时 run 同时存在时，定时仍只有 1 |
| R2 | 忙时让路：存在运行中**人工任务**或**模型下载**时，定时触发推迟（deferred，不丢不丢周期——next_run_at 不推进，每 tick 重查，空闲即跑） | 忙信号 = `tasks:status` running 中非 schedule_id 任务 >0 或 model_download 活动 isActive；两个信号 Python 侧现成 | 人工任务运行期间定时不启动；结束後下个 tick 内自动开跑 |
| R3 | 子进程低优先级：任务 venv 的 shell/python 子进程以低优先级启动（Windows `BELOW_NORMAL_PRIORITY_CLASS`，POSIX `nice 10`），前台交互天然抢占 | 已落地：`tools/proc_priority.low_priority_kwargs` 接线执行链五个 spawn 点（shell / code_executor / package_manager / venv 创建与预装 / Skill 脚本），全局生效（人工任务同样受益，OS 前台调度天然优先） | 定时采集运行中，前台操作无可感知卡顿 |
| R4 | 通知分级：定时产出完成**默认静默**（通知中心记录 + 速览行更新，不弹 Toast）；失败/熔断/补偿跳过才弹 Toast；设置项 `schedule_notify`（silent / toast，默认 silent） | 已落地：设置页 GeneralSettings 开关（SettingsModel / defaults 白名单键，POST /settings 不丢）+ ActivityMonitor 消费（dispatchToasts 跟随设置：settings:get 读 + settings-changed 重读）；failed/熔断/interrupted 恒弹不受开关影响 | 默认配置下定时完成无弹窗；失败必弹 |

> 不做「执行时间窗」设置：R1/R2 的让路机制已覆盖「忙时不扰」；时间窗属锦上添花，登记为未来方向（需真实使用反馈再定形态），非遗留决策。60s tick 天然覆盖休眠唤醒场景（唤醒后最多 60s 内接管），无特殊处理。

## 6. 产出沉淀与资源治理（情报档案制，复用 E2 导入通道）

**沉淀形态：情报档案制（2026-10-18 三次裁决）**——动态流的沉淀不是「每期一份文件」，而是每订阅在目标容器维护**一份持续累积的情报档案**：

- 档案文件：`{订阅名}·档案.md`，结构 = 头部元信息（订阅名/周期/沉淀起始）+ `## 时间线`（每期一节 `### YYYY-MM-DD`：摘要要点 + 正文 + 来源，经 LLM 整合自该期报告 D4 结构）。
- 三形态取舍：逐期文件入库（时间线✓ 但知识库膨胀/检索互稀释/wiki 源臃肿✗）；滚动覆盖只留最新（不膨胀✓ 但时间线丢失✗，已否决）；**档案制**（文档内时间线累积✓ + 恒定 1 文件/订阅✓ + wiki 源干净✓）。
- 合并机制（**LLM 合并**，2026-10-18 四次裁决：机械追加只会堆叠报告堆，档案要像一份连贯文档，必须 LLM 整合）：期次 done 且 target 非空 → **窗口制 LLM 合并**——输入 = 档案头部 + 最近 30 期节 + 待合并期次报告（通常 1 期；失败补并时多期，按序），LLM 指令：新动态并入时间线（新增日期节）、与近期节重复表述精简、状态变化修正对应节；输出 = 修订后的整窗口节 → 机械替换窗口区间写入档案工作副本（30 期以前的早期节原样保留不进 LLM——单次成本恒定 ~4 万 token，时间线完整）→ `archive_file_id` 非空则清目标容器旧档案数据 → 档案重新入库（[0.5 §2](0.5product-redesign.md) 同一底层 `_upload_core`，file 活动）→ 回填 `archive_file_id` / `archive_last_run_id`。未绑定去向 → 只更新工作副本不入库（看过产出后再绑定，绑定即从全部副本重建）。**互斥**（review P1-1）：合并/重建/换向共用档案互斥锁（asyncio.Lock，与在途 done 回调互斥），防并发写档案工作副本交叉损坏；**每批上限**（review P2-5）：单次合并最多 10 期（ARCHIVE_MERGE_BATCH）；**丢节拒绝**（review P2-9）：LLM 输出节数不足窗口 = 丢节（静默落盘会永久丢失期次节且锚点已推进永不补并）→ 拒绝落盘走失败补并；期次节以 `### YYYY-MM-DD` 日期行切分（正文 `###` 子标题不截断日期节）。
- 失败补并：LLM 合并/入库失败不回滚 done、**不更新档案**（archive_last_run_id 不动）：通知单列 kind=`archive_failed`（warning 档 Toast/色点，同 overdue 组）「产出已生成，档案合并失败（原因）」；下期 done 合并时自动补并锚点以来全部未合并期次（按序一次合并）；详情卡去向行「重建档案」可手动触发（POST /schedules/{id}/rebuild-archive → `schedules:rebuildArchive`，仅已绑定去向时显示，2026-10-23 自操作条移入去向行与「查看档案」同域）。
- 分工：档案 = **LLM 整合的时间线原料**（窗口制控制成本，期期连贯）；wiki = **全册认知整合**（LLM 编译素材成册，现有机制）——时间线不丢，从 365 个散文件变为 1 份档案里的 365 个日期节。
- **增量降重在产出侧**（档案不膨胀的前提）：调度执行前，若该订阅存在上期 done 报告副本 → 复制入本期新 workspace（`上一期报告.md`）+ prompt 附加增量指引（「重点报告与上期相比的新增动态，延续内容简要带过」）——影子任务每期全新 workspace 本读不到历史，注入使「每期只写新增」成为可能，档案时间线节才不会重复堆叠。
- **去向时机（确认的正确位置）**：创建订阅时去向**可选**（默认「不沉淀」）；看过产出质量后，在订阅详情卡或编辑弹层第③步随时绑定/更换项目/基础库，绑定即从既有期次副本重建档案（rebuild-archive）——入库决策发生在质量确认之后，而非创建时盲绑。**换向**（review P1-2）：从目标 A 更换到 B 时先清 A 的档案数据（cleanup_file_data 全链：向量 + FTS + 磁盘）再在 B 重建，旧目标不留孤儿档案（R3-P1：清旧 + 置空锚点同步完成、重建转调度器后台任务——schedules:update 15s IPC 超时内返回；后台重建失败经 archive_failed 通知，下期 done 补并/手动重建可续。R4-P1：换向/删除前置取消本订阅在途重建——防连续换向双重回填孤儿档案、删除后孤儿上传与工作副本复活；残余窗口：tick 合并持锁单批数十秒期间换向仍需等锁，全局锁粒度成本）。
- 入库是长时活动（file kind，[0.4](0.4lifecycle-design.md)），无新增 kind。
- wiki 联动（「先删除、重新入库、wiki 编辑」闭环）：target=项目 → 档案重新入库走现有建档链，自动进入项目待编译集合（[2.6](2.6wiki-design.md) 实时口径，无需新增）→ 用户在项目页按需触发编译，最新档案进 wiki；target=基础库 → 无 wiki 消费，档案仅可检索。
- 订阅删除：档案文件在目标容器独立存在（沉淀不受订阅删除影响）；档案工作副本 `archive_{schedule_id}.md` 随订阅删除清理。
- 目标容器删除（验收-P2 对称置空）：删除项目时指向它的订阅 `target_type/target_id` 置空（`db.clear_schedules_target`，auto_import 保留——重新绑定后偏好不变），并合并一条通知（kind=info，列受影响订阅名）——否则订阅每期 `archive_failed` 幽灵警告（产出正常但无处沉淀，根因无处可见）；与「删订阅时 tasks.schedule_id 置 NULL」同构（target_id 无外键，手动等价 ON DELETE SET NULL）。基础库不可经项目删除端点删除，无此场景。

**报告副本（D5）**：done 回调将报告 md 复制到 `data/schedules/{run_id}.md`，ReadView 全文优先读副本（IPC 复用 `tasks:{id}/files/content` 的目录越界白名单思路，schedules 目录单独白名单），workspace 清理不影响阅读；导入目标容器的副本独立存在（沉淀不受订阅删除影响）。副本生命周期 = 所属 run 行：启动保留期维护（`schedule_runs_retention_days`，默认 90 天，0=永不清理，maintenance.cleanup_expired_schedule_runs）删过期 run 时一并 `os.remove` 副本（B5，2026-10-20 审计补——行删后文件成孤儿；路径经 `_is_under(data_dir/schedules)` 锚校验防 DB 值异常时误删任意文件，已删幂等跳过）。

**workspace/venv 保留期**：影子任务的 workspace 与 venv 是执行资源，按「每订阅保留最近 N 期（默认 10，done **与 failed** 均计入保留——failed workspace 可能含排查线索，review P2-8）」自动清理更早的 run 目录（done 回调触发，常量起步，设置化后置）；人工任务的 workspace 生命周期不受影响。全局另有 run 行保留期（`schedule_runs_retention_days`，设置页存储管理，默认 90 天，0=永不清理）：过期 run 的影子任务（delete_task 全链含 workspace/venv）与报告副本随行一并清理（B5）——期数保留（订阅内滚动，保近期排查线索）与天数保留（跨订阅全局硬上限）独立生效，重复命中幂等。

## 7. 数据流

```
【调度链（写）】
scheduler tick（60s）
  → GET 到期订阅 → 创建任务（tasks.schedule_id）+ run(running)
  → POST /tasks/{id}/chat（prompt=订阅 prompt，复用 1.1 全链）
  → SSE 落库（无前台会话）→ 终态
  → 回调：run(done/failed) + 摘要解析 + next_run_at 推进
  → activity_events 终态通知（Toast，文案带订阅名）
  → 档案合并（追加日期节 → 清旧传新入库，file 活动）

【阅读链（读）】
通知 Toast ─┐
首页情报速览 ├→ ReadView（run_id 入参）
管理台 ──────┤    ├─ 摘要卡：runs.summary（直读，零文件解析）
项目素材沉淀 ─┘    ├─ 全文：报告副本 data/schedules/{run_id}.md（D5）→ Markdown 渲染
                   └─ 动作：导入项目/导出/打开执行回放（只读）

【任务列表隔离（D2）】
tasks:list 服务端排除 schedule_id 非空行（与 origin='chat' 过滤同构）——前端零特判；
运行中影子任务仅表达于：任务 Tab 运行角标（计入，真实占闸门）+ 管理台该订阅行呼吸点（侧栏摘要行计数同步）。

【刷新纪律（0.4 §8.1）】
digest：挂载拉一次 + task 终态 completed 事件边沿重拉——零新增轮询
管理台：挂载拉一次 + 边沿刷新（创建/删除/翻 enabled/标记已读后本地更新；inbox 流随 markRead 边沿更新）；期次单条删除后 reload 按当前已加载量重拉（limitsRef 模式，不退回第一页）
```

## 8. 查看与阅读（本设计核心）

### 8.1 四条阅读动线

| 动线 | 入口 | 承载 | 适合 |
|------|------|------|------|
| ① 产出就绪（静默） | 通知中心完成记录 + 首页速览行新红点（默认不弹窗，R4） | 点击速览行或通知开 ReadView | 刚发生，即时读 |
| ② 首页情报速览 | 首页区块（每订阅一行：最新报告标题 + 相对时间 + 状态点） | 点击开 ReadView | 早晨盘点「昨晚世界发生了什么」 |
| ③ 订阅管理台 | 任务页侧栏「定时订阅」**摘要行**（`订阅 N · 新产出 M · 异常 K`，异常红显；240px 只承载告警与入口，规模不限）→ 点击开**全宽管理台**（任务页内容区替换，与 ReadView 同模式）：左列 = 订阅列表（分类页签 全部/产业/企业/通用 + 状态筛选 全部/异常/暂停 + 搜索 + 多选批量启停/删除）；右列 = 期次面板（未选中订阅 = **收件箱**：全部未读期次时间流；选中 = 该订阅配置 + 期次历史 + 管理操作，头部「返回收件箱」按钮复位默认视图）；「＋新建订阅」→ 弹层向导 | 期次行点击**统一** → ReadView 全内容区替换（打开即已读；2026-10-22：收件箱与期次历史一致，不再按 task_id 分流直入回放）；回放 = ReadView 头部「执行过程」切换（唯一入口）；报告/回放页头部「返回」回宿主页（管理台恢复选中订阅 / 首页） | 规模化管理与回溯（2026-10-18 二次评审：30+ 订阅场景下「一级列表 + 抽屉」左栏撑爆、未读散落、无筛选/批量，升级为「摘要行 + 全宽管理台」；D2 管理主体不变） |
| ④ 项目素材/基础库 | 自动导入后的长期沉淀 | 项目内检索与阅读 | 复用与引用 |

**订阅管理台（动线③承载，规模分层设计）**——侧栏摘要 / 全宽管理 / 首页收件箱摘要，三层各管一段：

```text
左栏(240px)              任务页全宽管理台                        首页（高频）
┌─────────────┐ 点摘要行 ┌───────────┬─────────────────┐    ┌──────────────┐
│ 定时订阅      │ ──────→ │ 订阅列表    │ 期次面板           │    │ 情报速览       │
│ 30·新8·异常1⚠│         │ 页签/搜索/  │ 未选中=收件箱       │    │ 今日 8 条新产出 │
└─────────────┘         │ 多选批量    │ （全部未读期次时间流）│    │ →「查看全部」   │
                        └───────────┴─────────────────┘    └──────────────┘
```

- 左列行 = `名称 · 周期 · 状态点（运行呼吸/异常红/暂停灰，互斥：运行 > 失败红〔含熔断，需行动不淡显〕 > 手动暂停淡） · 未读数`，暂停订阅行名称/周期文字灰显（2026-10-23 对齐速览 rowPaused；历史可读——未读点/状态点/checkbox/操作钮不受影响）；按 category 分组；页签/搜索/批量均为**服务端参数**（`?category=&enabled=&q=`），不做前端全量过滤；
- 收件箱按 run 的 finished_at 倒序**跨订阅聚合**，未读以 run 为粒度（read_at，ReadView 打开即回填）——「今天有哪些新产出、读了没有」一眼可见，不靠扫 30 个红点；期次行悬停显删除按钮（收件箱与期次历史共用；running 行不渲染——在途执行后端 409 拒删，删除确认文案说明报告副本一并移除）；
- 批量操作 = 多选行 → 暂停/恢复/删除（删除确认弹层列出合计「将删除 N 条执行历史」），覆盖「项目结项、停掉相关 10 个订阅」类操作。

**订阅来源（三渠道，殊途同归——`schedules.prompt` 存最终填好的 prompt，引擎无差别）**：

| 渠道 | 入口 | 形态 |
|------|------|------|
| 从模板 | 订阅中心「＋新建订阅」弹层第①步「从模板」页签；任务欢迎页模板卡「设为定时」 | 占位符表单化（变量按名去重，同一占位符出现多次只一个输入框、填一次全量替换，[0.5 §4.4](0.5product-redesign.md)），填一次周期复用 |
| 自由输入 | 订阅中心「＋新建订阅」弹层第①步「自由输入」页签 | 直接写 prompt，适合把一次性想法转成周期任务 |
| 从人工任务 | 任务页文件树/预览层动作区「设为定时」（与 E2 导入按钮同层，已完成任务可用） | **LLM 提炼转化**（2026-10-18 二次裁决：人工任务是对话流，问东问西混杂，首条消息未必是要周期化的意图）：取全部对话（过滤 `[系统]` 注入消息，截断保护）→ POST /schedules/refine-prompt（LLM 单次调用，标准档路由解析）→ 提炼出{建议订阅名 + 周期执行 prompt 草稿 + 建议输出物} → 预填弹层（跳过来源页签）→ 用户把关修改后保存；提炼失败（无 LLM 配置/超时）结构化报错，弹层降级自由输入；产出结构约定自动附加 |

### 8.3 产出结构约定（D4，订阅创建时自动附加到 prompt 末尾，用户可在订阅编辑中修改）

```
输出为工作区根目录单个报告文件 report.md，结构：
## 摘要
- 3~5 条要点，每条一行（含定性：正面/负面/中性）
## 正文
（分节详述，数据标注来源与日期）
## 来源
1. {来源名} · {日期} · {URL}
```

> 文件名固定 `report.md`（工作区根目录）：终态回调按此路径定位报告副本源文件（D5），无需扫描 workspace。

解析规则（终态回调）：取报告首个「## 摘要」节下的列表项为 summary（JSON 存 run 行）；无该节则 summary 为空数组，ReadView 摘要卡显示「未按模板产出摘要」（提示检查订阅 prompt），正文照常渲染——解析失败不阻塞阅读。

### 8.4 状态-界面映射

| 状态 | 用户看到 |
|------|----------|
| 订阅运行中 | 任务 Tab 角标 +1（计入，真实占并发闸门）；订阅中心该订阅行呼吸点；情报速览该行转呼吸点；人工任务列表不出现该执行（D2） |
| 本期完成 | 默认静默（R4）：通知中心记录 + 速览行更新标题+时间+红点，不弹 Toast；动线①②③④任一可开 ReadView |
| 定时让路中（deferred） | 用户无感（正是目的）；订阅中心该订阅行显示「排队中·等待空闲」（轻提示，不报警） |
| 档案已更新 | 项目素材 Tab 档案文件更新时间变化（现有 file 活动反馈）；ReadView 底部「已沉淀至 {目标名}·档案」可点跳容器；管理台详情卡去向行同步可点 +「查看档案」切档案阅读页（2026-10-23） |
| 执行失败 | 失败 Toast；速览行红点；run 状态 failed；ReadView 显示失败原因与「重跑」 |
| 档案合并失败 | warning Toast（kind=`archive_failed`：产出已生成，档案合并失败，下期自动补并）；详情卡去向行「重建档案」按钮（2026-10-23 自操作条移入去向行）；本期产出照常可读（ReadView 不受影响，run 仍 done） |
| 连续 3 次失败 | 订阅自动暂停通知；速览该订阅行灰显「已暂停」；管理页置顶提示 |
| 应用未运行错过 | 启动后补跑（≤24h）或汇总通知（>24h，missed）；上次异常退出遗留的 running 行启动清扫置 failed + interrupted 汇总通知（§5.4） |

### 9.2 关键交互规则与不变量

1. 订阅启停开关即时生效（PATCH enabled），暂停后速览行与管理台列表行灰显但历史可读；
2. ReadView 的摘要永远来自 runs.summary（预解析），不做渲染期文件二次解析（渲染只读全文）；
3. 「设为定时」必须先有模板占位符值——占位符未填齐时入口禁用（tooltip「请先补齐模板信息」）；
4. run-now 不改变周期（next_run_at 不动）；异步受理——受理即返回（成功 Toast「已受理开始执行」/忙时 deferred 提示稍后重试），终态经通知中心 R4 反馈；
5. 删除订阅二次确认（弹层列出「将删除 N 条执行历史」）；确认后先取消在途换向重建（R4-P2-1）与在途执行再删除（在途 run 置 failed + 孤儿文件清理，review P2-4）；
6. 影子任务隔离不变量：定时执行永不出现于人工任务列表（服务端排除，前端零特判）；执行过程从报告页头部「执行过程」进入，且为只读回放（无输入框/无续跑/无重命名删除操作，清理随保留期自动；2026-10-22 起期次行点击统一进报告页，回放入口唯一切换按钮）；
7. 任务 Tab 运行角标计入运行中影子任务（真实占用并发闸门，必须可见），点击角标进任务页看不到 run 属预期——运行中的订阅在管理台该订阅行有呼吸点，侧栏摘要行计数同步；
8. 全部新增文案 zh-CN/en-US 双语（规范 §2.3）；
9. 新建/编辑订阅统一为**弹层向导**（不设独立页面）；弹层第①步「从模板/自由输入」双页签，从人工任务「设为定时」进入时跳过来源页签（prompt 已预填，§8.1 渠道③）；编辑态不区分来源，统一呈现 prompt + 占位符高亮；交互结构与位置以本文 §8/§9 文字设计为准（2026-10-18 原型废弃删除，无原型文件）；
10. 规模分层不变量：侧栏只承载摘要行（绝不展开全量订阅列表）；未读以 run 为粒度（ReadView 打开即调 markRead 回填 read_at）；收件箱跨订阅按 finished_at 倒序；筛选/搜索为服务端参数；批量操作必须走确认弹层（列出合计影响）。
