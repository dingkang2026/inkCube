## 1. 定位与决策沿革

### 1.1 定位变更

| | 原定位（作废） | 新定位 |
|---|---|---|
| 管线 | Word 报告 → 模板渲染 → PPT（确定性排版） | 报告 md + 图片库 → LLM 生成管线（ppt-master）→ 可编辑 PPTX |
| 质量 | 受模板还原能力限制，排版还原成本高 | 逐页 SVG 创作 + 内置质量门禁，接近手工水准 |
| 形态 | 报告导出的一个格式按钮 | 「项目-报告」内独立交付物体系（生成 / 模板双路由） |

作废原因：确定性模板渲染对演示文稿排版还原成本高、上限低。ppt-master（MIT，v4.8.0，作者 Hugo He）经真实任务验证：LLM 逐页创作 SVG → `svg_to_pptx` 导出**可编辑 PPTX**，上限显著更高，且原生提供模板工坊能力。

### 1.2 产品决策记录（2026-10-16 与用户对齐）

| 决策项 | 结论 |
|---|---|
| 功能范围 | 双路由：生成 PPT / 模板工坊；Fill Native 暂不做 |
| skill 集成 | 全量随包内置（83.6 MB），协议墙零修改自然合规 |
| 执行引擎 | 复用任务体系；`tasks.origin` 分离（chat / ppt），PPT 任务不进任务 Tab |
| 交互形式 | 图形交互：向导创建 + 进度卡片 + SVG 预览 + 门禁确认卡片（非聊天窗口） |
| 门禁机制 | 暂停恢复 + 确认交互（awaiting_input），复用任务暂停状态机；Generate 两阶段确认内嵌原生 confirm_ui 页面（2.3.1 §5.4） |
| UI 挂载 | 报告 Tab 内 PPT 区块；模板工坊在全局模板管理页加「PPT 模板」分区 |
| 素材链 | 报告 content.md（mermaid 经图表执行器重绘）+ 项目图片库（VLM 描述/分类） |
| 模板归属 | 双源：用户库 `<data_dir>/ppt-library/templates/`（收录落地，可管理）+ 随包内置源（只读展示，builtin 标记）；目录 + `*_index.json` 文件即状态，不建库表（E2 库外置 2026-10-20） |
| 安全机制 | PPT 任务命令执行静默（免 shell 确认弹窗）；skill 首用确认经 seed 免弹 |
| 任务参数 | 迭代上限等按 PPT 场景大幅调整（§3.2 预设表） |

### 1.3 MIT 合规策略

- License 为标准 MIT；SKILL.md 内置协议墙（`attribution_guard.py`，fail-closed：SKILL.md 元数据 + LICENSE 哈希 + 12 个核心脚本执行前门禁，任一修改即 `SystemExit(78)` 拒绝执行）。
- 合规方式：**包内零修改**——skill 原样内置，InkCube 全部在外部驱动（创建任务、注入素材、应答门禁、消费产物）；PPT 详情「关于」区展示 MIT 归因（作者 Hugo He）。

## 2. ppt-master 集成模型

### 2.1 包构成（83.6 MB / 13,245 文件）

| 目录 | 体积 | 作用 |
|---|---|---|
| scripts/ | 15.4 MB | svg_to_pptx（SVG→可编辑 DrawingML）、图表校验、图片获取、动画/音频等 80+ 脚本 |
| templates/ | 23.5 MB | 12 内置 style + 1.2 万 phosphor 图标 SVG + kenney 音效 |
| references/ | 44.1 MB | 37 个角色/标准 md + 视觉参考图（多模态审美基准） |
| workflows/ | 0.6 MB | 4 条顶级路由 + profiles + stages（LLM 工作流说明书） |

注：references 视觉参考图需多模态模型才生效；纯文本模型走其文本审美规范，质量降级可接受。

### 2.2 内置打包与种子安装

- 分发：`resources/skills/ppt-master` 随包 → electron-builder `extraResources`（asar 外，同 mermaid 渲染器策略，见 0.2）→ 运行期经 `INKCUBE_RESOURCES_DIR` 定位。
- 种子安装：扩展 seed（现单 skill 硬编码 browser-fetch）为清单式多 skill：copytree → `<data_dir>/skills/<name>` + skills 表 upsert（source_type='builtin'）+ `confirm_skill_by_name` 免首用确认。
- 启动性能：13,245 文件逐次启动幂等拷贝不可接受 → 写版本指纹文件（`<data_dir>/skills/<name>/.inkcube-seed.json`：skill 版本 + 文件数 + 总大小），指纹匹配跳过拷贝，不匹配（升级）才重拷。
- 内置 skill 不出现在 skill 管理的可卸载列表（同 browser-fetch 既有语义）。

### 2.3 运行依赖

| 依赖 | 层级 | 策略 |
|---|---|---|
| python-pptx / skia-pathops / uharfbuzz | 硬依赖 | PPT 任务 venv 首次创建时随预装清单安装（任务 venv 预装机制，1.1 §2.3） |
| flask | 硬依赖 | confirm_ui 确认页服务 + svg_editor 预览服务（2.3.1 §8.5） |
| requirements.txt 首用校验 | 兕底 | skill 自带，loader 现有机制提示安装 |
| PyMuPDF 等重可选件 | 可选 | 不预装，缺失时工作流内提示 |

凭据注入（图片生成/搜索/TTS）：子进程环境变量注入（`IMAGE_BACKEND`、`<BACKEND>_API_KEY` 等，进程环境优先级最高，2.3.1 §8.1）；兼容位为任务工作区 CWD 下 `.env`（ppt-master 官方查找链首位）。E1 复用现有 openai 兼容网关凭据（`IMAGE_BACKEND=openai` + `OPENAI_BASE_URL`）；未配置图片凭据时向导 image_usage 收窄为 provided/placeholder/none。

## 3. 执行引擎：任务框架适配

PPT 任务 = tasks 表中 `origin='ppt'` 的任务，由 TaskAgent 原样驱动（系统提示注入 ppt-master SKILL.md 与工作流说明书；工具同 chat 任务：shell / file_ops 等）。框架复用，参数与交互按 PPT 场景调整。

### 3.1 形态分离（origin）

- `tasks.origin TEXT NOT NULL DEFAULT 'chat'`（未上线无存量数据，直接改 DDL，不做迁移）。
- 值域：`chat`（任务 Tab 现有形态）/ `ppt`（本文档，报告 Tab PPT 区块承载）。
- 过滤点：任务 Tab 列表查询固定 `origin='chat'`；PPT 区块按 ppts 表关联聚合。
- 通知分流：notifications.entity_type 值域新增 `ppt`，container 归项目，点击导航至 PPT 详情。

### 3.2 PPT 任务参数预设（迭代上限大幅提升等）

实测依据：ppt-master 真实生成任务共 169 轮、41 分钟（默认 60 轮上限被切断 3 次，靠恢复续跑）；svg_to_pptx 大页数转换单命令可达数分钟，远超 chat 默认 30s 单命令超时。

| 参数 | chat 现值 | ppt 预设 | 依据 |
|---|---|---|---|
| 迭代上限（chat 通用键 `task_max_iterations` / ppt 专用键 `task_ppt_max_iterations`） | 60 | **240** | 实测 169 轮 + 余量 |
| 单次命令超时（同上双键，注入 shell / code_executor，非任务总时长） | 30 | **600**（`task_ppt_timeout`） | svg_to_pptx 长转换远超 chat 默认 |
| 预算收束提醒提前量 | 剩 3 轮（BUDGET_WARNING_LEFT） | `max(3, max_iter // 10)` → 240 轮任务剩 24 轮提醒 | 长工作流需更早收束，末 3 轮来不及保存 |
| shellConfirmMode | 用户设置三档 | 固定 auto 语义（§3.3） | 工作流静默 |
| 任务总时长上限 | 无 | 无（保持） | awaiting_input 可无限期等待用户 |

- 预设实现：agent 侧 `ORIGIN_PRESETS` 常量，承载专用键 `task_ppt_*`（defaults 白名单默认 None——通用键恒有默认值 60/30，以「get 为 None」判定未设置只对专用键成立，用通用键则预设失效）。专用键未设置时预设值落地为运行参数（`task_ppt_X → task_X`，下游消费点不变），显式设置即覆盖；ppt 与 chat 通用设置完全解耦（设置页调 task_max_iterations / task_timeout 只影响 chat 任务，反之亦然）。回归：test_ppt_service.py `TestOriginPresetsIntegration`（真实 get_settings 形状）。
- 预算软着陆复用：收束提醒文案为通用指令（存 workspace、简述进度），PPT 场景语义自然成立（半成品 SVG 亦是中间产物）；恢复时过滤旧提醒机制照常生效。
- 模型档位路由（2026-10-19 档位制补齐）：PPT 任务主对话模型按 `ppt_model` 档位解析（唯一默认 high 的业务线），其余任务按 `task_model`——agent `_apply_task_routing` 按 origin 分流（ppt 走 `get_task_settings("ppt")` 统一入口留 routing 日志，其余走 `resolve_model`）；档位解析语义见 [2.6 §12.2.13](2.6wiki-design.md)。回归：test_task_agent_routing.py。
- 恢复语义复用：迭代耗尽 → paused；PPT 详情「继续」→ 恢复（新一轮全新预算 + 历史摘要线重建，1.1 §5.3）。
- 上下文有效性边界（2026-10-27 核实 `references/executor-base.md` §2.1）：ppt-master 以三态判定执行上下文——Valid（完整 design_spec + spec_lock 在未压缩活跃上下文，每页复用不重读）/ Invalid（全新/恢复/重启/摘要式恢复，须完整重读 design_spec.md → spec_lock.md，deck 中途恢复另读最新完成 SVG 与图片元数据）/ Uncertain（先查 retained lock 再读 spec 片段，冲突时 Design Spec 为上游权威）；配套「五页轻量锁重读」（仅 Default Generate：完成 P05/P10/P15… 且仍有后续页时，下一页前完整读一次 spec_lock.md，纯上下文再锚定防长上下文规格漂移）。InkCube 恢复语义（历史摘要线重建）天然落在 Invalid 态，重读由 skill 说明书自治，平台零干预。**红线**：禁止为恢复加速做上下文保温（跨进程快照/复用 LLM 会话历史）——会使 agent 误判 Valid 跳过重读，平台侧绕穿防漂移设计；恢复必须 = 摘要上下文 + Invalid 完整重读，慢是正确性代价。

### 3.3 安全确认机制：PPT 任务静默策略

| 机制 | 现状 | PPT 任务策略 |
|---|---|---|
| shell 命令确认（confirm-shell，设置三档 strict/smart/auto） | 命中规则的命令弹确认卡片（允许 / 本会话允许 / 拒绝） | **静默**：固定 auto 语义，跳过交互确认 |
| skill 首用确认（needs_confirm + confirm-skill） | 首用弹窗，确认后永久信任入库 | **免弹**：第一道 seed 安装时 `confirm_skill_by_name` 置 0（内置代码可信，同 browser-fetch）；第二道 origin=ppt 直行（第三方 skill 未置信时也不弹，纵深防御，1.1 §7.1） |
| git commit 确认（confirm-shell 通道） | commit 前弹确认 | **静默**：origin=ppt 直行（工作流产物的版本固化，属工作流内环） |
| 文件写入 | 工作区内自由 | 不变 |

静默理由：PPT 任务命令谱系 = 内置 skill 固定脚本清单 + 工作区文件操作，来源可信且可预期；逐条确认在百轮级任务下不可用。残余风险（LLM 越谱系命令）与用户在 chat 任务显式选 auto 档等同；创建向导明示「工作流将自动执行内置脚本」。

### 3.4 门禁确认卡片（工作流决策点，不静默）

与 §3.3 命令安全确认不同，这里是**工作流内容决策**（选哪个模板 / 策略是否 OK / 预览是否通过），是图形交互的核心交互点。

| 路由 | 门禁点（工作流实测） | 交互形态 |
|---|---|---|
| Generate | **两阶段**：Stage 1 沟通契约 + 模板选择一次提交 → agent 自动装模板 → Stage 2 完整方案 + 生产机制（2.3.1 §4） | webview 内嵌原生 confirm_ui 页面（下） |
| Create Template | **唯一确认门**：brief 确认（素材分析后 agent 提出带来源标注的自然语言创建计划，用户逐句修正或确认；创建策略 standard/fidelity/mirror 为 agent 内部派生值，明文禁止向用户提问；全程无 confirm_ui 页面） | 确认卡片 |

机制：复用任务暂停状态机——门禁处任务转 `awaiting_input` + notifications。Generate 的两阶段由后端按 `confirm_ui/` 产物文件出现顺序判定（2.3.1 §9.1），**不使用官方 `--wait-only` 阻塞**（长任务不挂 wait）；Create Template 走 `confirm_request` 卡片，应答经 `POST /ppts/{id}/answer` → agent resume（应答文本注入任务消息）。不设超时自动拒绝（用户可任意时刻应答）；用户也可手动暂停走普通 pause 流程。

集成形态（关键决策，2.3.1 §5.4）：**内嵌原生 confirm_ui 页面**——前端详情页以 webview/iframe 加载 `http://127.0.0.1:<port>`；sha256 校验链、四语言、模板候选目录与 Stage1→Stage2 轮询全部复用官方 UI（自渲染全部字段成本高且易随上游 schema 漂移，弃）。InkCube 门禁卡片降级为**状态摘要条**（读产物 JSON 显示阶段 + 「打开确认页」按钮）。**服务生命周期系统接管（S1，2026-10-28）**：`server.py --daemon --no-browser --timeout 0` 由系统拉起——sync_progress 门禁置位（pending 且回合结束）与重启恢复 awaiting 两挂点调 `_ensure_confirm_ui`：lock 端口 TCP 探活活则跳过（泵心跳高频幂等）、死/无 lock 先 `--shutdown` 清残留再 DETACHED 分离拉起（`--daemon` wrapper 退出后 server 常驻不随父亡）。曾由 agent shell 手动启动：shell 工具 10s 超时把前台启动误判为失败（exit=1）诱导单会话 3-4 次重复启动（端口漂移 + lock 覆盖），且长驻服务生命周期本不该由 agent 管理——首条消息已同步删除启动/关停指引。关停链路：页面提交前端自动 `POST /api/shutdown`（官方 UI 内置）→ 泵终态落 failed / recover paused-completed / cancel / delete 显式 `--shutdown` 兜底（释放 5050 段端口给 live_preview；2026-10-26 review 封泄漏清单，S1 后 agent 侧已无自关路径需封）。

### 3.5 长任务交互提醒机制

40 分钟级任务的全程可感知设计（全部走现有通道，不自建轮询，符合 0.4 §3 统一活动模型）：

| 时点 | 机制 | 用户在哪看到 |
|---|---|---|
| 启动 | notifications（entity_type=ppt） | 通知中心；报告 Tab 卡片出现 |
| 阶段推进 | ppts.stage / progress 更新（注册统一活动 kind='ppt'） | 卡片进度条 + 阶段标签；活动中心条目 |
| 页级推进 | 后端聚合 workspace 已完成 SVG 页计数（不依赖 LLM 自觉上报） | 卡片「第 N/M 页」 |
| 门禁待确认 | awaiting_input + notifications | 活动中心红点 + 卡片高亮「待你确认」 |
| 预算收束提醒 | thought 事件（1.1 §5.6 现有机制） | 运行详情时间线 |
| 迭代耗尽 | task paused + notifications | 卡片「已暂停」+ 继续 / 终止 |
| 完成 / 失败 | ppts 终态 + notifications | 通知 + 卡片终态（打开文件 / 查看错误） |

- 进度口径：stage ∈ intake → strategy → authoring → export；progress = 已完成页数 / 规划页数（authoring 阶段），其余阶段按边界推进。
- 触达原则：用户不在 PPT 详情页时靠通知中心与活动中心，进入详情页后靠时间线与卡片；不引入 OS 级弹窗（与项目现有通知习惯一致）。

### 3.6 产物工作区与交付物

- 工作区：任务体系既有 `data/tasks/<task_id>/workspace/`，ppt-master 项目目录即在其中（deck/template 由**系统在 prepare 阶段执行 init 创建**：`_init_project_skeleton` 产出 `ppt_project_ppt169_<YYYYMMDD>`，首条消息声明目录并禁止 agent 重复初始化——2026-10-28 修订：曾由 agent 自行 init，cli 给裸名追加后缀产出 `ppt_project_ppt169_YYYYMMDD`，而全链锚定固定名 `ppt_project` → 锚定落空读空，Stage 1 确认页打不开），目录契约从 ppt-master 实测（2.3.1 §3.1）：`sources/`（报告 md）、`images/`（图片库导出）、`confirm_ui/`（门禁产物）、`svg_output/`→`svg_final/`（页面 SVG；官方工作流不约束文件名，预览与页计数按文件名数字序聚合，兼容 page_N.svg / NN.svg / NN_<type>.svg——2026-10-28 修订：曾硬编码 page_*.svg，agent 按官方姿态产 NN.svg 致预览空、page_done=0、progress 恒 0 三者同源）、`notes/`、`exports/`（PPTX）、`validation/workflow.log`（命令账本，诊断用）。
- ppts.workspace_path 指向项目目录；export_path 指向最终 PPTX——**文件名带时间戳**（`<name>_YYYYMMDD_HHMMSS.pptx`，svg_to_pptx 强制附加），存储实际文件名。
- 预览：SVG 页经现有任务文件端点读取（`pages` 以**任务 workspace** 为基准返回：`pages_for_workspace` 在 `list_pages` 项目目录相对路径上补齐项目目录层，前端 `tasks:readFile` 可直读——2026-10-28 修订：曾直接返回项目目录相对路径，基准错位致预览网格恒占位），前端内嵌渲染（SVG 浏览器原生支持）；PPTX 本体不预览，提供「另存为」（现有文件保存 IPC，同报告导出模式）与「打开所在文件夹」。
- 删除 PPT → 级联删除关联任务与工作区（现有任务删除链复用）。

## 4. 两条路由功能映射

### 4.1 Generate PPTX（报告 → PPT）

- 入口：报告详情「生成 PPT」+ PPT 区块「新建」。
- 创建向导（保持轻量，正式决策留给 Stage 1 门禁）：

| 输入项 | 形态 | 说明 |
|---|---|---|
| 标题 | 文本 | |

### 4.2 Create Template（模板工坊）

- 入口：全局模板管理页「PPT 模板」分区「新建模板」→ 向导：模板类型（四类，ppt-master 原生定义，与索引文件一一对应）→ 参考素材（现有 pptx / SVG / 图片 / 文档 / 网站 / 纯描述）→ 产出 scope 固定 project（模板包留在任务工作区，完成由系统收录进用户库，E2 库外置；agent 不执行注册命令）。

| 类型 | 管什么 | 索引文件 |
|---|---|---|
| Brand 品牌身份 | logo/色板/字体规范——「identity truth」，**不含页面结构** | brands_index.json |
| Style 视觉风格 | 色板/字体/质感氛围 | styles_index.json |
| Layout 版式 | 单页结构骨架（brand-neutral，Master/Layout SVG 合同 + 占位符几何） | layouts_index.json |
| Deck 成套 | branded 结构系统，整套页 roster（可叠 brand 身份，category: brand） | decks_index.json |

- 门禁：**仅一处**——素材分析后 brief 确认（create-template.md Step 3 User Confirmation Gate，chat 文字确认形态；Review PPTX 是产物不是门禁，生成后由系统收录进用户库，无第二个人工确认点）（§3.4）。
- 产物（E2 库外置 2026-10-20）：任务工作区 project scope 模板包（agent 按 create-template.md project 分支产出，spec 限定名 `templates/design_spec.<kind>.<id>.md`，不注册全局索引）→ 回合结束系统校验（限定名 spec + 结构完整：结构型 Layout/Deck 须有 SVG 页面原型）→ **收录**：拷入用户库 `<data_dir>/ppt-library/templates/<kind_dir>/<id>/`（spec 归一为库形态 design_spec.md，templates/ 整目录 + images/icons/exports 存在才随包，索引条目从 spec frontmatter 按 kind 提取；先拷库根 `.collecting/` 暂存再整体切名——拷贝中断不留半包在正式名下被 rescan 误收录成缺图包；同名覆盖为删除重建（幂等重收录语义，手工改动被覆盖留日志），切名失败回滚索引条目防悬空（重试收录可恢复）；索引读-改-写与目录切名持库锁，与 rescan 重建/delete 删条目互斥防丢更新）→ 分区列表即时可见；收录失败任务置 failed 带原因（禁静默降级）。收录是幂等纯本地操作：失败行可经任务卡「重试收录」（POST /ppts/{id}/retry-collect，工作区包完整时前端才展示入口，不跑 agent、不耗模型）自助恢复，无需删任务重跑。自建模板**不进 Stage 1 自动候选**（候选读内置索引），仅向导显式选择可用。模板包内容（即模板详情页展示源，**仅结构型 Layout/Deck**，实测 decks/中国电信）：`templates/design_spec.md`（brief：frontmatter 画布/摘要/关键词/主色 + 正文色板/字体/页面清单）、`templates/*.svg`（页面原型，`NNN_<page_type>.svg` 命名如 `01_cover.svg`——**详情页预览网格数据源**）、`images/`（包内资产）、`exports/`（Review PPTX `<id>_template_preview.pptx`：多 Master 必生成、单 Master 按需）。注意：`manifest.json`/`native_structure.json`/`svg/master_*.svg` 是 pptx_template_import 的**临时分析工作区**产物，不进模板包（2.3.1 §6.2）；**Style/Brand 为纯 spec 型**（仅 design_spec.md + 索引 summary/keywords，无 SVG/资产），详情页以「模板规范」区渲染 design_spec.md 正文（frontmatter 剥离，Markdown 渲染）。
- 分区能力：按类型分组双源列表（内置带「内置」徽标 + 用户库可管理）、**模板详情**（摘要/主色/关键词/页面类型/模板规范正文渲染/页面原型预览图网格（点击放大 lightbox）/包内资产 images 网格/包内文件清单（全文件相对路径+大小，图片类点击预览，非预览类如 PPTX/JSON 仅列出——零盲区盘点）/Review PPTX 下载；Brand/Style 无原型时以规范正文为主体）、删除（**仅用户库模板**；内置模板不可删——升级种子重拷会原样恢复源包内容，删除必然「复活」，2026-10-19 决策：内置卡片带「内置」徽标且无删除入口，后端 DELETE 拒绝）、重新扫描（自扫用户库重建四类索引，目录树为权威、残缺目录跳过，不再调 register CLI）。

### 5.1 ppts（新建，照 reports 模式）

```sql
CREATE TABLE IF NOT EXISTS ppts (
    id TEXT PRIMARY KEY,
    project_id TEXT NOT NULL,
    task_id TEXT NOT NULL,               -- 引擎句柄：tasks.id（origin='ppt'）
    title TEXT NOT NULL,
    kind TEXT NOT NULL DEFAULT 'deck',   -- deck=生成 / template=模板工坊
    status TEXT NOT NULL DEFAULT 'running',
        -- running / awaiting_input / paused / completed / failed / cancelled
    stage TEXT,                          -- intake / strategy / authoring / export
    progress REAL NOT NULL DEFAULT 0,    -- 0-1（authoring 按页计）
    page_count INTEGER,                  -- 规划页数
    page_done INTEGER,                   -- 已完成页数
    source_report_id TEXT,               -- 内容源报告（可空=自由主题）
    source_images_json TEXT,             -- 复合选择物化后的入池图（staging 相对路径，E2）
    style_ref TEXT,                      -- 模板选择标识串 "kind:id,..."（E2 向导选择器，选择结果持久化）或 legacy 风格文本
    template_kind TEXT,                  -- E2 模板工坊：brand/style/layout/deck（kind='template' 行）
    template_id TEXT,                    -- E2 模板工坊：目标模板 id（完成判定 + 用户库收录定位）
    workspace_path TEXT,                 -- ppt-master 项目目录（deck：ppt_project_*；template 同）
    export_path TEXT,                    -- 最终 PPTX 相对路径
    error TEXT,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    -- E2 补充（_migrate_add_column）：template_kind / template_id；
    -- E3 下线（2026-10-28，迁移反转）：enhance_source_path 列已 DROP（同 wiki
    -- pending_compile_count 先例）；kind 值域 = deck（生成）/ template（模板工坊，
    -- project_id='' 全局资产）
);
CREATE INDEX IF NOT EXISTS idx_ppts_project ON ppts(project_id, created_at DESC);
```

## 6. 数据流

### 6.1 分层组件

```
前端                                Python(FastAPI)                     引擎 / skill
──────────                         ──────────────                      ────────────
报告Tab→PPT区块 ──HTTP──▶ routers/ppts.py ──▶ ppt_service ──▶ TaskAgent(origin=ppt)
模板管理→PPT分区 ──HTTP──▶ routers/ppt_templates.py ──▶ 双源聚合（内置随包索引只读 + 用户库索引可管理）
PPT详情(运行中) ◀─轮询─ tasks 状态 + 消息流 ◀── TaskAgent ──▶ skill 工作流（shell 跑 scripts/）
  门禁卡片 ──POST answer──▶ ppt_service ──▶ agent.resume
```

### 6.2 端到端路径（生成 PPT）

1. 向导提交 → `POST /projects/{pid}/ppts` → 建 ppts 行 + tasks 行（origin='ppt'）→ prepare 线程池段系统执行 ppt-master init 建项目骨架（`_init_project_skeleton`，目录名带后缀与锚定一致，失败向上抛回滚孤儿行）→ 后台启动 TaskAgent（首条消息声明项目目录，禁止重复 init）。创建原子性：素材就位中断回滚孤儿 task（origin='ppt' 不进任务 Tab，泄漏不可见）；launch 失败行置 failed 而非僵尸 running——含非 RuntimeError 异常（如并发写库锁冲突），`_start_drive` 内 DB 写先行、泵创建垫底，任一失败时行尚未 running，回滚路径统一处置。
2. intake：agent 经 file_ops 拷素材 / 重写引用 → 更新 ppts.stage。
3. strategy：两阶段门禁（Stage 1 契约+模板 → agent 自动装模板 → Stage 2 方案）→ awaiting_input → 用户在内嵌确认页提交 → 后端检测 confirm_ui 产物推进；回执落盘后自动续跑（双驱动：泵伴随心跳 + 详情页 3s 轮询接棒——泵随回合结束退出，续跑由轮询驱动）。
4. authoring：逐页 SVG（file_ops 写 svg_output/）→ 后端聚合 page_done / progress。
5. export：shell 跑 svg_to_pptx（timeout 600s）→ exports/*.pptx → ppts 终态 + 通知。泵退出后 `_finalize_or_fail` 收尾：`_finalize` 线程池执行（含收录拷贝等重 IO，不阻塞事件循环），终态写前让位判定（`_superseded`：行删/状态偏离快照/新泵在飞即让位——线程池化后 answer/auto_resume 可在收尾窗口开新泵、轮询可先落门禁态，过期快照覆盖曾致状态回退）；收尾异常兜底置 failed（可重试）并同步关停确认页 daemon；awaiting 回执续跑由收尾落盘后补触发（`_start_drive` 需事件循环线程）。

### 6.3 端点清单（新增）

| 端点 | 方法 | 作用 |
|---|---|---|

| /ppts/{id}/cancel | POST | 取消（走任务 cancel 链） |
| /ppt-templates | GET | 双源聚合（E2 库外置 2026-10-20：内置条目读随包源索引 builtin=True + 用户库条目 builtin=False，同 id 用户库优先；产物盘点随条目源展开） |
| /ppt-templates/jobs | GET | 模板工坊任务列表（kind='template' 行，E2 已实现；分段契约：活跃段 running/awaiting_input 恒全量 + 终态段 limit/offset，has_more 只看终态段，limit=0 全量）。template 行富化 package_ready（工作区包完整性，失败行「重试收录」按钮的展示判定） |
| /ppt-templates/{kind}/{name}/spec | GET | 模板规范文档（design_spec.md 正文，frontmatter 剥离；详情抽屉「模板规范」渲染源；源随条目切换——内置读随包源、用户库读库根）。错误码：400 INVALID_TEMPLATE_ID / 400 INVALID_TEMPLATE_KIND / 404 SPEC_NOT_FOUND（纯索引条目无 spec，前端静默空态） |
| /ppt-templates/create | POST | 创建 Create Template 任务（120s 超时同 ppt:create，E2 已实现） |
| /ppt-templates/{kind}/{name} | DELETE | 删除用户库模板（rmtree 目录 + 索引条目；内置源只读不可删；6b 连带清理同模板创建任务历史：活跃 running/awaiting_input → 409 拒绝提示先取消，仅终态 → 逐行 delete_task（消息+托管工作区）+ delete_ppt，JobCard 不留指向已删模板的孤儿记录；TOCTOU 两阶段重查：快照检查后 failed/paused 行可被 resume 激活，_do_delete 先全量重验全部任务仍为可删态（部分清理比整体放弃更糟）再进入删除循环，否则整体放弃 409；模板已不在但终态历史残留亦可清——幂等修复；清理失败整体失败可重试，返回 purged_jobs 计数）。错误码：400 INVALID_TEMPLATE_ID（含路径穿越终检） / 400 INVALID_TEMPLATE_KIND / 400 BUILTIN_TEMPLATE（内置同名保护，2026-10-19 决策） / 404 TEMPLATE_NOT_FOUND / 409 TEMPLATE_JOB_ACTIVE（存在进行中创建任务） / 500 TEMPLATE_DELETE_FAILED |
| /ppt-templates/rescan | POST | 自扫用户库重建四类索引（目录树为权威：库形态 design_spec.md 存在才算完整包，frontmatter 按 kind 提取重建条目，残缺目录跳过；索引写回持库锁并锁内合并重读（扫描在锁外，锁内把快照缺失但目录仍存在的现存条目保留——扫描窗口内新收录不被重建快照吞，目录已消失的漂移条目幂等清；与收录/delete 互斥防丢更新；不再调 register CLI——其根写死 skill 安装目录内））。返回 {results: [{kind, count, skipped}]} |

页预览不走独立端点：GET /ppts/{id} 详情聚合 `pages` 清单（后端 `pages_for_workspace`：`list_pages` 按文件名数字序聚合 `svg_output/*.svg`——官方工作流不约束文件名，page_N.svg 与 NN.svg 同权、非标名沉底；再转为任务 workspace 相对路径），页面内容前端经 `tasks:readFile` 逐页拉取（新页出现时增重拉，已拉页缓存不重复读）。

IPC：仅「另存为」复用现有文件对话框与保存 IPC（同报告导出通道）；其余全为 HTTP 轮询（项目既有模式）。

### 7.2 状态-界面映射

| ppts.status | 界面 |
|---|---|
| running | 卡片进度条（stage 标签 + 第 N/M 页）；详情时间线滚动 |
| awaiting_input | 卡片高亮「待确认」；详情 ConfirmCard 置顶（Generate=打开确认页入口；Template=结构化卡片） |
| paused | 卡片「已暂停」；详情 继续 / 终止 |
| completed | 卡片封面 + 另存为 / 打开文件夹；详情预览网格 |
| failed / cancelled | 卡片错误摘要；详情错误详情 + 继续（failed 可重试：answer 不再拒绝 failed，续跑从 DB 历史重建上下文；cancelled 为用户显式终止，无重试入口）；模板任务卡失败态另有重试收录（工作区包完整时） |

### 7.3 交互规则与不变量

- PPT 任务永不进任务 Tab（origin 过滤）。
- 门禁应答前任务可手动暂停；暂停不丢 confirm_request（恢复后卡片仍在）。
- 同一项目允许多个 PPT 交付物；同一报告可多次生成（每次新 ppts 行 + 新任务）。
- awaiting_input 不计入任何超时（任务无总时长上限）。
- 内置模板不可删除（判定 = 随包源同名目录存在，seed 同源）：前端卡片/详情均无删除入口，后端 DELETE 拒绝（BUILTIN_TEMPLATE）双保险；升级重拷后内置集合自动跟随源包（新增自动纳保护）。源定位失败（打包异常）退化为非内置，不锁死用户库。
- 删除项目级联删除 ppts 与关联任务工作区（归档/删除守门含 running/awaiting PPT，复用统一活动 status 字段；删除时逐行复用 service.delete 链路：bounded 等待 agent 退出 + 关停确认页 + 删任务工作区 + 删行，清理失败即中止、整单可重试）。
