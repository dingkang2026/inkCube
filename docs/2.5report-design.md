# 报告系统设计

> **概述**：报告系统是项目的主要产出形式——用户从模板库选择模板、配置知识来源后，引擎在后台执行「变量解析（研究 DAG）→ 归一化 → 两遍章节生成（检索 + 知识卡片 + 校验 + checkpoint）→ 全局收尾 → 渲染」流水线，产出带引用溯源的 Markdown 报告并导出 Word。本文覆盖四部分：报告 Tab 交互（§1）、模板系统（§2）、生成引擎（§3）、存储 / API / 模块结构（§4-§6）。
>
> 关联：知识检索通道复用 [2.2 §6](2.2knowledge-base-design.md) 混合检索引擎；Wiki 通道复用 [2.6](2.6wiki-design.md) 的 wiki_search；互联网通道为网络搜索 API（Tavily / 智谱二选一，2026-10-19 供应商化）；报告作为长时活动接入活动中心（[0.4 §3](0.4lifecycle-design.md)）；项目页与看板归属见 [2.1 §9](2.1project-design.md)；PPT 交付物独立体系已落地 E1（2026-10-16，内置 ppt-master skill，报告 Tab 内 PPT 交付物区块 + 新建向导，[2.3](2.3ppt-export-design.md)）。

## 1. 报告 Tab 交互（前端）

### 1.1 看板（列表视图，默认）

报告按模板 `stage` 分组的看板布局：

| 项目类型 | 列 |
|---|---|
| 招商引资 / 投资分析 | 投前（before）/ 投中（during）/ 投后（after）/ 其它（stage 非 before/during/after 的报告：模板无 stage、模板已删、template_json 损坏或值越界）四列 |
| 通用（general） | 仅「其它」单列 |

卡片内容：标题 + 模板名 · 输出格式 · 创建日期，底部状态区。点击卡片进入详情页（ReportPreview）。

看板布局（2026-10-25 二次裁决）：四列（投前/投中/投后/其它，general 单列）横向 `flex: 1` 均分铺满内容区宽度，空列与有内容列同权均分、窄窗口下 `min-width: 220px` 保底后横向滚动；通用项目「其它」单列限内容宽 640px 不拉伸报告卡。（历史：本日曾改「空列窄条化」，实测全空项目四列全部命中窄条压缩至左侧，与「泳道铺开」预期相悖，同日撤销。三轮「右侧留白」反馈的真正根因在宿主容器：OutputTab.wrap 自 T11 起缺 `flex: 1`，在 .tabContent（row flex）中宽度塌缩为内容自然宽——与下方 §1.3 ReportPreview 修复前的病灶同源，2026-10-25 补齐 `flex: 1; min-width: 0` 对齐其余三个 Tab 根类惯例。）

| 状态 | 卡片显示 | 操作 |
|------|---------|------|
| done | ✅ 已完成 | 导出 Word（仅 done 可点）、删除 |
| generating | ⏳ 进度百分比（progress 列） | 暂停（写 pause_requested，当前章节完成后生效，§3.8 修订）、删除（生成中禁用 + tooltip 提示，后端同步 409——防生成中误删致 runner 写孤儿数据；孤儿 generating 由启动扫描救回后可删） |
| paused | ⏸ 已暂停（保留进度） | 恢复（retry resume 断点续跑）、重新生成（确认后 retry restart 全量重跑）、删除 |
| error | ❌ 失败（hover 显示 error_message） | 重试（默认 resume 续跑）、删除 |

看板刷新模型（0.4 统一骨架）：`usePolling('reports-generating', 3s)` 谓词从全局心跳 `useActivity('report')` 派生（本地列表是挂载快照，心跳是全局事实）+ `useEdgeRefetch` 终态边沿补拉；`applyReports` 同步更新 previewReport 快照，防止预览页持有陈旧 status。

看板下方并列 **PPT 交付物区块**（PptSection，[2.3 §7](2.3ppt-export-design.md)）：PPT 卡片列表（进度条 / 状态徽章）+ 新建入口 + 详情入口，轮询模型同报告（`useActivity('ppt')` 驱动 3s 轮询 + `useEdgeRefetch` 终态补拉）；新建向导（PptWizard）内容源限定本项目已完成（done）报告（可空选），配图取项目图片库已完成描述的图片，另支持风格意向与补充要求。

### 1.2 新建向导（ReportWizard，2 步）

**Step 1 选择模板**：按 stage 分组展示，过滤条件 `project_types` 包含当前项目类型；支持名称搜索。

**Step 2 配置（只读大纲 + 配置项）**：

| 配置项 | 交互 | 后端字段 |
|--------|------|---------|
| 知识来源 | 项目知识库（默认勾选，可取消；取消后本项目内材料——文件知识库与已编译 Wiki——不参与本报告的章节检索与变量抽值）+ 招商/投资基础库（按项目类型自动匹配）+ 自定义基础库（baseLib:list 动态加载手动勾选）；勾选变化即时回写项目关联（project:linkBaseLib / unlinkBaseLib，见 2.1 决策 8） | `base_project_ids` / `include_project_kb` |
| 报告大纲 | 只读展示（模板定义，不支持在向导内调整——需到模板管理修改）；按章分组分层展示，与后端两级执行大纲（§2.1.5 / get\_execution\_sections）镜像：有 children 的章显示组头 + 章内编号节行，无 children 的章自身即节 | — |
| 互联网检索 | 报告级总开关 + 每个 standard 章节逐节开关（post\_body 不检索、无开关，以「全文综述」标签替代开关展示）；未配置网络搜索（供应商未选或所选 Key 为空）时总开关置灰 | `internet_enabled` / `section_internet` |
| 变量填写 | 模板声明的 `source: user` 变量逐项输入（required 校验） | `variables` |
| 补充说明 | 自由文本，生成时追加到模板 global_requirements | `supplementary_notes` |

点击「开始生成」：必填变量前端先行校验（空值 toast 列出缺失项，不下发请求）；入口经 `guard('report')` 就绪度校验（缺 LLM / 嵌入模型引导弹层，0.4 §7.3），随后 `POST /reports/generate` 立即返回，前端回到看板轮询进度；请求失败（网络 / 409 / 429 等）toast 呈现错误原因，不静默。

**互联网两层开关语义**：总开关 OFF → 全报告（含派生变量解析）强制仅用知识库，章节开关失效；总开关 ON → 各章节按逐节开关附加 internet 通道，派生变量按其 `data_sources` 声明取通道。网络搜索未配置而开关已开时，引擎写 warning 级报告日志显式告知（不静默降级）。

**项目知识库开关语义**：默认勾选（对齐既有行为）；取消后本项目内材料（文件知识库 + 已编译 Wiki，Wiki 同为项目主体材料的高浓度载体且采信优先级最高）退出本报告全部检索（章节检索的 knowledge / wiki 通道 + 派生变量抽值），基础库勾选与 internet 通道不受影响——支撑「通用行业 / 区域研究不携带项目主体材料」场景（与模板 subject_anchored 配套，§2.1.2 / §3.5）。全通道无材料时走既有降级 / 跳过判定（§3.3）。配置随报告行持久化，retry resume / restart 原样恢复（§3.8）。

### 1.3 报告详情页（ReportPreview）

| 区域 | 内容 |
|------|------|
| 顶部工具栏 | 返回 + 标题 + 导出 Word 按钮（exporting 中或报告非 done 时禁用——终稿 content.md 收尾才落盘，非 done 导出会得到不完整文档），点击弹出导出面板（见下） |
| 正文区 | components/Markdown 渲染 content.md（与 chat / wiki 同一组件：标题 / 表格 / 代码块 / mermaid 图 / 引用 / 列表）；正文数字引用 `[n]` 渲染为上标 `<sup>[n]</sup>`（视觉尾注预览端，§3.7「渲染」；文档内查找键用原始文本，转换段落经共享组件渲染为 p 叶子块可被查找命中，sup 以私有区占位符协议进入行级 HTML 管线、不切开行内加粗/code 配对——Markdown.tsx 单点实现，chat/wiki 同惠） |
| 文档内查找 | 正文可见（非 generating/paused/error，与 Markdown 渲染分支同条件）时 Ctrl/Cmd+F 或工具栏放大镜呼出 FindBar（Enter=下一个 / Shift+Enter=上一个 / Esc=关闭）：叶子块匹配 → 居中滚动 + 闪烁定位。公共基座 `useMarkdownBlockFind`（2026-10-23 自本页实现抽取，期次阅读页 / 档案页 / Wiki 阅读器同源），闪烁动画统一于 global.css `.find-flash` |
| 生成中状态 | 进度条 + 百分比 + 旋转图标 + 暂停按钮（§3.8 修订）；进展日志默认展开、新日志自动滚底 |
| 暂停状态 | 「已暂停 + 进度」+ 恢复（retry resume）/ 重新生成（确认后 retry restart）按钮 |
| 错误状态 | 错误信息展示 + 恢复生成（retry resume）/ 重新生成（确认后 retry restart）按钮（§3.8.3 崩溃恢复：error 保留 checkpoint，与 paused 同构） |
| 来源面板 | registry.entries 按 source_title 聚合引用片段数（默认收起，可手动展开） |
| 日志面板 | report_logs 取最新 N 条按时间正序返回（时间轴视图：旧上新下；DB 子查询倒序截取后反转为正序，同序键以插入序稳定排列）；生成中 `usePolling` 5s 全量重取刷新（不做 `?after=` 增量——单报告日志量有限），新日志自动滚底。内容粒度：章节起止 + 每节检索/建卡摘要（query 数/通道命中/卡片数/充足性+补搜轮次）+ 降级警告 + 校验违规明细 + LLM 重试警告（§3.8 事件流） |

**导出面板**（点击工具栏「Word」弹出，点外部关闭）：

| 项 | 内容 |
|---|---|
| 页面方向 | 纵向 / 横向 radio（默认纵向，前端记忆上次选择），决定 pandoc reference-doc 样式模板（§3.7） |
| 另存为… | 主进程 dialog.showSaveDialog（默认文件名 `{标题}.docx`，标题经文件名 sanitize）→ 选定路径渲染 → toast 显示完整路径 |
| 直接打开 | 渲染到产物目录默认位置（`{标题}.docx`）→ shell.openPath 以系统默认程序打开，零选择 |

两形式共用方向选择；「直接打开」产物复用产物目录内的默认 docx（已存在则覆盖重渲染，默认文件名取 sanitize 后的标题）。看板卡片导出按钮无面板，直接弹出另存为对话框（方向沿用详情页导出面板记忆值，同一 localStorage 键）。

布局与终态不变量：详情页容器 `flex: 1` 铺满 tabContent（此前无 flex 声明，在 row flex 父容器中宽度塌缩为内容宽度）；终态（done）正文优先——进入终态边沿日志自动收起，来源 / 日志默认均收起、均可手动展开。

### 1.4 编辑策略与产品边界

应用内「查看 + 导出」、Office「精修」：墨方负责内容生成（0→1）——模板生成、Markdown 渲染、来源追溯、进度日志、导出 Word；格式呈现（1→100）——字体样式、Logo、页眉页脚、表格美化、最终审阅批注由用户导出后在 Office 内完成。应用内不提供逐章节重新生成与大纲调整（大纲变更走模板管理）。

## 2. 模板系统

### 2.1 模板结构（schema v2）

模板 = 元信息 + 大纲（outline）。

#### 2.1.1 单一真相与校验

模板 JSON 结构以 `resources/templates/_schema.json` 为单一真相：jsonschema Draft7 校验，closed schema（`additionalProperties: false`，未声明字段一律非法）。写入与加载均过校验闸门，结构演进与历史版本迁移规则见 §2.4。

#### 2.1.2 元信息字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `template_id` / `template_name` / `version` | string | 唯一标识 / 名称 / 版本号 |
| `schema_version` | int | 当前为 2（§2.4 版本化） |
| `project_types` | string[] | 适用项目类型（多选：investment / recruitment / general） |
| `stage` | string/null | 所属阶段（单选 before / during / after / null=通用） |
| `output_format` | string | 当前仅 `docx` |
| `role_hint` | string | 生成角色定位，注入 System Prompt |
| `audience` | string | 报告场景 / 读者，影响文风深度 |
| `report_depth` | enum | `full`（长文）/ `brief`（精炼），贯穿检索量、prompt、校验目标（2.1.6） |
| `global_requirements` | string[] | 全局写作要求 |
| `variables` | object[] | 变量声明（user / derived 两类，见 §2.2） |
| `subject_anchored` | boolean | 主体锚定（可选，缺省 true）：true 时 System Prompt 注入【报告主体】段（company_name）；false 时不注入——行业 / 区域 / 目标企业池类研究报告以模板变量为研究锚点，不绑定项目公司（§3.5）。optional + default 演进，不升 schema_version（§2.4） |

#### 2.1.3 章节字段

`section_id`（唯一）、`title`、`description`（给人看：检索 query 素材与前端展示，不注入写作 prompt）、`compose_mode`（`standard` 先检索再生成 / `post_body` 基于全文摘要综合，不可有子节点）、`writing_brief`（行文任务书：编号小节清单，逐条写明「写什么 + 怎么写 + 用什么形式」，作为该节写作 prompt 的主体；可选，缺省回退 description 注入，§3.5）、`prompt_hint`（任务书之外的补充约束）、`target_words`（节级篇幅护栏，覆盖全局 depth 的字数校验目标；可选 int，§3.6 规则 3；仅 full 深度生效——prompt 注入与规则 3 校验均限 full，brief 深度配置了也不注入不校验，模板应避免该组合）、`optional`（材料不足可跳过）、`position`（post_body 渲染位置 front / end）、`children`（支持多级，见 2.1.5）。三级及更深节点的 writing_brief 折叠时并入二级节 writing_requirements（§3.2）。

> 设计说明（借鉴 enterprise_report_1_1 的 edit_instructions）：长短文不由字数指标表达，而由任务书的小节数量 × 每小节深度自然涌现——篇幅是结构清单的结果。

#### 2.1.4 compose_mode 执行语义

standard 第一遍按大纲顺序执行（检索 + 生成）；post_body 第二遍在全部 standard 完成后执行，输入为各节 digest + 全文关键数据表，不做任何检索。

#### 2.1.5 多级大纲与归一化

大纲 1/2 级结构恒定，不因数据多寡增删节点；三级及更深层级在执行前由归一化折叠为二级节点的写作要求（writing_requirements），交 LLM 在节内组织（§3.2）。

#### 2.1.6 report_depth 的贯穿影响

| 维度 | full | brief |
|------|------|-------|
| System Prompt 深度指令 | 详尽长篇、多角度、数据详实 | 每节 200-500 字、结论先行 |
| 检索量（每通道 top_k） | 20 | 10 |
| digest 目标字数（纲要式：主题/论点覆盖清单，不搬运数值与引用编号） | 120 字 / 节 | 60 字 / 节 |
| 字数校验（规则 3） | 启用（目标 = 节级 target_words 或 1200，±20%） | 不启用（与「200-500 字」指令冲突） |

#### 2.1.7 变量占位符注入（声明式 `{{}}`）

解析出的变量值通过模板文本中的 `{{name}}` 占位符注入，注入位置由模板作者写在 title / description / prompt_hint / writing_brief 中决定；`list` 以顿号连接为字符串；`UNRESOLVED`（None）注入空串。大纲不因变量取值增删节点——无循环展开语法（早期的 foreach / item_as 列表展开已移除，残留字段由加载器治愈层剥离，见 §2.4）。

### 2.2 变量模型（研究 DAG）

变量三分类：

| 类别 | 声明位置 | 取值时机 | 例子 |
|---|---|---|---|
| 隐式·项目上下文 | 不声明，恒可用 | 运行时从 projects 行映射 | `company_name` / `credit_code` / `project_name` / `project_type` / `stage` |
| 用户输入 `source: user` | `variables` | 向导 Step2 填写 | `报告期` / `行业` |
| 派生 `source: derived` | `variables` | 生成前变量解析层求值（§3.1） | `产业领域` / `竞争对手` |

user 变量字段：`name / source / label / required / placeholder`；derived 变量字段：`name / source / label / depends_on[]（构成 DAG，成环校验报错）/ derive_hint（自然语言解析指令）/ data_sources[]（knowledge / internet；internet 受报告级总开关 gating，knowledge 中的项目知识库受向导 include_project_kb 开关 gating，§1.2）/ cardinality（scalar / list）`。

**降级**：派生变量解析失败 → `UNRESOLVED`，下游 `depends_on` 变量连锁降级，消费节按 §3.3 材料不足路径处理（跳过或 sparse 写作模式）。

**必填防护**：`required`（默认 true）的 user 变量缺失或仅空白（向导初始值即空串，空白不是有效输入）→ 变量解析入口 fast-fail 抛 `TEMPLATE_VARIABLE_ERROR`（message 列出缺失 label、建议返回向导填写），不进入任何检索/生成——避免空串静默注入 prompt 后生成跑题内容（optional 变量缺失仍走 UNRESOLVED 降级链路）。

**边界**：本模型是「模板声明的、在 knowledge + internet 上的研究 DAG」，不是运行时自主 agent——研究计划的自适应发生在编写期（§2.3.2 样例提取产出 DAG 草稿、人工在编辑器 review 冻结），运行期确定性执行。单变量解析为 one-shot（一轮检索 + 一次抽值，§3.1.1）。

### 2.3 自定义模板创建与编辑器

#### 2.3.1 三种创建入口

统一进入同一编辑器：上传样例提取（LLM 草稿预填）/ 从预置复制（完整副本）/ 空白创建（空表单）。

#### 2.3.2 上传样例 LLM 提取流程

`template_extractor.py`，`POST /reports/templates/extract-sample`：

```
上传样例文件（.docx 或 .pdf）
  → 文档解析：python-docx 提取全文 + 标题样式 / PDF 提取文本与结构
  → LLM 全文分析（单次调用，结构化 JSON 输出）：
      大纲结构、每节 description / writing_brief / prompt_hint、audience、role_hint、
      global_requirements、project_type / stage 推断、
      变量 DAG 草稿（user 输入项 + derived 依赖链）
  → _sanitize_variables 清洗（治愈优先：字段补全 / 非法项丢弃）
  → 返回模板 JSON 草稿（未保存）→ 进入编辑器人工审阅
```

提取策略为 LLM 全文分析而非仅读标题样式——样例格式千差万别，LLM 能统一处理并提取语义信息；编辑器是必备能力（LLM 草稿不追求完美，人工调整出成品）。

#### 2.3.3 模板编辑器（TemplateEditor，内嵌于编辑抽屉）

| 区域 | 可编辑内容 |
|------|----------|
| 基本信息 | template_name、version、project_types、stage、output_format、role_hint、audience、report_depth、subject_anchored（「以项目公司为报告主体」复选框，缺省勾选）（template_id 只读） |
| 大纲编辑 | 递归树任意层级：增删节点、同级上移 / 下移、提升 / 降级；post_body 禁止子节点 |
| 节点字段 | title、description、compose_mode、writing_brief、prompt_hint、target_words、optional、position（section_id 自动生成） |
| 全局配置 | global_requirements |
| JSON 源码 | 完整 JSON 读写；切换 tab / 保存时校验（可解析、必填字段、version 格式、section_id 全局唯一、post_body 无子节点），失败阻止并提示 |

### 2.4 模板 schema 版本化与迁移

显式 `schema_version` + 链式迁移注册表（loader.py）：`CURRENT_SCHEMA_VERSION = 2`；`MIGRATIONS = {1: _migrate_v1_to_v2, ...}`（未来升级追加）；`migrate_template()` 幂等（已是当前版本原样盖章返回，未知 / 更高版本返回 None）。

**版本探测**（`detect_schema_version`）：优先读显式 `schema_version`；无版本号时结构探测（节点用 `id` 而非 `section_id`、存在 v1 专属废弃字段 `terminology` / `word_count` 等、`output_format` 非 docx → 判 v1）。注意 `variables` 在 v1 / v2 均存在（仅形状不同），不作判据。

**v1 → v2 迁移内容**：节点 `id` → `section_id`（递归）；v1 扁平字符串 variables 转换为结构化 user 变量（保留原名）；删除废弃字段（顶层 `terminology`；节点 `word_count` / `query_hints` / `notes` / `must_cite` / `data_sources` / `promote_subhead`）；`output_format` 归一 docx；盖章。

**v2 内部治愈层**：`foreach` / `item_as` 节点字段已随列表展开能力移除（改为声明式 `{{}}` 注入，2.1.7）——每次加载均剥离残留（与 v1 判定分离，不升版本），使手写 / 陈旧模板通过 closed schema 校验。

**自定义模板升级机制（不静默删数据）**：

| 情形 | 处理 |
|------|------|
| 迁移 + 校验成功 | 原地自动升级：首次备份原文件为 `.json.bak`（不覆盖已有），写回迁移后 JSON + 更新 DB 缓存 |
| 迁移 / 校验失败 | 保留文件与 DB 行，记入 `_custom_problems`；列表「待升级」徽章 + 一键升级通道；删除为最后手段 |

**三条触发链路**（自动为主、手动兜底）：① 冷启动——`main.py lifespan()` 创建进程级 TemplateLoader 单例（deps.template_loader），预置无条件重载 + 自定义逐个 migrate+validate；② 读取自愈——`get_template()` 读 DB 缓存后再迁移，不同则回写；③ 手动——`POST /templates/{id}/upgrade`：能修则治愈刷新；修不了返回 best-effort 迁移结果 + 校验错误，前端以 JSON 源码页 + 错误条打开编辑器引导修复。

**演进纪律**：新增字段一律 optional + default（不升版本不写迁移，永不新增必填字段）；破坏性变更才升 `schema_version` + 注册一次性迁移；jsonschema 校验是闸门、引导修复是兜底——即便某版本跳跃没写迁移，模板也落入「待升级 + 引导修复」而非死胡同。写入时 `save_custom_template` / `copy_template` 均 setdefault 盖章当前版本。

### 2.5 模板管理页（全局）

模板管理为全局功能（侧边栏底部入口，与基础库并列、跨项目共享、独立顶级页无返回按钮）。列表占满全宽：筛选栏（名称搜索 + 项目类型 + 阶段 + 刷新，筛选变化时重置两个表格页码）+ 预置 / 自定义两个独立分页表格（每页 10 条，8 列：名称 / 类型徽章 / 阶段 / 报告深度 / 章节数 / 版本 / 更新时间（预置为 `-`）/ 操作）。

查看 / 编辑以右侧覆盖式抽屉呈现（`position: fixed`，宽 `min(72vw, 980px)`，遮罩 / Esc / × 关闭）：
- 查看抽屉双 tab：「结构化」（元信息 + 章节树全字段）与「JSON」（归一化对象全 key 呈现 + 一键复制）
- 编辑抽屉：内嵌模板编辑器（§2.3.3）
- 状态迁移：查看 → 编辑（自定义）/ 复制后编辑（预置）；保存成功关闭并刷新；关闭一律丢弃未保存编辑

操作规则：预置模板只读不可删，可「复制」为自定义后编辑；自定义模板可编辑 / 删除；「待升级」徽章行（§2.4 迁移失败者）提供一键升级入口。筛选栏尾部「刷新」按钮（仅「报告模板」分区呈现；填表模板分区数据源独立不走此通道）触发 `reports:refreshTemplates` → POST /reports/refresh-templates 强制重载预置 + 自定义模板后重拉列表，成功 toast 报告总数、期间按钮禁用旋转，失败 toast 报错。

## 3. 生成引擎

执行模型：一次生成 = 后台任务（FastAPI BackgroundTasks）内运行 ReportRunner；Runner 是 async generator，逐节 yield 事件，路由层消费事件写库 / 记日志 / 推进度（§3.8）；全程逐节点 checkpoint，崩溃后可 resume 续跑。

**数据流全景**：

```
模板（DB 缓存，含变量解析短路结果）
  → 变量解析 §3.1（研究 DAG 求值 → resolved_variables + resolution_evidence）
  → 实例化 + 归一化 §3.2（{{}} 注入；多级大纲折叠为两级执行大纲）
  → 第一遍：逐 standard 节（按大纲顺序）
      LLM 检索策略 → 多通道检索 → 知识卡片 §3.3
      → 注册引用 → 生成（§3.5 prompt）+ 校验重试（§3.6 / §3.9）
      → digest 生成 + checkpoint 落盘 §3.8
  → 第二遍：逐 post_body 节（全量 digest + 关键数据表，无检索）
  → 全局收尾 §3.7（引用清理重排 / ◆转换 / 衔接润色 / 目录 / 参考来源 / 装配）
  → content.md → 导出时渲染 docx（§5 export）
```

### 3.1 变量解析层（variable_resolver.py）

生成开始前，将模板声明的 derived 变量沿 DAG 求值（隐式项目变量与 user 变量此时已就位）。产出三元组：`resolved_variables`（name → value）+ `resolution_evidence`（name → 证据文本）+ usage（token 记账）；前两者随 checkpoint 持久化，resume 时直接短路复用——解析结果确定且 token 已消耗，不重复解析。

**执行顺序**：Kahn 拓扑排序，同层就绪队列按变量名排序保证确定性；求解为串行（无依赖分支并行是未来优化）。

**internet gating**：报告级总开关 OFF 时，变量 `data_sources` 中的 internet 被强制剔除（仅 knowledge），与章节级开关语义一致（§1.2）。

**knowledge gating**：向导取消项目知识库（include_project_kb=false）时，抽值检索同样排除本项目知识库（仅勾选的基础库），与章节检索语义一致（§1.2 / §3.3）。

#### 3.1.1 one-shot resolver

每个派生变量一次求解 = 一轮检索（按 data_sources）+ 一次 LLM 抽值（build_extract_value_prompt：scalar 输出名词短语 / list 输出 JSON 数组）+ `_parse_list_value` 三级解析降级（JSON 数组 → 代码块 → 按行分割）。抽值失败 → `UNRESOLVED`（None），下游 depends_on 连锁 UNRESOLVED（§2.2 降级）。

**throwaway registry**：抽值检索使用一次性引用注册器，证据不进入正式报告的参考文献——变量解析与正文生成的引用体系完全隔离。

### 3.2 归一化与实例化（normalizer.py）

- **instantiate**：`resolved_variables` 对模板做文本级替换（json.dumps 转义后整体替换，避免部分替换破坏 JSON）；`{{\w+}}` 正则支持中文变量名；通不过校验的未声明变量抛 ValueError。
- **normalize_outline 折叠**：三级及更深节点折叠进二级节点的 writing_requirements，产出两级执行大纲（2.1.5）。
- **validate_execution_outline**：section_id 唯一、post_body 无 children。
- **get_execution_sections**：注入 `_chapter_title`（所属章标题，供 prompt 展示节位置）。

### 3.3 检索层（retrieval.py + search_strategy.py + card_builder.py）

**LLM 检索策略**（search_strategy）：每节先让 LLM 基于节定义 + 前文 digests（最近 5 节 × 500 字窗口）生成该节检索 query 列表；LLM 不可用时降级为节标题。token 记入 `search_queries` 类型。

**迭代检索循环**（多轮搜索-卡片积累）：

```
轮 1: 检索策略(3-6 query) → 三通道检索 → 建卡+充足性评估（同一 LLM 调用）── sufficient → 进入写作
          │ insufficient 且轮次 < 上限（评估同时输出补搜 queries，见下）
          ▼
      补搜 queries 三通道检索 → 增量建卡+评估（针对累计材料，再出 queries）─┐
          │ insufficient 且达上限                                        └→ sufficient → 进入写作
          ▼
      停止补搜，sparse 写作（insufficient 处置，见降级表）
```

- **轮次上限**：settings `report_retrieval_max_rounds`（默认 3，范围 1-5）；sufficient 即停，充足节零额外成本。
- **评估时机**：充足性评估嵌在建卡 LLM 调用内（card_builder 任务 5），每轮一次；补搜轮的评估针对**累计材料**（已有卡片 + 新增结果合并后整体判断），insufficient 的 reason 随轮次更新（盲区收窄）。sufficiency 输出为三字段 `{level, reason, follow_up_queries}`——**补搜 queries 由建卡调用直接产出**（刚通读全部原始材料的模型最清楚缺什么，零信息损耗，省一次独立 LLM 调用与一来一回延迟；reason 与 queries 互补：queries 是动作，reason 是日志与 UI 的审计解释）；level=sufficient 时 follow_up_queries 为空数组（prompt 规则防偏置）。
- **增量建卡**：`build_knowledge_cards` 接受 `existing_cards`——已确认卡片原样保留（card_id 与已注册引用编号不漂移），LLM 仅为新增 raw 提卡；补搜轮 user 消息同时注入**已用 queries 全量清单**（含轮 1 检索策略产物），prompt 硬约束 follow_up_queries 不得语义重复（清单仅百 token 级）。
- **跨轮去重**：新增 raw 先按 `(source_type, source_from)` 与已有卡片对比粗滤，`registry.register_card` 三元组 key（§3.4）兜底精确去重。
- **补搜 queries 生成**（内联于建卡调用，无独立 LLM 请求）：模型在 prompt 中已具备全部决策要素——章节信息（标题 + 写作要求）、全部原始检索结果、existing_cards、已用 queries 清单；对 insufficient 判定输出 2-4 组 follow_up_queries（JSON 字段）。降级路径：建卡 LLM 失败走 `_fallback_cards`（无 queries）→ 不补搜直接 sparse 写作（与独立查询生成同告失败的情形等价）。
- **可观测**：每轮检索/建卡/评估结果以事件上报（§3.8），报告日志可见「第 N 轮补搜：+X cards (sufficient|insufficient: reason)」。

**三通道并行检索**（asyncio.gather(return_exceptions=True)，单通道异常不拖垮整体，降级为 warning）：

| 通道 | 启用条件 | 实现 |
|---|---|---|
| knowledge | include_project_kb（默认勾选可取消，§1.2）或勾选了任一基础库——任一存在即启用 | KnowledgeSearchTool（[2.2 §6](2.2knowledge-base-design.md) 向量 + BM25 + RRF 融合）；query × 检索范围（include_project_kb 时含本项目 + 勾选基础库，否则仅基础库）组合并行（Semaphore 4）；chunk_id 去重按 score 排序；片段截断 500 字 |
| wiki | include_project_kb（§1.2，随项目内材料同一开关门控）且项目存在已完成页面（compiled / user_edited）时启用 | search_wiki 引擎（[2.6](2.6wiki-design.md)，enable_graph=True）；页面集拉取一次多 query 复用；片段截断 800 字 |
| internet | 报告级总开关 + 节级开关（仅 standard）+ 网络搜索已配置（`web_search_provider` 已选且对应 Key 非空，经 `web_search_cfg_from_settings` 归一） | 按供应商分发（retrieval.py `_web_search_api`）：**Tavily**——每 query max_results=5，include_answer 仅非 CJK query（answer 段不受 language 控制，中文摘要失真回归 c2f24e5c），answer 条目以 `tavily://answer/` 伪 URL 进入且 score=1.0；`language: zh-cn` 语言加权（中文 query 命中质量，纯加权不丢结果）；认证走 `Authorization: Bearer` header；轮 2+ 补搜 `search_depth` 走 settings `report_tavily_search_depth`（Tavily 专属，默认 basic，可选 advanced=2 credits，仅补搜轮生效）。**智谱**——`POST /api/paas/v4/web_search`，`search_query` ≤70 字符硬限截断、`search_intent: false`、`content_size: "high"`，引擎走 settings `zhipu_search_engine`（默认 search_pro）；响应 `search_result[]` 无 score，按返回序号倒序加权（`len-i`）。失败警告 `_search_failure_warning` 按供应商生成文案（401/403 Key 无效、402 额度、429 超限、连接类、兜底，均带「设置 > 基础配置 > 网络搜索」指引）；429 指数退避（2s / 4s，最多 2 次） |

top_k 按深度：full=20 / brief=10（每通道，2.1.6）。

**知识卡片**（card_builder）：`build_knowledge_cards` 将原始片段聚合为结构化卡片（card_id 格式 `C{section_id[:4]}_{序号:03d}`，含来源类型标签与 source_title / source_from）；LLM 构建失败时 `_fallback_cards` 直接包装原始片段。同时产出充足性评估 `sufficiency`（三字段：level / reason / follow_up_queries，§3.3 迭代循环）。

**降级与跳过判定**（检索层内完成）：

| 情形 | 判定 | 后果 |
|---|---|---|
| 全通道无结果 + optional=true | skip | 节输出哨兵文本「（本节因材料不足已跳过）」，不进入正文实质内容（模板作者明确允许跳过，语义不变） |
| 全通道无结果 + optional=false | is_degraded | sparse 写作模式（§3.5）：开头声明信息局限 → 仅陈述可确证事实 → 转宏观 / 方法论论述 → 将信息缺失本身作为风险分析；禁虚构数据与引用；字数校验不启用（借鉴 enterprise_report_1_1 sparse 分支：材料稀疏不是跳过，而是换一种写法） |
| 部分通道失败 / 材料有限 | warnings / insufficient | 显式警告写入报告日志（分文案：Key 未配置 / 401 / 402 / 429 / 网络失败，含修正指引）；insufficient 先触发补搜（见迭代检索循环，上限内），达上限仍 insufficient 时 prompt 注入 sparse 指令（弱化版：材料可支撑的维度正常写，不足的维度按 sparse 纪律处理），字数校验下限放宽至 60% |

### 3.4 引用 Registry（registry.py）

全局单例 CitationRegistry 贯穿全程：卡片注册时按三元组 key `(source_type, source_from, content_hash16)` 去重后发号 `[n]`；生成时 `format_cards_for_prompt` 输出卡片与给定编号；post_body 用 `format_source_list` 列可用引用；收尾阶段 `mark_cited` / `remove_uncited` / `renumber_and_remap` 清理未引用条目并重排编号映射正文（§3.7）；终态序列化到产物 registry.json（前端来源面板消费）。

### 3.5 生成层 Prompt（prompts.py）

| Prompt | 构成 |
|---|---|
| System Prompt（全文共享） | 角色（role_hint）+ 场景（audience）+ 主体（company_name，仅 subject_anchored=true 时注入，§2.1.2；行业 / 区域 / 企业池类模板不注入）+ 深度指令 + 文风规则（客观克制 / 段落 150-300 字 / 数字规范 / 「本报告」「我们认为」/ 术语解释到位 / 不改写材料事实 / 分析判断必须给依据与不确定性）+ **行文形式规范（全文统一，代码层承载，借鉴 enterprise_report_1_1 ChapterEditorAgent 输出规范，pandoc 支持矩阵实测闭环）**：结构化对比数据优先 Markdown 表格 / 流程与结构关系可用 mermaid 图（graph / timeline / gantt / pie / xychart-beta，每图配文字说明与数据解读）/ 关键结论可用引用块强调 / 公式用 LaTeX（$…$ 或 $$…$$）/ 禁内联 HTML 与补充平面 emoji（pandoc 导出丢失语义或乱码，BMP 几何符号 ↑↓© 可用）；数据口径与来源标注沿用数字规范的行文要求（括号注明），不用 markdown 脚注——多节生成期 LLM 无法协调全局唯一脚注编号，pandoc 遇重名定义静默取首个，跨节错乱风险不可接受 + 输出契约 6 条：不写节标题 / [n] 紧跟句末 / 仅可用给定编号 / 列表≤5 项 / 无总结套话 / 无前言 |

| 辅助 | digest 纲要生成（目标 120/60 字）、关键数据提取、变量抽值（§3.1.1） |

**前文摘要窗口**：standard prompt 的前文摘要注入**全量**已完成节 digest（纲要式定位：列「本节写了哪些方面」而非内容简写，不搬运具体数值——数据统一由关键数据表供 post_body；逐节 120/60 字总量可控，不截断），用于衔接与避免重复；无「全局一页纸摘要」（全量 digest 本身即逐节摘要视图，无需再造）。

### 3.6 校验层（validator.py）

每节生成后规则校验（编号沿用代码内常量，无规则 6）；违规带反馈重试（反馈进 messages，MAX_RETRIES=3，仍违规取最后一次）；每次重试与最终接受均将违规明细（规则号 + 内容 + 级别）写入 app.log（INFO/WARNING）与报告日志（warning 事件，§3.8）：

| # | 规则 | 判定 |
|---|---|---|
| 1 | 引用编号子集 | 输出中 [n] 必须属于本节给定编号集合 |
| 2 | 禁用 markdown 标题 / 正文加粗 | 正文不得包含 # 标题（节标题由组装层生成）；加粗检查排除表格行与围栏代码块内（表格单元格粗体是合法强调形式，配合 §3.5 形式规范） |
| 3 | 字数 | full 模式 standard 节：目标 = 节级 target_words（有则用）否则 1200，±20%；brief 不启用；sparse 降级节不启用 |
| 4 | ◆ 小标题长度 | 生成期内联小标题标记 ≤15 字 |
| 5 | 结尾套话 | 「综上所述 / 总而言之」等收尾禁止 |
| 7 | 首行正文 | 首行不得为前言说明性文字 |

**全局校验**（收尾阶段 validate_global）：幻觉引用修复（`fix_hallucinated_refs`——超出可用集合的 [n] 直接删除）、未引用条目清理、编号连续性。

### 3.7 全局收尾与渲染（finalizer.py + renderer.py）

3. **衔接润色**：悬空过渡词、空行压缩两类规则（原「节首重复标题」规则已上移至装配层——装配层持有节题上下文，子节化后按章比对失效，见第 4 步）。
4. **目录 / 参考来源 / 装配**：runner._assemble_full_text 按**两级大纲结构**组装（2026-10-27 一级目录修复，此前展平执行节全部输出 `## n` 导致章级在正文与目录中双双丢失）：有 children 的章 → `## n 章题` + `### n.m 节题`（子节号章内递增、跨章随章号）；无 children 的章平铺 `## n 标题`（向后兼容）；post_body 章前置（front）/ 后置（end）重排，post_body 子节独立成章（自定义模板边界形态，原章留剩余子节不空壳）；无内容子节跳过、全空章整体不出现，章/子节编号按最终呈现顺序连续注入——序号写进标题文本作为单一事实源，网页端预览（Markdown 原文渲染）、docx 导出、目录三方同源一致，不依赖模板 numPr 或前端 CSS counter。节首重复标题剥离在本层执行（节首行剥 `n[.m]` 号后与节题比对，命中即删）。_build_toc 两级目录：扫描 ## 生成章条目（目录行保留 `idx.` 列表序号、剥标题前导号避免双号）、### 生成缩进子节条目（`n.m 标题`）；文末「参考来源」列表由 registry 生成（引用展示形态见下「渲染」视觉尾注）；全文按 `## 标题` + 空行 + `---` 分隔逐章组装。

### 3.8 生命周期与容错（runner.py + routers/reports.py）

**状态机**：generating → done / error / paused（error 携 error_message；error / paused 可 resume / restart；paused 为报告级暂停稳定态，§3.8 修订）。

**事件流**：Runner.run() 逐节 yield 七类事件——section_start / section_done / progress / warning / paused / complete / error；路由层 `_run_report_generation` 消费：

| 事件 | 路由层动作 |
|---|---|
| section_start / progress | 更新进度与报告日志；收尾阶段以 progress 事件 phase=finalizing 标记，进度推进至 95 |
| section_done | 写 report_sections（内容 / 状态 / 字数 / compose_mode）+ 进度 = int(完成节数 / 总节数 × 90) + 检索摘要写报告日志（query 数 / 各通道命中 / raw→cards / 充足性 level+reason / 补搜轮次与每轮 follow_up_queries，§3.3） |
| warning | 写报告日志（面向用户的降级文案；含校验违规明细 §3.6 与 LLM attempt 失败 §3.9） |
| paused | 状态置 paused（保留进度；checkpoint 已随最后完成节落盘）+ activity_events.pause_report 通知（异步生效的稳定态需感知，未读查重防重复）；本轮事件流终止 |
| complete | content.md 落盘 + registry 写产物 + activity_events 终态（0.4 活动中心），进度 100（token 无收尾回写——调用时已由 llm/usage.py 收口逐条落库，见 [2.10](2.10token-usage-design.md)） |
| error | 状态置 error + error_message + 活动终态 |

进度模型：章节阶段封顶 90%、收尾 95%、完成 100%（导出不在进度内）。

**并发限制**：settings `report_max_concurrent`（默认 2）；generate 前先 `ensure_ready("report")` 就绪度校验，再检查活跃报告数，超限返回 429。

**报告级暂停**（§3.8 修订；替代原队列级暂停——settings `report_paused` 键与 generate/retry 的 423 拒绝已删，0.4 §6.7 同步收敛为两类）：

- **请求**：`POST /reports/{report_id}/pause` 校验 status=generating（缺失 404 / 非 generating 409）→ 写 reports.pause_requested 标志即返回；
- **生效**：Runner 构造时注入 pause_check 探针，两遍循环每节开头检查——请求在章节生成中到达不打断 LLM 调用，当前章节完成（checkpoint 已落盘）后 yield paused 事件终止推进 → status=paused 稳态；
- **出口**：恢复 = retry(resume) 从 checkpoint 续跑（保留进度、清标志）；重新生成 = 确认后 retry(restart) 删 checkpoint 全量重跑（进度归零、清标志）；
- **语义**：paused 不占并发名额（count_active_reports 只扫 generating）、崩溃恢复不碰 paused（启动扫描只扫 generating）；按钮落点：报告卡片 + ReportPreview 正文区。

**崩溃恢复**：
- **checkpoint**（产物目录 checkpoint.json，逐节落盘）：outputs / digests / order / registry / resolved_variables / resolution_evidence 六字段（原 token_tracker 字段已随 2.10 单源迁移移除，token 记录在调用时即已持久落库，断点恢复天然无损）。**原子写**（临时文件 + os.replace）——直接覆盖在写入中途被杀会留半写 JSON，resume 解析失败静默全量重跑；checkpoint 损坏时 resume 返回用户可见 warning 并从第 1 节重跑（不静默）。resume 从最后一个完成节继续（变量解析短路复用；运行配置 template_id / variables / base_project_ids / internet / include_project_kb 从报告行恢复，行为与中断前一致）；restart 删 checkpoint 全量重跑（配置同样从报告行恢复）。章节边界同时是报告级暂停的停点（§3.8 修订）——暂停复用崩溃恢复的同一断点机制。
- **启动扫描**：服务启动时将**所有** generating 状态的报告标记 error（进程重启后 runner 必然已死，任何 generating 均为孤儿；不设时间阈值——曾用 5 分钟阈值，只会在重启后留下进度不推进、暂停无人消费的「假生成中」窗口）。
- **retry 双模式**（status ∈ error / paused）：resume（默认，从 checkpoint 续跑；paused 保留原进度）/ restart（删 checkpoint + 清空 report_sections 旧行后全量重跑，进度归零）；两者均清 pause_requested 遗留标志；从 DB 恢复 template_id / variables / base_project_ids / internet / include_project_kb 配置后重新入队。

#### 3.8.7 Token 统计（已迁移，[2.10token-usage-design.md](2.10token-usage-design.md)）

原 token_tracker.py 独立记账已由全局用量记录层取代：每次 LLM 调用时经 `llm/usage.py` 收口逐条落 `llm_usage` 表（entity_id=report_id，purpose 细分口径见 2.10 §3.3），section 级明细由 `detail.section_id` 还原。reports.token_usage 列、token_usage.json 产物、checkpoint 内 token_tracker 字段均已移除。

### 3.9 智能重试分类（runner.py `_generate_with_retry`）

两级分类：

1. **结构化错误类优先**（isinstance）：LLMInvalidKey / LLMQuotaExhausted / LLMModelNotFound → fatal（不重试，直接 error 终态）；LLMRateLimited / LLMNetworkError → 可重试（指数退避）。
2. **字符串规则兜底**（`_classify_error`，异常对象无结构化信息时）：content_filter → 降级模式重试一次（prompt 追加中性事实陈述重写指令 + sparse 口径生成，字数校验不启用），重试仍失败返回占位文本（finish_reason=error 终态）——不静默返回空串（空串会在组装时静默消失、成品缺节且 resume 永不补）；context_length → **保尾截断**（写作任务与参考资料位于 prompt 尾部必须保住，digests 段在头部被优先裁剪，段落边界切割）至 4000 字重试一次，耗尽同样落占位文本；429 / timeout → 指数退避重试；空响应 → 直接重试。

校验违规重试独立于错误分类：带反馈 messages 重试（§3.6，MAX_RETRIES=3）。

**降级终态可观测**：占位文本进正文与 checkpoint；`section_done` 携 `generation_failed` 标志 → 路由层写 error 级报告日志「章节生成失败」（用户在详情页显式可见，文案带重新生成指引）；占位节不产 digest——后续章节的检索策略不应把占位说明当作已有内容。

**输出截断可观测**：chat_full 返回 finish_reason；`length`（输出被 max_tokens 截断，reasoning 模型思考 token 亦计入输出预算）→ logger.warning + 报告日志 warning 事件（用户可见），不重试（同参数重试无意义，字数校验是 full 模式的次级兜底）。配套：报告路径 LLM settings 输出预算抬升 `max(用户设置, 32000)`（同 wiki/ingest 先例）。
