## 1. 阅读模型：加载链是关系的根

ppt-master 的 md 不是平级资料，而是**按「强制加载序」组织的运行时程序**（SKILL.md §Mandatory Load Order）：

```
SKILL.md（入口，恒读）
  └─ ① scripts/attribution_guard.py 非零即停（协议墙）
  └─ ② workflows/routing.md（路由权威，恒读）
       └─ ③ 选定唯一路由 → 只读该路由的 runtime authority：
            generate-pptx.md / quick-generate.md / beautify-pptx.md /
            image-to-pptx.md / create-template.md / template-fill-pptx.md /
            native-enhance-pptx.md
            └─ ④ 路由权威按步骤显式触发的支撑文档：
                 stages/*（阶段）、references/roles（角色切换）、
                 references/tech（条件技术规范）、templates/*_reference（产物 schema）
```

三条铁律（写 InkCube 系统提示时必须保留的语义）：

1. **selected authority only**：路由选定后禁读其他路由的过程文件；Default 与 Quick 互斥（Default 不读 quick-generate.md，反之亦然）。
2. **支撑文档只被显式触发**：stages 与 references 不预载，按路由步骤的条件分支加载（executor-base §开头有完整分支路由表）。
3. **角色切换协议**：进入新角色前必须先读对应角色 reference 并播报 `[Role Switch]`（SKILL.md §Global Communication Rules）——InkCube 的 agent 提示词工程需保留此协议输出。

### 4.3 零入引（孤儿）分类

| 类别 | 例子 | 定性 |
|---|---|---|
| 数据文件型 | 内置模板 41 个 design_spec、image-palettes 成员、sound/chart/table-vocabulary | **设计使然**：md 只是数据载体，靠 _index/目录注册表连接，不需要被文档引用 |

| 维护者型 | workflows/index.md | 设计使然：运行时不读，维护者专用 |
| 合规型 | THIRD_PARTY_NOTICES ×2、NOTICE | 设计使然 |
| 遗留型 | `image-palettes/`（连 _index 也无文档引用） | **唯一真疑点**——E1 研读时向 image 链（strategist-image/image-generator）验证是否仍在消费；若已废弃，InkCube 打包时可裁剪 |

### 4.4 关系类型总结（五种边）

1. **强制链边**：SKILL.md → routing.md → 路由权威（恒读，不可跳过）
2. **显式触发边**：路由权威 → stages / 角色规范（步骤内「Read X」指令）
3. **条件分支边**：executor-base → 8 分支 / L7 条件规范（内容特征驱动）
4. **schema 契约边**：strategist / template-designer → templates/*_reference（产物字段权威）
5. **数据索引边**：_index → 成员（运行时查表，非文档引用）
