## 3. Layer 1：崩溃检测 + 自动保存

### 3.1 自动保存 agent state

**改动文件**: `python/agent/task_agent.py` — `_run_inner()` 主循环

每个 iteration 完成后，保存**完整的 messages 列表**（含 tool_calls 和 tool 结果）到 `task_agent_state` 表：

```python
# _run_inner 主循环，约 L1141 处
for iteration in range(start_iteration, max_iter):
    # ... 执行 _handle_fc_iteration ...
    if fc_completed:
        if fc_status == "continue":
            # ── 自动保存完整状态（用于崩溃恢复）──
            self.db.save_agent_state(task_id, {
                "messages": messages,  # 完整列表，含 system/user/assistant(tool_calls)/tool
                "iteration": iteration + 1,
                "recent_errors": list(recent_errors),
                "auto_saved": True,
            })
        elif fc_status in ("done", "error"):
            self.db.delete_agent_state(task_id)
            yield {"type": "done", "data": {}}
            return
```

**关键**: 保存完整 `messages`（含 `tool_calls`/`tool_call_id`），而非仅 `role`+`content`。否则恢复后 LLM 无法配对 tool call 与 tool result。

## 4. Layer 2：per-task 流式状态 + 运行状态指示

### 4.1 核心改造：useTaskChat.ts

**实际架构（混合模式）**:

活跃任务使用 React state（驱动 UI 渲染），后台任务使用 `useRef<Map>` 存储（不触发渲染）。

```typescript
interface BgTaskState {
  content: string; reasoning: string; steps: StreamStep[]; iteration: number;
  isGenerating: boolean; planData: PlanData | null;
  iterationReasoning: Map<number, string>; iterationThoughts: Map<number, string>;
  pendingShellConfirm: ShellConfirmData | null; pendingSkillConfirm: SkillConfirmData | null;
}

// 后台任务状态（不触发渲染）
const bgStates = useRef<Map<string, BgTaskState>>(new Map())

// 活跃任务状态（React state，驱动渲染）
const [isGenerating, setIsGenerating] = useState(false)
const [streamContent, setStreamContent] = useState('')
const [streamSteps, setStreamSteps] = useState<StreamStep[]>([])
// ... 其他字段
```

**设计决策**: 不使用 `useState<Map>` 存储所有任务状态。原因：后台任务每秒可能收到多个 SSE 事件，如果每次事件都触发 React 渲染，会造成不必要的性能开销。使用 ref 存储后台状态，仅在切换任务时通过 save/restore 同步到 React state。

### 4.2 事件处理改造

**当前**: `task:stream` 监听器按 `activeTaskIdRef` 过滤，丢弃非活跃任务事件。

```typescript
// 当前（L64-67）:
const off = window.electronAPI.on('task:stream', (data: unknown) => {
  const { taskId, type, data: payload } = data as { ... }
  if (taskId !== activeTaskIdRef.current) return  // ← 丢弃后台任务事件
  handleStreamEventRef.current(type, payload)
})
```

**改为**: 不过滤，按 taskId 路由到不同处理函数。

```typescript
const off = window.electronAPI.on('task:stream', (data: unknown) => {
  const { taskId, type, data: payload } = data as { ... }
  if (taskId === activeTaskIdRef.current) {
    handleStreamEventRef.current(type, payload)    // 活跃任务 → React state
  } else {
    handleBgStreamEventRef.current(taskId, type, payload)  // 后台任务 → ref Map
  }
})
```

`handleStreamEvent` 操作 React state（驱动渲染），`handleBgStreamEvent` 操作 bgStates ref（不触发渲染）。两者逻辑基本对称，`handleBgStreamEvent` 同样处理 `confirm_shell`/`confirm_skill` 事件——将其存入 bgStates，用户切换到该任务时恢复并显示确认卡片。

### 4.3 状态读取

活跃任务直接使用 React state 变量（无需从 Map 查找）：

```typescript
// 活跃任务的流式状态 — 直接是 React state
const isGenerating = /* useState */ ...
const streamContent = /* useState */ ...
const streamSteps = /* useState */ ...
// 切换任务时通过 save/restore 同步 bgStates ↔ React state
```

切换逻辑（`useEffect([activeTaskId])`）：
- 切走：将当前 React state 快照存入 `bgStates.set(prevId, ...)`
- 切入：从 `bgStates.get(activeTaskId)` 恢复到 React state，或 `clearStreamState()` 如果无缓存

### 4.4 切换行为

```
切换任务（activeTaskId 变化）:
  ├─ 将当前 React state 快照存入 bgStates（保存）
  ├─ 从 bgStates 恢复目标任务的 state 到 React state，或 clearStreamState()
  ├─ 后台任务的流式状态继续累积到 bgStates ref（不受影响）
  └─ 切回时恢复累积的状态（无丢失）
```

## 5. Layer 3：暂停/恢复 UI 补全

### 5.1 修复 resume → chat 衔接流程

**问题**: `POST /tasks/{id}/resume` 只重存 state，没有触发 agent 继续执行。

**修复**: 修改 `tasks:chat` 支持 `resume` 标志。

```python
# python/schemas.py
class TaskChatRequest(BaseModel):
    task_id: str
    message: str
    resume: bool = False  # 新增

# python/routers/tasks.py — task_chat
if req.resume:
    state = deps.db.load_agent_state(task_id)
    if not state:
        return {"error": "没有可恢复的任务状态"}
    # 不保存 user 消息，直接触发 agent

    deps.db.save_task_message(task_id, "user", req.message)
    deps.db.update_task_title_from_message(task_id, req.message)
```

```javascript
  // ...
```

## 7. 数据流图

### 7.1 多任务并行（Phase 2 后）

```
Task A 运行中 → 用户切换到 Task B
  ├─ Task A 的 SSE 连接仍然活跃（Electron 层）
  ├─ Task A 的 task:stream 事件继续到达前端
  ├─ handleBgStreamEvent('taskA', ...) → 累积到 bgStates ref（不触发渲染）
  ├─ 前端显示 Task B 的消息历史（isGenerating=false，可输入）
  ├─ Task A 在任务列表显示 ⟳ 运行中指示器
  └─ 用户切回 Task A → 直接显示累积的流式状态（无丢失）
```

### 7.2 崩溃恢复

```
任务运行中 → Python 进程崩溃
  → SSE reader done → 无 done 事件
  → python-manager: process.on('exit') → python:process-exit
  → 前端: isGenerating=false, 显示 banner

Python 重启:
  → lifespan(): 检测 task_agent_state 残留
  → auto_saved=True → 写入中断提示消息（保留 state）
  → 前端: has-state API 返回 true → canResume=true → 显示恢复 banner
  → 用户点击 [▶ 恢复] → tasks:chat(resume=true) → _run_inner 检测 state → 继续
```

### 7.3 暂停/恢复

```
暂停: ⏸ → pause_task_chat → get_messages(task_id) 取 in-memory messages
       → pause_task() 保存完整 state（含 tool_calls/tool_call_id）
       → cancel → done → isGenerating=false
恢复: ▶ → tasks:chat (resume=true) → _run_inner 检测 state → 继续
```

**关键**: pause 端点使用 `_task_messages[task_id]` 获取 in-memory 消息（含 `tool_calls`/`tool_call_id`），而非从 DB 截断。否则恢复后 LLM 无法配对 tool call 与 tool result。

## 8. 边界情况

| 场景 | 处理方式 |
|------|---------|
| 恢复时模型已更换 | 正常。state 只保存 messages，不保存模型配置 |
| 恢复时工作区文件已修改 | 正常。工具读取当前文件状态 |
| 自动保存失败 | 只记 warning，不中断任务 |
| 多个任务同时崩溃 | 各自独立恢复，按 task_id 隔离 |
| 恢复过程中再次崩溃 | 下次启动再次检测，再次提示（已加防重复：检查最后一条消息是否已是中断标记） |
| 暂停后删除任务 | `delete_task` 同步清理 `task_agent_state`（防止残留 state 干扰 `has-state` API） |
| 恢复时 tool_calls 引用的工具已变更 | LLM 根据当前工具列表重新决策 |
| 3 个任务都在运行，用户只看一个 | per-task state 各自累积，列表显示 3 个 ⟳ |
| 后台任务需要 shell 确认 | `handleBgStreamEvent` 处理 `confirm_shell`/`confirm_skill` 事件，存入 bgStates。用户切换到该任务时恢复为 React state，显示确认卡片。用户确认后正常发送 IPC 响应。 |
| context collapse 在自动保存后触发 | 恢复后首次 iteration 会再次检查压缩 |
