# V2.1 组合周报 + 知识册导出实施计划（0.6 §9 V2.1 候选行细化）

> 依据：[0.6v2-ux-redesign.md](../../docs/0.6v2-ux-redesign.md) §9 V2.1 行（「订阅 scope 扩展：盯梢 / 撒网 / 组合周报三型 + 知识册导出（复用 docx 生成器）」；原文标注「实施前单独细化」——本计划即细化产物，详细设计随 T1 落 2.11 增补节）。
> 验收：组合周报按周期自动产出且四动线可读；知识册导出 docx 可打开且含图片；vitest/pytest/tsc/build/orphan audit 全绿 + CodeReview 收口。

## 现状盘点（2026-10-24 探查）

| 项 | 现状 |
|---|---|
| 订阅模型 | `task_schedules`（id/name/prompt/mode/category corporate·industry·region·general/interval_type/interval_value/target_type/target_id/archive_file_id/auto_import/enabled/next_run_at）；无 scope 字段——「盯梢（定点企业）/撒网（产业·区域赛道）」目前只是 category 的概念映射，非结构化维度 |
| 执行链 | Run = 影子 tasks 行（schedule_id 关联，D2）+ `task_schedule_runs` 历史；复用 1.1 chat 执行链；产出 workspace md + `data/schedules/{run_id}.md` 副本（D5，阅读视图优先读副本） |
| 汇总能力 | 零——期次副本只被阅读视图单期消费，无跨期次/跨订阅聚合读取端点 |
| docx 生成器 | `python/report_generator/renderer.py: render_markdown_to_docx`（报告生成链在用，md→docx 含图片处理先例）；知识册编译产物为结构化 md（WikiTab 编译视图，成册进度环 + 台账时间轴） |
| 知识册导出挂点 | WikiTab 现无导出入口；项目级导出（2.9 project_export）不含知识册 docx 形态 |

## 设计裁决

1. **组合周报 = 汇总型订阅，非新采集引擎**：`task_schedules` 加 `scope` 列（TEXT，`'focus' | 'sweep' | 'digest'`，默认 `'focus'` 存量零迁移回填）；digest 型订阅的「执行」不发送采集 prompt，而是读取既有订阅近期期次副本（`data/schedules/*.md` + run 历史聚合）→ LLM 跨订阅汇总 → 产出组合周报。执行仍走影子任务链（D2 不破坏），复用并发闸门与 G5 让路约束。
2. **scope 三型语义**：`focus` = 现有定点盯梢（corporate 类归此）；`sweep` = 撒网（industry/region 类归此）；`digest` = 组合周报（新建订阅时可选，prompt 由系统按 scope 组装而非用户手写——digest 的 prompt 输入是「近期期次摘要集合」）。存量订阅 scope 回填规则 = category 映射（corporate→focus、industry/region→sweep、general→focus），一条 UPDATE 迁移幂等可重入。
3. **组合周报范围可配**：digest 订阅带 `digest_schedule_ids`（JSON 数组列，NULL = 全部启用订阅）——「我的盘子」由用户圈选，默认全量；期次窗口 = 上次 digest 执行时刻至今（时间基准不变量同 §6.3 规则 13）。
4. **知识册导出 = WikiTab 封面动作**：编译完成态封面加「导出 docx」钮 → 既有编译产物 md（按目录序拼接）→ `render_markdown_to_docx` → 落 `{workspace}/exports/`（复用项目导出目录惯例）→ 完成后 toast + 打开文件。零新表；导出记录不落库（文件即产物，重复导出覆盖写）。
5. **零新轮询**：组合周报产出沿用 task 终态心跳 + 四动线通知；导出为同步短任务（IPC invoke 即完成，超长册分块拼接上限见 T1 设计）。
