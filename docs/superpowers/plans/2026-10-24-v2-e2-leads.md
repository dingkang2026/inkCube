## Global Constraints
- 只动呈现层之外的**新增器官**：数据流变化全部登记于 0.6 §5（E2 已预登记 5 通道），通道语义零临时发明。
- 新表启动幂等建表（CREATE TABLE IF NOT EXISTS）、失败向上抛阻断启动（对齐 db/database.py 惯例）；存量数据零迁移（新表）。
- 列表接口一律分页契约 `limit/offset/has_more/total`（0.1 §16）；LeadPool 前端挂载 `limit=0` 全量（状态分组视图需全集，薄卡池量级小，属选择器/分组场景豁免）。
- 提取候选**零自动入池**（必须勾选确认，§6.3-10）；转任务/存线索/提取都不自动补完语义。
- 线索池薄卡不变量（§6.3-8）：只有名称/来源/状态/备注/立项指向，禁止 CRM 器官。
- 新文案双语 i18n；硬编码禁令（0.3 §5）；关键操作走统一日志框架。
- 验证：TDD（失败测试先行）；每任务 py_compile/tsc + 定向测试；收口 pytest + tsc + vitest + build + orphan audit 四组 0。

## T2 routers/leads.py 五端点 + 注册
- `GET /leads`（status 可选 + limit/offset/has_more/total）；`POST /leads`（name 必填非空；source_type ∈ run|manual；run 来源须带 source_run_id + source_schedule_name 快照）；`PATCH /leads/{id}`（status 值域 new/contacting/evaluating/hold/converted + note/project_id；404）；`DELETE /leads/{id}`（404）；`POST /leads/extract`（run_id → 候选清单）。

- main.py：import + include_router（注册序随 schedules 后）。
- 测试：端点级（TestClient），extract 用 monkeypatch 假 LLM。

## 已裁决取舍（PM 决策登记）
1. 批量入池 = 前端循环调 leads:create（5 通道契约不变，N 次小事务；不做批量端点）。
2. LeadPool 全量拉取（limit=0）：分组视图需全集；池为薄卡器官（§6.3-8 反 CRM）量级天然受限；端点仍带完整分页契约。
3. 升级订阅复用 ScheduleFormModal + prefill prop 扩展（新建态专用），不复制弹层代码。
4. 提取已在池判定在前端做（leads:list 既有通道 limit=0），不加查询参数端点。
5. 立项类型选择复用 ProjectType（recruit/invest/general），不含 business_attraction（非项目类型词表）。
