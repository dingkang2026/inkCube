# 0.5 产品化整改 E2 实施计划 — 模板持久化 · 导入通道 · 新产出角标

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 落地 0.5 文档 E2 期——task_templates 表与自定义模板 CRUD、任务文件「导入到项目/基础库」（含 E3 依赖的底层导入链）、卡片墙「新产出」角标、ProjectChatPanel 模板复用、Onboarding 收尾衔接。

**Architecture:** 后端新增 1 表 + 4 REST 端点 + 4 IPC 通道（同变更内落地前端消费）；导入链零新增通道（复用 `knowledge:uploadFile` / `baseLib:upload`，`files/content` 端点扩展 `?b64=1` 参数）；角标从通知 unread 派生，零写入零新增轮询。

**Tech Stack:** React 18 + TypeScript + vitest；Python FastAPI + pytest；SQLite。

**Spec:** `docs/0.5product-redesign.md`（§2 缺口能力表 / §4.4 模板体系 / §5 task_templates DDL / §6 数据流 / §7 前端交互 / §8 E2 验收）。交互以该文档文字设计为准。

## Global Constraints

- 0.5 §5：内置模板不落库（始终以 i18n 为准）；表只存自定义行 + 内置置顶态（builtin=1 upsert 行）。
- 新增 4 个 IPC 通道必须同变更内落地前端消费（§2.9 孤儿零容忍）；交付前 `node dev/_orphan_channel_audit.js` 四组为 0。
- 「新产出」零写入：消费端从通知 unread 派生，禁止新建表/列/轮询。
- 导入是长时活动：走现有 file 活动注册（`_upload_core` → worker 队列），零新增 kind。
- 全部新增文案 zh-CN/en-US 双语（规范 §2.3）；键集合一致用 `node dev/_check_i18n_keys.js` 验证。
- 每任务完成即验证：`npx tsc --noEmit`（前端）/ `pytest python/tests/<file> -v`（后端）→ 最终统一 `npm run build` + 全量测试。
- **git 操作由用户手动执行**：各任务 commit 步骤实施者只核对暂存清单。
