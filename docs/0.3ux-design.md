# 全局 UX 设计规范 — "零培训"目标

> 墨方 InkCube 前端全局交互与视觉规范：布局结构、图标体系、统一交互模式、状态色与国际化。各功能模块的具体交互见对应专项文档（[0.4](0.4lifecycle-design.md) 活动体系、[2.1](2.1project-design.md) 项目、[2.2](2.2knowledge-base-design.md) 知识库、[2.5](2.5report-design.md) 报告、[2.6](2.6wiki-design.md) Wiki）。

## 1. 概述

**目标："零培训"** — 用户无需阅读文档或培训，打开软件就能理解每个按钮的含义和操作方式。

四条设计原则：

| 原则 | 含义 |
|------|------|
| 文字优先 | 操作按钮用文字标签（或图标 + 文字），不依赖纯图标/符号猜含义 |
| 状态可见 | 关键信息（运行状态、工作目录、模式、处理进度）在列表与界面上直接呈现 |
| 图标统一 | 全部使用 Lucide SVG 图标，经中央注册表统一分发；禁止 emoji 当图标 |
| 中英双语 | 所有 UI 文案经 i18next（zh-CN / en-US），不硬编码文案 |

产品决策：**不做暗色主题**，单一浅色主题。

要点：

- **对等页面无返回按钮**：设置页 / 模板管理 / 基础库详情为主内容区全量替换渲染（非弹窗），Sidebar 常驻 + TitleBar 侧栏切换按钮覆盖全部退出路径
- **侧栏可折叠**；Wiki 沉浸模式（`app:wiki-immersive` 事件）自动折叠侧栏，退出沉浸时恢复折叠前状态
- **设置页锚点直达**：`app:navigate-settings` 事件携带 `section`，设置页滚动到对应区块（首页红卡 / 向导 / 错误处理器共用此通道）

**图标语言规范（2026-10-19 全量收敛）**：

| 规则 | 定义 |
|------|------|
| lucide 优先 | UI 图标一律 lucide-react；emoji 禁入 UI（跨平台字体渲染不可控、彩/黑不一致） |
| 文件类型图标 | `src/features/task/utils.ts` `fileIcon()` 统一返回 lucide 组件（兼容 `file.pdf` / `.pdf` / `pdf` 三形态），任务域 FileTree 与知识域 FileUploader 共用，禁止各自建映射 |
| 内置工具图标 | `SkillManagement.tsx` `TOOL_ICONS` 按 tool name 映射；后端 `BUILTIN_TOOLS` 不再下发 icon 字段（图标属 UI 语言） |
| 状态图标 | 可用/不可用 → `CheckCircle2` / `XCircle`（色随 `--success` / `--error`）；Toast 四态 → CheckCircle2/XCircle/Info/TriangleAlert |
| 几何符号白名单 | 单色文本符号渲染稳定且全站一致，保留：`↑↓`（token 方向）、`→ ←`（分页/推进）、`▾ ▴ ▸`（折叠）、`↔`（关联）；关闭/刷新等有 lucide 对应的职能不在此列（`✕` `↻` `×` 已全部 lucide 化） |
| 后端不下发图标 | 服务端契约不携带 emoji/图标字段，图标映射属前端职责 |

## 4. 统一交互模式

### 4.1 列表项操作（hover 文字按钮）

任务项（TaskItem）、项目项（ProjectSidebar）等列表项统一模式：

```
默认：  标题
        元信息（时间 · 消息数 · 工作目录后两级 · 模式标签）
hover：  标题                    [重命名] [删除]   ← 右侧滑入，删除为红字
```

- 操作按钮用**文字**，不用图标猜含义
- 删除操作红色文字（`--error`）

### 4.2 全局弹窗（ConfirmDialog / PromptDialog）

全局 promise 式确认弹窗（`src/components/ConfirmDialog.tsx`，`useConfirm()` 消费，替代原生 `window.confirm`）：

- 结构：可选标题 + 消息 + [取消] [确认]
- `danger` 选项：确认按钮红色（默认 true），用于删除/危险操作
- 交互：Escape / 点击遮罩取消；打开时确认按钮自动聚焦
- i18n：按钮文案经 i18next

全局 promise 式输入弹窗（`src/components/PromptDialog.tsx`，`usePrompt()` 消费，替代原生 `window.prompt`——Electron 不支持该 API，调用即抛异常）：

- 结构：可选标题 + 可选提示文案 + 输入框 + [取消] [确认]；确认返回输入值（可能空串），取消 / Escape / 遮罩返回 `null`
- 交互：打开时输入框自动聚焦并全选；Enter 确认
- Provider 挂载：两者均在 `main.tsx` 挂载（ConfirmProvider > PromptProvider）

### 4.3 状态色规范

以 CSS 变量落地于 `src/styles/global.css`，全局统一语义：

| 状态 | 视觉 | CSS 变量 | 色值 |
|------|------|---------|------|
| 成功 / 正常 | 实心圆点 | `--success` | `#22c55e`（绿） |
| 失败 / 错误 | 实心圆点 / 红字 | `--error` | `#ef4444`（红） |
| 危险 chip | 红字 + 浅红底 | `--text-danger` / `--bg-danger` | `#dc2626`（红）/ `#fef2f2`（底） |
| 警告 / 注意 | 橙点 / 橙字 + 浅橙底 | `--text-warning` / `--bg-warning` | `#d97706`（橙）/ `#fffbeb`（底） |
| 运行中 / 处理中 | 脉冲圆点 / spinner | `--accent` | `#2563eb`（蓝） |
| 等待 / 待定 | 空心圆点 | `--text-muted` | `#9ca3af`（灰） |

适用：服务状态卡片、文件解析状态（灰=待处理、蓝=解析中、绿=完成、红=错误）、工具卡片结果（绿=成功、红=失败）、能力徽章（✓支持 / ✗不支持 / ?未知）、自动保存状态（保存中/已自动保存/失败红字）、脉搏带与知识健康卡的状态 chip（危险/警告底色对，3.0 一期；不另增 token，直接消费上表既有变量）。

### 4.4 设置页自动保存

设置页（`SettingsPage.tsx`）无"保存"按钮：

- 任一字段改动后 **800ms 静默期**自动全量落盘（连续输入/滑块拖动合并为一次）
- 标题行右侧显示保存状态：保存中… → 已自动保存 / 失败（红字）
- 页面卸载（切换导航）时未落盘修改立即 flush
- 保存后回灌跳过自身快照，避免保存飞行中的新输入被旧值回滚
- **加载基底合并**：`useSettings` 以 `DEFAULT_SETTINGS` 为基底合并 `settings:get` 响应（缺键回退默认值）——dev 后端进程无热重载，新增字段键要等进程重启才进响应，直接断言会让受控输入收到 undefined（React 判为非受控，首次输入即报 "changing an uncontrolled input to be controlled"，2026-10-15 实证）；回归：tests/useSettings.test.tsx
- 「测试并检测能力」按钮独立于自动保存，保留原位；连通后探测 Function Calling / 思考深度 / 思考开关，结果为三枚能力徽章（遵循 §4.3 状态色），探测结论不锁定配置

**设置页布局规范（2026-10-19 规范化）**：

| 层 | 规范 |

| 外部模型详情 | 连接配置 + 模型槽位（2026-10-19 路由拆出并档位化）：基础连接（含 LLM 连接/读取超时，自通用移入）→ 模型槽位（标准模型 / 高配模型两槽手填，开箱默认 glm-5.3-flash / glm-5.3，互为回退——单槽空回落另一槽，两槽均空则依赖路由的管线就绪度告警；旧全局模型单键废弃；vlm 三键随 2026-10-21 独立 VLM 链路删除，图片理解统一走 standard 档，两槽 hint 注明模型须为多模态）→ 生成参数 → 系统提示词（工具密钥已拆出为独立「网络搜索」条目，同日供应商化）；密钥显隐用 lucide Eye/EyeOff（aria-label 双语） |

### 4.6 首启引导（Onboarding）

新用户判定（无 API key、无内部模型、无项目、无任务、未完成引导）自动弹出 `OnboardingWizard`：① 配置外部模型 → ② 配置网络搜索（可跳过）→ ③ 下载内部模型 → ④ 开始使用。「去配置 / 去下载」会挂起向导跳转设置页对应锚点，设置页关闭后回到向导继续，引导不断开。完成标记落库（`/onboarding/done`）；完成后若零项目 → 自动导航至项目欢迎页三步引导（衔接 [0.5 §4.3](0.5product-redesign.md)，`navAfterOnboarding` 纯函数；已有项目则停留当前页）——「引导卡的下一步就是引导本身」（0.5 E2 已落地，2026-10-19）。

### 4.7 空态即引导与产品化文案（0.5 整改，E1 已落地）

> 以下为 [0.5](0.5product-redesign.md) §4.1 确立的全局原则，适用于所有页面（原型已废弃，交互以文档文字为准）。E1 范围（首页重排/项目欢迎页三步引导/任务欢迎页模板化）已于 2026-10-18 落地，其余页面随各页整改继续对齐。

| 原则 | 规则 |

| 空态即引导 | 每个空状态必须回答「这是什么 + 我下一步该点哪里」，并给出可点击动作（新建/发起/上传），禁止仅一句静态描述 |

首页信息架构已按 [0.5 §4.2](0.5product-redesign.md) 落地（服务状态卡移出首页、今日概览条、快捷动作卡）；空数据区块保留显示空态占位（2026-10-18 用户裁决，首页完整性优先于「空即隐藏」）。E2 扩展落地（2026-10-19）：项目内对话面板空会话空态 = 引导语 + 项目作用域模板网格（复用任务欢迎页 TaskTemplatePanel，「空态即引导」原则延伸到会话面板）。
