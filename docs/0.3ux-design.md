# 全局 UX 设计规范 — "零培训"目标

> 墨方 InkCube 前端全局交互与视觉规范：布局结构、图标体系、统一交互模式、状态色与国际化。各功能模块的具体交互见对应专项文档（[0.4](0.4lifecycle-design.md) 活动体系、[2.1](2.1project-design.md) 项目、[2.2](2.2knowledge-base-design.md) 知识库、[2.5](2.5report-design.md) 报告、[2.6](2.6wiki-design.md) Wiki）。

## 1. 概述

**目标："零培训"** — 用户无需阅读文档或培训，打开软件就能理解每个按钮的含义和操作方式。

四条设计原则：

| 原则 | 含义 |
|------|------|
| 文字优先 | 操作按钮用文字标签（或图标 + 文字），不依赖纯图标/符号猜含义 |
| 状态可见 | 关键信息（运行状态、工作目录、模式、处理进度）在列表与界面上直接呈现 |
| 图标统一 | 全部使用 Lucide SVG 图标，经中央注册表统一分发；禁止 emoji 当图标 |
| 中英双语 | 所有 UI 文案经 i18next（zh-CN / en-US），不硬编码文案 |

产品决策：**不做暗色主题**，单一浅色主题。

## 2. 全局布局

### 2.1 窗口结构

```
┌──────────────────────────────────────────────┐
│ TitleBar（品牌 · 菜单 · 侧栏切换 · 窗口控制）      │
├──────────┬───────────────────────────────────┤
│ Sidebar  │  主内容区                            │
│ NavTabs  │  （首页 / 任务页 / 项目页 /           │
│ 列表区    │    设置页 / 模板管理 / 基础库详情，     │
│ UserBar  │    互斥全量渲染）                     │
├──────────┤                                    │
│(ResizeHandle 拖拽宽度 200~480，双击重置 260)      │
└──────────┴───────────────────────────────────┘
```

| 组件 | 文件 | 职责 |
|------|------|------|
| TitleBar | `src/components/layout/TitleBar.tsx` | 品牌、四组菜单（文件/编辑/视图/帮助）、侧栏折叠切换、窗口控制（自绘 SVG：最小化/最大化还原/关闭） |
| Sidebar | `src/components/layout/Sidebar.tsx` | 承载 NavTabs、模块列表区（项目侧栏 / 任务列表）、UserBar、BaseLibFooter |
| NavTabs | `src/components/layout/NavTabs.tsx` | 三个导航 Tab + 活动徽章（§2.2） |
| ResizeHandle | `src/components/layout/ResizeHandle.tsx` | 侧栏宽度拖拽（`useResizeHandle(260, 200, 480)`） |
| UserBar | `src/components/layout/UserBar.tsx` | 设置入口、模型下载进行中圆点 |

要点：

- **对等页面无返回按钮**：设置页 / 模板管理 / 基础库详情为主内容区全量替换渲染（非弹窗），Sidebar 常驻 + TitleBar 侧栏切换按钮覆盖全部退出路径
- **侧栏可折叠**；Wiki 沉浸模式（`app:wiki-immersive` 事件）自动折叠侧栏，退出沉浸时恢复折叠前状态
- **设置页锚点直达**：`app:navigate-settings` 事件携带 `section`，设置页滚动到对应区块（首页红卡 / 向导 / 错误处理器共用此通道）

### 2.2 导航与徽章

导航 Tab（`NavTabs.tsx`）：

| Tab | key | 图标 | 徽章（数据来自 ActivityContext） |
|-----|-----|------|--------------------------------|
| 首页 | `home` | `Home` | — |
| 任务 | `tasks` | `Wrench` | 运行中任务数（数字徽章） |
| 项目 | `projects` | `BookOpen` | 摄入进行中（Loader2 呼吸图标）+ Wiki 待审阅数（数字徽章） |

徽章是 Activity Hub 的 L1 层呈现，数据流见 [0.4 §5](0.4lifecycle-design.md)。

### 2.3 键盘快捷键

| 快捷键 | 作用 | 实现位置 |
|--------|------|---------|
| Ctrl+1 / 2 / 3 | 切换 首页 / 任务 / 项目 | App.tsx 全局 keydown |
| Ctrl+, | 打开设置 | TitleBar.tsx |
| Ctrl+Q | 退出 | TitleBar.tsx（经 `menu:action` IPC） |
| Ctrl+= / - / 0 | 缩放 放大 / 缩小 / 重置 | TitleBar.tsx（输入焦点时不劫持缩放键） |

菜单（`menuDefinition.ts`）：文件（设置 / 退出）、编辑（撤销 / 重做 / 剪切 / 复制 / 粘贴 / 全选）、视图（三项缩放）、帮助（关于 / 查看日志 / 导出日志）。

## 4. 统一交互模式

### 4.1 列表项操作（hover 文字按钮）

任务项（TaskItem）、项目项（ProjectSidebar）等列表项统一模式：

```
默认：  标题
        元信息（时间 · 消息数 · 工作目录后两级 · 模式标签）
hover：  标题                    [重命名] [删除]   ← 右侧滑入，删除为红字
```

- 操作按钮用**文字**，不用图标猜含义
- 删除操作红色文字（`--error`）

### 4.2 全局弹窗（ConfirmDialog / PromptDialog）

全局 promise 式确认弹窗（`src/components/ConfirmDialog.tsx`，`useConfirm()` 消费，替代原生 `window.confirm`）：

- 结构：可选标题 + 消息 + [取消] [确认]
- `danger` 选项：确认按钮红色（默认 true），用于删除/危险操作
- 交互：Escape / 点击遮罩取消；打开时确认按钮自动聚焦
- i18n：按钮文案经 i18next

全局 promise 式输入弹窗（`src/components/PromptDialog.tsx`，`usePrompt()` 消费，替代原生 `window.prompt`——Electron 不支持该 API，调用即抛异常）：

- 结构：可选标题 + 可选提示文案 + 输入框 + [取消] [确认]；确认返回输入值（可能空串），取消 / Escape / 遮罩返回 `null`
- 交互：打开时输入框自动聚焦并全选；Enter 确认
- Provider 挂载：两者均在 `main.tsx` 挂载（ConfirmProvider > PromptProvider）

### 4.3 状态色规范

以 CSS 变量落地于 `src/styles/global.css`，全局统一语义：

| 状态 | 视觉 | CSS 变量 | 色值 |
|------|------|---------|------|
| 成功 / 正常 | 实心圆点 | `--success` | `#22c55e`（绿） |
| 失败 / 错误 | 实心圆点 / 红字 | `--error` | `#ef4444`（红） |
| 危险 chip | 红字 + 浅红底 | `--text-danger` / `--bg-danger` | `#dc2626`（红）/ `#fef2f2`（底） |
| 警告 / 注意 | 橙点 / 橙字 + 浅橙底 | `--text-warning` / `--bg-warning` | `#d97706`（橙）/ `#fffbeb`（底） |
| 运行中 / 处理中 | 脉冲圆点 / spinner | `--accent` | `#2563eb`（蓝） |
| 等待 / 待定 | 空心圆点 | `--text-muted` | `#9ca3af`（灰） |

适用：服务状态卡片、文件解析状态（灰=待处理、蓝=解析中、绿=完成、红=错误）、工具卡片结果（绿=成功、红=失败）、能力徽章（✓支持 / ✗不支持 / ?未知）、自动保存状态（保存中/已自动保存/失败红字）、脉搏带与知识健康卡的状态 chip（危险/警告底色对，3.0 一期；不另增 token，直接消费上表既有变量）。

### 4.4 设置页自动保存

设置页（`SettingsPage.tsx`）无"保存"按钮：

- 任一字段改动后 **800ms 静默期**自动全量落盘（连续输入/滑块拖动合并为一次）
- 标题行右侧显示保存状态：保存中… → 已自动保存 / 失败（红字）
- 页面卸载（切换导航）时未落盘修改立即 flush
- 保存后回灌跳过自身快照，避免保存飞行中的新输入被旧值回滚
- 「测试并检测能力」按钮独立于自动保存，保留原位；连通后探测 Function Calling / 思考深度 / 思考开关，结果为三枚能力徽章（遵循 §4.3 状态色），探测结论不锁定配置

### 4.5 全局反馈通道

| 通道 | 组件 | 说明 |
|------|------|------|
| Toast | `ToastProvider`（knowledge/Toast.tsx） | 操作即时反馈 |
| 活动徽章 | NavTabs / UserBar | L1 常驻提示（§2.2） |
| 首页活动区 | HomePage | L2「进行中」活动卡 + 「最近动态」列表，见 [0.4](0.4lifecycle-design.md) |
| 进程退出横幅 | App.tsx | Python 退出时顶部横幅（退出码 + 查看日志 + 关闭） |

### 4.6 首启引导（Onboarding）

新用户判定（无 API key、无内部模型、无项目、无任务、未完成引导）自动弹出 `OnboardingWizard`：① 配置外部模型 → ② 下载内部模型 → ③ 开始使用。「去配置 / 去下载」会挂起向导跳转设置页对应锚点，设置页关闭后回到向导继续，引导不断开。完成标记落库（`/onboarding/done`）。

## 5. 国际化

- 框架：i18next + react-i18next；语言包 `src/i18n/locales/zh-CN.json`、`en-US.json`
- 切换入口：设置 → 通用（`GeneralSettings.tsx`，`i18n.changeLanguage`）
- 要求：新增 UI 文案一律进语言包（key 命名 `<module>.<name>`），组件内不硬编码中/英文

## 6. 差异与下一步优化建议

| 项 | 现状 | 建议 |
|----|------|------|
| UserBar 图标与用户名 | 设置按钮用 `⚙` 字符（未走 Lucide）；用户名 "Kelvin" 硬编码 | 换用 Lucide `Settings`；用户名接设置项或移除展示 |
| 设置项搜索 | 设置页无搜索 | 数量增多后补 Ctrl+F 设置项过滤 |
| 专业参数提示 | Temperature 等参数对普通用户偏专业 | 增加 "这是什么?" 悬浮说明 |
| 危险确认倒计时 | ConfirmDialog 无倒计时进度条（Shell/Skill 确认依赖用户手动处理，等待期由任务韧性机制接管，见 [1.3](1.3task-resilience-design.md)） | 如需"超时默认拒绝/允许"语义，在 1.3 的确认策略上统一评估，不为弹窗单独造轮子 |
| 代码注释节号漂移 | `SettingsPage.module.css` 注释引用「0.3 §3.5 v0.8.0」——自动保存设计现位于 §4.4，旧节号与版本号已失锚（代码变更，另行处理） | 随设置页样式下次改动时顺手修正注释 |
| i18n 英文复数 | 语言包含 `{{count}}` 的键均未提供 `_one/_other` 复数形式，英文单复数句式不精确（3.0 一期 review 登记；主语言中文不受影响） | 作为全仓 i18n 惯例统一处理：引入复数后缀约定后批量迁移既有键，不逐键零散修补 |
