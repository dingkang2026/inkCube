# "项目"功能整合设计文档

> 版本: 1.3.0 | 日期: 2026-09-23 | 状态: 产品方案
>
> 核心变更: 将"知识库"与"产业报告"合二为一，统称为"项目"

---

## 1. 背景与目标 

### 1.1 现状问题

墨方当前导航有 5 个入口，其中"知识库"和"报告"在概念上割裂：

- **知识库**：上传文档 → 向量化 → RAG 检索/问答（已实现）
- **报告**：预留入口，尚未实现（导航中已禁用）
- 两者的目标用户和工作流高度重叠，却分属不同入口

### 1.2 设计目标

将"知识库"和"报告"合并为**"项目"**——面向招商经理和投资经理的统一工作空间。

**核心价值主张：**

> 一个项目 = 一套完整的工作闭环：收集资料 → 知识编译 → 生成报告/填表

### 1.3 目标用户

| 角色 | 核心工作 | 典型产出物 |
|------|---------|-----------|
| **招商经理** | 招商引资、企业引进、园区推介 | 招商推介方案、项目评估报告、招商跟踪表 |
| **投资经理** | 投资尽调、项目分析、投后管理 | 尽职调查报告、投资分析报告、尽调清单 |

## 2. 信息架构

### 2.1 导航结构

**变更前 → 变更后：**

```
变更前:                          变更后:
┌──────────┐                    ┌──────────┐
│ 🏠 首页   │                    │ 🏠 首页   │
│ 💬 产业洞察 │ ──┐               │ 🛠 任务    │ ← 通用 Agent（主推通用模式）
│ 📚 知识库   │   ├→              │ 📂 项目    │ ← 合并
│ 🛠 任务    │   │               └──────────┘
│ 📊 报告(禁) │ ──┘
└──────────┘
```

- 导航项从 5 个（含 1 个禁用）精简为 **3 个**
- “产业洞察”有意撤掉，其通用 Agent 能力由“任务”承接
- 快捷键映射：Ctrl+1 首页, Ctrl+2 任务, Ctrl+3 项目

### 2.2 “任务”定位说明

“任务”是通用 Agent 入口，**主推通用模式**，同时包含编程模式。内置互联网工具，可独立完成各类任务。

**任务能做什么：**

| 能力 | 说明 |
|------|------|
| 产业问询 | 联网搜索，了解行业动态、政策信息 |
| 企业调研 | 查询企业基本情况、工商信息、融资历史 |
| 简单报告 | 生成轻量级的分析、总结、报告 |
| 通用问答 | 任何不属于具体项目的问答 |
| 编程模式 | 代码编写、数据处理等技术任务 |

**“任务”与“项目”的关系：**

| 维度 | 任务 | 项目 |
|------|------|------|
| 定位 | 轻量、即时、通用 | 重量、持续、专业 |
| 知识来源 | 互联网 + 通用能力 | 项目知识库 + Wiki + 基础库 |
| 产出物 | 一次性结果（对话、简单报告） | 结构化产出（报告、填表、Wiki） |
| 生命周期 | 用完即走 | 长期跟踪，分阶段管理 |
| 衔接 | 暂不考虑两者间的功能衔接 | — |

**Agent 能力不消失，而是下沉到项目内部：**

```
项目内部每个 Tab 都有 Agent 参与:
├── 📁 资料 — Agent 负责文档解析、RAG 检索
├── 📖 Wiki — Agent 负责知识编译、增量更新
├── 📊 报告 — Agent 负责按模板生成内容
├── 📋 填表 — Agent 负责数据提取和填充
└── 💬 Chat — Agent 负责项目级问答
```

**产品边界划分：**
- **墨方负责内容生成**（从 0 到 1）：生成报告内容、编译 Wiki、填充数据
- **Office 负责格式呈现**（从 1 到 100）：字体排版、企业标识、最终审阅

### 2.3 项目分类体系

项目分为三大类：**普通项目**、**预置基础库**和**自定义基础库**。

```
侧边栏:
┌──────────┐
│ 🏠 首页    │
│ 🛠 任务    │
│           │
│ ─ 项目 ── │
│ 📁 XX科技   │  ← 普通项目
│ 📁 YY生物   │
│ 📁 ZZ新能源  │
│           │
│ ─ 基础库 ─ │
│ 📚 招商基础库 │  ← 预置（招商引资类项目自动关联）
│ 📚 投资基础库 │  ← 预置（投资尽调类项目自动关联）
│ 📚 我的资料库 │  ← 用户自定义基础库
│    [+ 新建]  │
│           │
│ ──────── │
│ 👤 Kelvin │
│    📊  ⚙  │
└──────────┘
```

- **普通项目**：完整四 Tab 工作空间（资料 → Wiki → 报告 → 填表）
- **预置基础库**：系统内置，按角色分为招商基础库 / 投资基础库，简化版两 Tab（资料 + Wiki）
- **自定义基础库**：用户自行创建的基础库，自定义名称，同样两 Tab 结构
- 基础库被普通项目引用，报告生成时自动注入为上下文

### 2.4 两层知识架构

```
┌─────────────────────────────────────────────────┐
│              共享知识库（基础库）                   │
│  ┌──────────────┐  ┌──────────────┐             │
│  │ 招商基础库 (预置) │  │ 投资基础库 (预置) │             │
│  │ 政策、园区...  │  │ 基准、法规... │             │
│  └──────┬───────┘  └──────┬───────┘             │
│         │                 │                      │
│  ┌──────────────┐                                │
│  │ 自定义基础库…  │  ← 用户自建，名称自定            │
│  └──────┬───────┘                                │
│         │                                        │
│    ┌────┴─────────────────────────┐             │
│    │   报告/填表生成时自动注入为上下文  │             │
│    └────┬─────────────────┬────┘             │
│         │                 │                  │
│  ┌──────┴───────┐  ┌──────┴───────┐         │
│  │ 项目A 知识库   │  │ 项目B 知识库   │         │
│  │ 企业BP、财报   │  │ 企业BP、行业   │         │
│  └──────────────┘  └──────────────┘         │
└─────────────────────────────────────────────────┘
```

**知识流向：**

```
预置基础库(招商/投资) ──┐
自定义基础库(用户自建) ──┤
                       ├──→ 报告/填表 Agent ──→ Word/PPT/DOCX表单
项目库(私有) ─────────┘
```

## 3. 项目类型

### 3.1 类型定义

创建项目时选择类型，类型决定默认预设（模板可见性、Wiki 编译规则、填表模板）：

| 项目类型 | 适用角色 | 默认报告模板 | 默认 Wiki 结构 |
|---------|---------|------------|---------------|
| 🏭 **招商引资** | 招商经理 | 招商推介方案、项目评估报告、园区产业分析 | 招商政策、目标企业画像、园区概况、产业链、竞品园区对比 |
| 💰 **投资尽调** | 投资经理 | 尽职调查报告、投资分析报告、企业调研报告 | 公司概况、团队、财务健康度、法律风险、估值参考、风险清单 |
| 📊 **行业研究** | 通用 | 行业研究报告、竞争格局分析 | 行业概况、市场规模、驱动因素、竞争格局、产业链、趋势展望 |
| 📁 **通用** | 不限 | 全部模板可见 | 由 LLM 根据文档自动推断 |

### 3.2 类型的影响范围

项目类型**不改变**四 Tab 的基本结构，但影响：

| 影响维度 | 说明 |
|---------|------|
| 默认可见报告模板 | 不同角色看到不同的推荐模板 |
| 默认 Wiki 结构 | LLM Wiki 编译时遵循不同的 Schema |
| 默认可见填表模板 | 不同角色看到不同的推荐表格 |
| Agent 生成视角 | 报告生成的默认立场和风格 |

**关键原则：**
- 项目类型只是默认预设，不是限制——任何项目类型下都可以访问所有模板
- 用户可以随时在模板管理中启用/禁用特定模板
- 项目类型创建后不可更改（建议用户新建项目）

### 3.3 项目阶段（生命周期）

项目不是一次性工作，而是贯穿业务周期的持续管理。每个项目类型对应一套阶段定义：

| 项目类型 | 阶段 |
|---------|------|
| 🏭 招商引资 | 招商前 → 招商中 → 招商后 |
| 💰 投资尽调 | 投前 → 投中 → 投后 |
| 📊 行业研究 | 不分阶段（单次研究） |
| 📁 通用 | 不分阶段 |

**各阶段典型产出物：**

| 阶段 | 招商引资 | 投资尽调 |
|------|---------|----------|
| **前期** | 产业研究报告、目标企业筛选、园区推介材料 | 行业研究报告、企业调研报告、项目初筛表 |
| **中期** | 招商推介方案、项目评估报告、政策申报表 | 尽职调查报告、估值对比表、投资决策表 |
| **后期** | 落地跟踪报告、政策兑现跟踪表、企业经营跟踪表 | 投后管理报告、财务监控表、重大事项跟踪表 |

**阶段管理规则：**
- 用户**手动推进**阶段（“进入下一阶段”按钮），不是流程引擎
- 报告/填表按当前阶段分组显示
- 后期是**长周期**，会持续产出多份报告/填表（如季度投后管理报告）
- 阶段可以回退（如从“投中”退回“投前”补充材料）

### 4.4 知识问答（Chat）

Chat 面板为**项目级常驻**——不绑定某个 Tab，在任何 Tab 下都可以唤起提问。Chat 的检索范围包含：
- 当前项目的知识库文档
- 当前项目关联的基础库文档
- 当前项目的 Wiki 页面

## 5. 项目 Wiki（LLM Wiki）

> ⚠️ 本节为功能占位，详细设计待后续展开。

### 5.1 功能定位

引入 LLM Wiki 范式，作为现有 RAG 知识库的补充——将原始文档编译为结构化、互相链接的 Wiki 页面，实现知识沉淀。

| 维度 | RAG（现有） | LLM Wiki（新增） |
|------|-----------|------------------|
| 知识形态 | 向量切片（机器检索） | 结构化页面（人+AI 可读） |
| 核心价值 | 精准召回 | 知识沉淀、一致性输出 |
| 人类可读性 | 低（碎片化切片） | 高（完整 Wiki 页面） |

### 5.2 核心能力（规划）

| 能力 | 说明 |
|------|------|
| 知识编译 | 上传文档后，LLM 将原始资料编译为结构化 Wiki 页面 |
| 按项目类型编译 | 不同项目类型对应不同的 Wiki 结构（招商/投资/行业研究） |
| 页面浏览与编辑 | 用户可浏览、手动编辑 Wiki 内容 |
| 增量更新 | 新文档摄入时自动更新已有页面 |
| 来源追溯 | 每个 Wiki 页面标注来自哪些原始文档 |

### 5.3 Wiki 页面结构示例（按项目类型）

| 招商引资 | 投资尽调 | 行业研究 |
|---------|---------|----------|
| 招商政策摘要 | 公司概况 | 行业概况 |
| 目标企业画像 | 核心团队 | 市场规模与增速 |
| 园区/区域概况 | 财务健康度 | 竞争格局 |
| 产业链分析 | 法律风险 | 产业链图谱 |
| 竞品园区对比 | 风险清单 | 趋势与展望 |

### 6.2 报告编辑策略

采用**方案 B：应用内轻量编辑 + 导出 Office 精修**。

**产品边界清晰划分：**

| 层级 | 负责方 | 具体能力 |
|------|--------|--------|
| **内容生成（0→1）** | 墨方 | 按模板生成报告、逐章节重新生成、Markdown 级文字修改、调整大纲 |
| **格式呈现（1→100）** | Word/PPT | 字体样式排版、企业标识 Logo、页眉页脚、表格边框样式、最终审阅批注 |

**应用内提供的编辑能力：**

| 功能 | 说明 |
|------|------|
| Markdown 预览 + 编辑 | 修改文字内容，满足内容级修改需求 |
| 逐章节重新生成 | 对某一章节不满意，单独重新生成 |
| 调整大纲 | 增删、重排章节顺序 |
| 补充说明后重新生成 | "这段加上XX角度再写一遍" |
| 导出 Word/PPT | 最终格式调整交给 Office |

**应用内不提供的编辑能力：**

- 字体/字号/颜色调整
- 段落缩进/行距设置
- 页眉页脚/Logo 插入
- 表格边框/样式美化

这些全部由 Word/PPT 处理，用户导出后在 Office 中完成最终排版。

### 6.3 报告生成流程

```
用户选择模板 → 调整大纲 + 补充说明 → 开始生成
                                        │

                          │  逐章节生成内容            │

                          │  └─ 流式输出，实时预览       │

                          └───────────┘
                                        │
                          用户编辑/确认 → 导出 Word/PPT
```

**关键设计点：**
- **逐章节生成**：每章独立生成，支持单章节重新生成
- **多源知识融合**：自动从项目知识库 + 基础库 + Wiki 中提取相关内容
- **来源可追溯**：每个章节标注引用了哪些文档
- **流式输出**：用户实时看到生成进度和内容

- **模板分享**：自定义模板支持导出为文件，其他用户可导入使用

## 7. 填表系统

### 7.1 概述

填表是相对于报告的另一种产出形式——**结构化数据填充**，而非自由文本生成。主要输出格式为 **Word 表单**（DOCX 表格），部分场景支持 XLSX。

### 7.2 预置填表模板

| 表格名称 | 适用项目类型 | 输出格式 | 说明 |
|---------|------------|---------|------|
| 项目登记表 | 招商引资 | DOCX 表单 | 招商项目基本信息登记 |
| 招商跟踪表 | 招商引资 | DOCX 表单 | 招商进度跟踪、对接记录 |
| 政策申报表 | 招商引资 | DOCX 表单 | 企业政策扶持申报 |
| 尽调清单 | 投资尽调 | DOCX 表单 | 尽调所需资料清单与完成情况 |
| 投资决策表 | 投资尽调 | DOCX 表单 | 投资决策核心要素汇总 |
| 估值对比表 | 投资尽调 | XLSX | 同行业估值数据对比（表格场景） |

### 7.3 填表流程

```
选择表格模板 → 系统从知识库/Wiki 自动提取数据 → 填充表格 → 用户校验 → 导出
```
