## 1. 目标与约束

### 1.1 目标

- 所有任务智能体所需工具链（Python / uv / rg / ruff / pandoc）随安装包捆绑分发，用户零配置即可使用
- LibreOffice 不捆绑，运行时检测并引导安装
- Windows 平台先行，macOS / Linux 后续跟进

### 1.2 约束

- 安装包体积控制在合理范围（方案 B 后含 RAG 依赖 site-packages，约 1.5-2GB；AI 模型不随包，首次使用时下载）
- 开发阶段仍使用 conda 环境，打包后切换到捆绑版本，业务代码无需修改
- 跨平台路径差异需统一抽象

## 4. 路径解析抽象层（核心）

### 4.1 现状问题

当前各工具的路径查找逻辑分散在各个文件中，各自独立实现：

| 文件 | 方法 | 查找逻辑 |
|------|------|---------|
| `venv_manager.py` | `_find_uv()` | frozen → exe 旁 resources/ → PATH |
| `package_manager.py` | `_find_uv()` | PATH → app_dir/resources/ |
| `code_search.py` | `_find_rg()` | PATH → app_dir/resources/ |
| `code_lint.py` | `_find_ruff()` | PATH → app_dir/resources/ |
| `code_format.py` | `_find_ruff()` | PATH → app_dir/resources/ |

问题：
- 逻辑不统一（有的先查 PATH，有的先查 bundled）
- 没有环境变量覆盖机制
- 新增工具需要重复写查找逻辑
- 开发环境与生产环境切换不灵活

### 4.2 统一方案：`python/tools/tool_resolver.py`

新建统一的路径解析模块，所有工具查找走同一个入口：

```python
"""统一工具路径解析器。

三级查找策略：
1. 环境变量覆盖（开发/测试用）
2. 安装包捆绑路径（生产环境）
3. 系统 PATH 查找（兜底/开发环境）
"""
import os
import sys
import shutil
from pathlib import Path

# 工具注册表：工具名 → (环境变量名, 二进制文件名列表)
_TOOL_REGISTRY = {
    "uv":     ("INKCUBE_UV_PATH",     ["uv.exe", "uv"]),
    "rg":     ("INKCUBE_RG_PATH",     ["rg.exe", "rg"]),
    "ruff":   ("INKCUBE_RUFF_PATH",   ["ruff.exe", "ruff"]),
    "pandoc": ("INKCUBE_PANDOC_PATH", ["pandoc.exe", "pandoc"]),
}


def _get_app_data_dir() -> Path:
    """获取 %APPDATA%/InkCube/ 路径。"""
    if sys.platform == "win32":
        base = os.environ.get("APPDATA", Path.home() / "AppData" / "Roaming")
    elif sys.platform == "darwin":
        base = Path.home() / "Library" / "Application Support"
    else:
        base = os.environ.get("XDG_CONFIG_HOME", Path.home() / ".config")
    return Path(base) / "InkCube"


def _get_bundled_dir() -> Path:
    """获取安装包捆绑工具目录。

    生产环境：从 %APPDATA%/InkCube/tools/ 查找（历史回退路径，实际由 python-manager
    显式传 env 覆盖，见 §9）
    开发环境：从项目 resources/tools/ 查找
    """
    if getattr(sys, "frozen", False):
        # PyInstaller 时代的历史分支（方案 B 后 sys.frozen 恒为 False，仅保留兼容）
        return Path(sys.executable).parent / "resources" / "tools"
    # 开发环境：项目根目录/resources/tools/
    project_root = Path(__file__).resolve().parent.parent.parent
    return project_root / "resources" / "tools"


def resolve_tool(name: str) -> str | None:
    """解析工具路径，返回绝对路径或 None。

    查找优先级：
    1. 环境变量 INKCUBE_{NAME}_PATH（开发/测试覆盖）
    2. 捆绑目录 %APPDATA%/InkCube/tools/{name}.exe
    3. 开发环境 resources/tools/{name}.exe
    4. 系统 PATH（shutil.which）
    """
    if name not in _TOOL_REGISTRY:
        raise ValueError(f"未知工具: {name}")

    env_var, bin_names = _TOOL_REGISTRY[name]

    # 1. 环境变量覆盖
    env_path = os.environ.get(env_var)
    if env_path and os.path.isfile(env_path):
        return env_path

    # 2 & 3. 捆绑路径（生产: %APPDATA%/InkCube/tools/，开发: resources/tools/）
    bundled_dir = _get_bundled_dir()
    for bin_name in bin_names:
        candidate = bundled_dir / bin_name
        if candidate.is_file():
            return str(candidate)

    # 生产环境额外检查 %APPDATA%/InkCube/tools/（与 exe 不在同级目录时）
    if getattr(sys, "frozen", False):
        app_data_tools = _get_app_data_dir() / "tools"
        for bin_name in bin_names:
            candidate = app_data_tools / bin_name
            if candidate.is_file():
                return str(candidate)

    # 4. 系统 PATH
    for bin_name in bin_names:
        found = shutil.which(bin_name)
        if found:
            return found

    return None


def resolve_python() -> str | None:
    """解析 python-build-standalone 的 Python 路径。

    用于创建任务 venv 时作为 --python 参数。
    注意：这不是后端运行时的解释器（方案 B 后后端直接用 python-build-standalone
    运行 main.py；本函数指向 tool-initializer 解压到 userData 的副本，供任务 venv
    隔离使用，见 §9）。

    查找优先级：
    1. 环境变量 INKCUBE_PYTHON_PATH
    2. %APPDATA%/InkCube/python/python.exe（生产环境解压后）
    3. resources/tools/python-build-standalone/python.exe（开发环境）
    4. sys.executable（兜底：使用当前 Python）
    """
    # 1. 环境变量
    env_path = os.environ.get("INKCUBE_PYTHON_PATH")
    if env_path and os.path.isfile(env_path):
        return env_path

    # 2. 生产环境
    app_data_python = _get_app_data_dir() / "python"
    exe_name = "python.exe" if sys.platform == "win32" else "python3"
    candidate = app_data_python / exe_name
    if candidate.is_file():
        return str(candidate)

    # 3. 开发环境
    project_root = Path(__file__).resolve().parent.parent.parent
    bundled = project_root / "resources" / "tools" / "python-build-standalone" / exe_name
    if bundled.is_file():
        return str(bundled)

    # 4. 兜底
    return sys.executable
```

## 5. 首次启动初始化

### 5.1 流程

安装后首次启动，Electron 主进程在 `app.whenReady()` 中执行初始化：

```
app.whenReady()
  → 检查 %APPDATA%/InkCube/tools/ 是否已存在且完整
  → 若缺失或不完整：
      从 process.resourcesPath/tools/ 复制到 %APPDATA%/InkCube/tools/
      从 process.resourcesPath/tools/python-build-standalone/ 复制到 %APPDATA%/InkCube/python/
      生成 tool-versions.json
      通知前端显示进度（"正在初始化任务环境..."）
  → 确保用户数据目录结构存在：
      创建 %APPDATA%/InkCube/data/templates/
      创建 %APPDATA%/InkCube/data/reports/
      创建 %APPDATA%/InkCube/data/projects/
      创建 %APPDATA%/InkCube/data/logs/
  → 继续正常的 PythonManager.start() + createWindow()
```

> 复制全部采用异步 IO（`fs.promises`，libuv 线程池），不阻塞 Electron 主进程事件循环，
> 窗口/进度保持响应。

### 5.2 完整性检查

通过 `tool-versions.json` 判断是否需要重新解压：

```json
{
  "python": "3.12.13+20250617",
  "uv": "0.11.7",
  "rg": "14.1.1",
  "ruff": "0.12.0",
  "pandoc": "3.6.4",
  "prepared_at": "2026-09-22T00:00:00Z"
}
```

当应用更新时，比较版本号，若有变化则重新解压。

## 6. pandoc 捆绑方案

### 6.1 为什么捆绑

- pandoc 只有 ~30MB，体积可接受
- 用户不应为了生成 DOCX 文档还要自行安装工具
- 当前已有外部依赖检测 UI，如果检测不到只提示安装，体验割裂

### 6.2 捆绑方式

| 平台 | 捆绑内容 | 说明 |
|------|---------|------|
| Windows | pandoc 安装包中的 `pandoc.exe` | 单文件，无外部依赖 |
| macOS | `pandoc` 二进制 | 从 .pkg 中提取 |
| Linux | `pandoc` 二进制 | 从 .deb/.tar.gz 中提取 |

### 6.3 优先级

运行时 pandoc 查找优先级：
1. 环境变量 `INKCUBE_PANDOC_PATH`
2. 捆绑路径 `%APPDATA%/InkCube/tools/pandoc.exe`
3. 系统 PATH（用户自行安装的更新版本）

如果用户系统已安装 pandoc，优先使用系统版本（可能更新）。但捆绑版本始终可用，保证功能不缺失。

### 8.3 build-installer.ps1

```powershell
# 一键构建流程（方案 B，无 PyInstaller）：
# 1. 下载工具链（uv/ruff/pandoc/python-build-standalone）
.\scripts\prepare-tools.ps1

# 2. 装配后端：拷贝代码（排除 tests/__pycache__/data）+ uv 装依赖
robocopy python resources\python-backend /E /XD __pycache__ tests data /XF *.pyc
resources\tools\uv.exe pip install `
  --python resources\tools\python-build-standalone\python.exe `
  --target resources\python-backend\site-packages `
  -r python\requirements.txt

# 3. 构建前端
npm.cmd run build

# 4. 构建安装包
npx.cmd electron-builder --win
```

> 运行方式：`powershell -ExecutionPolicy Bypass -File .\scripts\build-installer.ps1`（避免 npm.ps1/npx.ps1 被执行策略拦截，脚本内部统一调 npm.cmd/npx.cmd）

## 9. Python 运行时的关系（方案 B）

PyInstaller 退役后，安装包内只有**一份** Python 发行版（python-build-standalone），两个用途：

| 角色 | 来源 | 用途 | 隔离方式 |
|------|------|------|---------|
| 后端运行时 | `resources/tools/python-build-standalone/python.exe`（只读） | spawn 运行 `resources/python-backend/main.py`，PYTHONPATH 指向 python-backend/site-packages | 依赖目录只读，不 pip install |
| 任务 venv 基底 | `%userData%/python/`（tool-initializer 从安装包拷贝的副本） | 创建任务 venv 的 --python 基底 | venv 机制隔离 |

启动链路（python-manager.js 生产模式）：
```
command: resources/tools/python-build-standalone/python.exe
args:    [resources/python-backend/main.py, --port, <free-port>]
env:     INKCUBE_DATA_DIR=<userData>/data（与 Electron 同一数据目录/app.log）
         INKCUBE_RESOURCES_DIR=<resourcesPath>（loader.py 读预置模板）
         PYTHONPATH=<resourcesPath>/python-backend/site-packages
         INKCUBE_{UV,RG,RUFF,PANDOC}_PATH=<userData>/tools/*（resolver env 一级优先）
         INKCUBE_PYTHON_PATH=<userData>/python/python.exe（任务 venv 基底）
```

注意事项：
- 装配（uv --python python-build-standalone）与运行时用同一解释器，消除版本断层
- requirements.txt 是依赖唯一事实源，PyInstaller hiddenimports 维护成本归零
- python-build-standalone（install_only_stripped）无 pip，不会被误用污染
- 用户代码在各自任务 venv 中执行，与后端完全隔离

## 11. 关键决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 分发策略 | 全部捆绑（LibreOffice 除外） | 用户零配置，体验一致 |
| 后端打包（v0.5.0） | 方案 B：python-build-standalone + site-packages，退役 PyInstaller | RAG 重依赖（torch/docling/rapidocr）函数级延迟导入，PyInstaller 静态分析丢失；onefile 全量超 3GB；pip 保证依赖完整性，requirements.txt 单一事实源 |
| 预置基础库（v0.5.0） | 不捆绑种子资料 | 预置库为空容器由用户自行上传（2.7 P3 决策） |
| 生产路径传递（v0.5.0） | python-manager 显式设 INKCUBE_* env | tool_resolver 的 %APPDATA%/InkCube 回退路径与 Electron userData 不一致，env 为一级优先级最可靠 |
| pandoc | 捆绑 | ~30MB 可接受，避免用户自行安装 |
| LibreOffice | 不捆绑，引导安装 | ~800MB 太大，非所有用户需要 |
| 平台优先级 | Windows 先行 | 用户群最大，开发环境现成 |
| 路径解析 | 统一 tool_resolver 模块 | 当前各工具各自查找，逻辑不一致 |
| 首次初始化 | Electron 主进程解压到 %APPDATA% | 避免写入 Program Files（需管理员权限） |
| Python 版本 | 两份独立 Python | 后端稳定性 vs 任务隔离性，各取所需 |
| 预置模板分发 | 捆绑在安装包内（只读） | 随版本更新，用户不可修改，只能复制为自定义模板 |
| 用户数据位置 | `%APPDATA%/InkCube/data/` | 与程序资源分离，跨版本保留 |
| 卸载时数据保留 | `deleteAppDataOnUninstall: false` | 用户数据不随卸载丢失，重装后数据还在 |
