## 1. 概述

墨方 InkCube 是一款桌面端智能助手客户端，面向**招商经理 / 投资经理**，提供本地知识库管理、LLM Wiki 知识编译、专业报告生成、通用任务智能体等能力。除大模型推理外，所有功能均在本地运行，保障数据隐私。

### 1.1 核心能力

| 能力 | 说明 | 对应模块 |
|------|------|----------|
| **任务智能体** | 基于 Function Calling 的双模式 Agent（编程 / 通用），支持多轮推理、工具调用、Skill 扩展、多任务并行、暂停/恢复/崩溃续跑 | `python/agent/`、`src/features/task/` |
| **项目工作空间** | 资料 → Wiki → 报告 → 填表 四 Tab 闭环；基础库跨项目复用 | `python/routers/knowledge.py`、`src/features/project/` |
| **本地知识库（RAG）** | 文档解析（Docling）→ 分块 → 向量化（bge-m3 / ChromaDB）+ 全文索引（SQLite FTS5）→ 混合检索（向量 + BM25 + RRF） | `python/knowledge/` |
| **LLM Wiki** | 逐文件增量摄入，将碎片文档编译为结构化、互链的 Markdown 知识页面（Karpathy LLM Wiki 范式） | `python/wiki/` |
| **报告生成引擎** | 模板驱动 + 多通道检索（知识库 / Wiki / 互联网）+ 知识卡片 + 两遍执行 + 校验重试 + 断点恢复，输出 Word/PDF | `python/report_generator/` |
| **完全本地** | 除 LLM / 网络搜索 API 外，无外部网络依赖，无遥测 | — |

### 1.2 开源协议

本项目采用 **AGPL-3.0** 协议。所有修改和衍生作品必须以相同协议开源，网络服务亦视为分发。

## 5. 关键设计决策

### 5.1 Python 进程管理

Python Agent 作为独立子进程运行，由 Electron 主进程管理生命周期。

**启动流程**（`app.whenReady()`，窗口先行 2026-10-24）：

```
Electron app.whenReady()
    ├── 注册 inkcube:// 协议 handler（本地文件白名单，见 §7）
    ├── 挂 fetch-pool SSRF 拦截器（2.8 §5.3）
    ├── 注册全部业务 IPC handler（registerIpcHandlers：baseUrl 动态解析，不依赖 Python 在线）
    ├── 注册 boot gate IPC：app:boot-status（invoke，拉取当前阶段）/
    │   app:relaunch（invoke，错误态重试 = app.relaunch + exit）
    ├── 创建 BrowserWindow ← 窗口先行（旧行为「健康检查通过 → 创建 BrowserWindow」
    │   已废，实测无窗口期 28.8s）：prod 加载 index.html（静态 splash 随 HTML 解析即见）；
    │   dev 先加载本地 boot-splash.html（毫秒级），waitForDevServer 轮询到 dev server
    │   可响应后自动切主页面——vite 冷启动期 HTTP 全局阻塞，直接 loadURL 会白等分钟级
    ├─┬ 后台启动链（阶段经 app:boot-stage 事件推给 renderer BootGate，各阶段耗时落日志）
    │ ├── stage=tools：首次启动解压工具链（tool-initializer.js，dev 跳过）
    │ │   + 轮询 DevToolsActivePort 取 CDP 端口（browser-fetch 2.8 §6.1）
    │ │   开发模式：探测 8765-8767 端口已有 Python 实例 → 直接复用
    │ │   （便于 PyCharm 手动启动 + 断点调试）
    │ ├── stage=python：分配空闲端口 + spawn Python 进程
    │ │     开发: conda env inkcube → uvicorn main:app
    │ │     生产: python-build-standalone/python.exe main.py
    │ │     + INKCUBE_* 环境变量（数据目录/资源目录/工具路径，见 0.2 §8）
    │ │   轮询 GET /health（300ms 间隔，60s 超时判定；后端冷启动含
    │ │   transformers/torch/docling 导入链，实测基线 8~10s，晚间/开机后
    │ │   IO 波动可达 15~20s，故预算须留足余量；进程提前退出立即抛错不傻等）
    │ └── stage=ready：Python 就绪；BootGate 收到后经 app:boot-status 连通
    │     确认并放行 App（业务 hook 挂载、首批数据拉取）——boot 期 App 未挂载，
    │     不向未就绪后端发请求
    └── bge-m3 预热（POST /models/preload）双条件触发：renderer 首次完整加载
        结束（did-finish-load）且 Python 就绪，二者缺一不可——CUDA 加载与
        renderer 模块图装载争抢 CPU/磁盘会把 dev 冷启动首屏拖到 ~85s
        （2026-10-13 实测 DCL 84s）；/models/preload 幂等
```

启动链任一阶段失败不再 `app.quit()`：错误态经 `app:boot-stage` 推送，BootGate 呈错误屏（重试 = `app:relaunch` / 退出）。

**BootGate 阶段-界面映射**（`src/components/BootGate.tsx`，i18n `boot.*`）：

| 阶段 | 触发方 | 界面呈现 |
|---|---|---|
| `tools` | main：启动链开始 | 「正在准备运行环境」+ 已等待 N 秒 |
| `python` | main：spawn 后等待 /health | 「正在启动本地服务」+ 已等待 N 秒 |
| `connect` | renderer：收到 ready 后的本地阶段 | 「正在连接数据服务」（boot-status invoke 兼作 IPC 链连通确认，通常瞬时） |
| ready 放行 | renderer 确认通过 | 渲染 children（App 挂载） |
| `error` | main 启动链抛错 / python:process-exit / 确认 invoke 失败 | 错误屏（main 传来的 message + 重试/退出） |

**白屏期覆盖**：窗口出现到 React 首渲之间——prod 由 index.html 静态 splash（`.bootstrap-splash-*`，纯 CSS 无 JS）覆盖；dev 由本地 `electron/boot-splash.html` 覆盖（同视觉，含「开发模式」提示），`waitForDevServer`（main.js）轮询 `http://[::1]:5173` 到可响应后自动 `loadURL` 切换，React 挂载后由 BootGate 接管。两处背景：① dev server 地址全链路（vite `server.host` / wait-on / loadURL / will-navigate 白名单）统一 `[::1]`——`127.0.0.1:5173` 被本机代理/TUN 类软件黑洞化，Chromium IPv4 优先会 SYN 超时轮询致连接层分钟级延迟（2026-10-24 实测）；② vite 冷启动期启动任务把 Node 单线程事件循环吃满（实测 99% CPU 持续数分钟，外部 curl 同样饿死），HTML 响应须待其结束，`server.warmup` 因此移除（实测反噬，见 vite.config.ts 注释）。故 dev 冷启动到 App 可用为分钟级（splash 持续显示非白板），prod 不受影响（静态产物毫秒级）。

**内置 skill 文件同步后台化**（2026-10-24，`skills/seed.py`）：启动 lifespan 内只做毫秒级同步部分（定位源 + skills 表 upsert，DB 行即时可见——TaskAgent 执行期实时 `list_skills`），文件同步（ppt-master 13,245 文件 / 78.2MB，实测全量拷贝 ~22s）经 `to_thread` 后台执行，不再阻塞 `/health`。完整性语义：拷贝走 staging 原子替换（`_atomic_install`），`install_path` 任意时刻是完整旧版或完整新版，无混合状态；拷贝失败回滚保留旧版（非阻塞契约不变）；进程被杀仅残留 `.staging`，下次启动开头清理。约定：源变更后首启的数秒内安装目录仍为旧版，随后原子换新。

**退出处理**：`before-quit → POST /shutdown（优雅关闭）→ 等待 2s → SIGTERM → 3s 后 SIGKILL 兜底`。双重保险：

- `watchdog.py`：后端每 5s 检查 `INKCUBE_PARENT_PID` 指向的父进程，父进程消失时 `os._exit(0)` 自杀，避免孤儿进程；
- `python-manager.js` 启动前清理 8765-8799 端口上的残留 uvicorn 进程（校验命令行归属后才 kill）。

**进程退出通知**：Python 进程 exit 时经 `python:process-exit` 推送渲染进程，前端重置生成状态并显示横幅。

### 5.2 通信协议与 API 路由

**Electron ↔ Renderer**：contextBridge + 通用 `invoke/send/on` 代理（`preload.js` 仅 13 行，不逐个注册通道）。前端通过 `window.electronAPI.invoke('<namespace>:<action>', ...)` 调用，共 140+ 通道（清单见 `electron/ipc-handlers.js`）。

**Electron ↔ Python**：HTTP + SSE。任务对话与报告生成使用 SSE 流式推送，事件携带 `taskId` 以支持多任务并行路由。

后端共 **14 个路由模块**：

| `health.py` | `/health` | 健康检查 + 功能就绪度 features 段（Readiness） |

| `models.py` | `/models` | 本地模型下载状态与下载、bge-m3 预热（2.2 §9.4）、LibreOffice 检测 |
| `system.py` | `/system` | 数据用量、数据清理、外部依赖检测、工具链状态 |
| `skills.py` | `/skills` | Skill 列表 / 安装 / 删除 / 启停 / 确认、内置工具清单 |

| `affairs.py` | `/projects` | 项目事务：待办/节奏/审阅到期、脉搏状态 |
| `forms.py` | `/forms` | 填表模板管理、分析（`/analyze`）、执行（`/fill`）、填表记录 |
| `web_logins.py` | `/web-logins` | 登录站点登记/删除（2.8 browser-fetch 登录墙应对） |
| `usage.py` | `/usage` | Token 用量统计：`/summary`（today/total/by_day/by_source/by_model/by_project）、`/task/{id}` 轮次聚合（见 [2.10](2.10token-usage-design.md)） |

### 5.3 任务智能体设计（Function Calling）

任务智能体采用 **OpenAI Function Calling 循环**（非纯文本 ReAct），交替进行推理与工具调用。详见 [1.1](1.1task-agent-design-unified.md)。

- **双模式**：`coding`（编程模式，全部工具）/ `general`（通用模式，10 个精简工具：file_ops、shell、web_search、knowledge_search、vision、doc_generator、repo_map、skill_runner、git_ops、lsp_client），由 `tasks.mode` 持久化，System Prompt 与工具集随模式切换。动态网页抓取由内置 Skill `browser-fetch` 提供（见 [2.8](2.8browser-fetch-design.md)）。
- **可选 Planner**：`task_planner_model` 选定档位时（空 = 不启用，单模型模式；档位经 llm/routing.py 解析到外部模型页对应槽位，标准/高配互为回退），先由 Planner 生成结构化执行计划再进入 FC 循环。
- **并发**：`MAX_CONCURRENT = 3`，per-task 隔离（cancel_events / iterations / tools / LLM client / in-memory messages）。
- **Stuck 检测**：连续 3 次相同错误后注入 stuck hint 提示模型换路径。
- **上下文管理**：`context_manager.py` 负责 Token 预算与 Context Collapse（早期对话压缩为摘要）、超长工具输出 Disk Dump、System Prompt 4000 token 预算（超限时按优先级丢弃 git/project_ctx/project_config/repo_map 可选段）。
- **项目上下文**：自动注入 git 状态、技术栈检测、repo_map（PageRank 排序，512 token 预算）；支持 `inkcube.md` / `.cursorrules` / `AGENTS.md` 项目级配置。
- **韧性**：每 iteration 自动保存完整 agent state（含 tool_calls），支持暂停/恢复/崩溃续跑。详见 [1.3](1.3task-resilience-design.md)。
- **流式渲染**：reasoning / answer_chunk / thought / action / observation / done 事件流。详见 [1.2](1.2streaming-thought-display.md)。

### 5.4 工具体系

**内置工具**（`python/tools/`，17 个，通过 Adapter 桥接为 Skill）：

| 分类 | 工具 |
|------|------|
| 文件 | `file_ops`（读写/inline diff/工作区配额）、`project_scaffold` |
| 代码 | `code_executor`（venv 内执行）、`code_search`（rg）、`code_lint` / `code_format`（ruff）、`repo_map`（tree-sitter + PageRank）、`lsp_client` |
| 系统 | `shell_tool`（域名白名单 + 用户确认）、`git_ops`、`venv_manager`、`package_manager`（uv） |
| 检索 | `knowledge_search` / `task_knowledge_search`（项目 RAG）、`web_search`（互联网，Tavily / 智谱二选一）；动态网页抓取经内置 Skill `browser-fetch`（CDP，见 [2.8](2.8browser-fetch-design.md)） |
| 文档 | `doc_generator`（pandoc + LibreOffice/MSO 转 Word/PDF） |
| 视觉 | `vision`（LLM 多模态图片理解：图片直解（单图 8MB 上限）；PDF/DOCX/PPTX 提取内部图片逐张分析，小图/超大/不支持格式过滤均显式计数，`max_images` 硬上限 50、截断显式声明；LLM 未配置时结构化报错引导配置，不建独立引导 UI；模型须为多模态） |
| Skill | `skill_runner`（执行第三方 Agent Skill） |
| 基础设施 | `base`（工具基类）、`tool_resolver`（统一工具路径解析，见 [0.2 §4](0.2packaging-design.md)） |

**Skill 框架**（`python/skills/`）：兼容 Anthropic **Agent Skills** 标准（`SKILL.md`）。内置工具通过 Adapter 永久桥接为 Skill；第三方 Skill 支持安装、启停、首次使用确认、渐进式披露（Level 1 元数据 + Level 2 执行时注入 body）。

### 5.5 数据存储策略

**存储分层：** SQLite 存结构化元信息，ChromaDB 存向量，文件系统存原始文档/报告内容/日志。

```
开发: python/data/
生产: %APPDATA%/InkCube/data/   （platformdirs，跨平台）
（可用 INKCUBE_DATA_DIR 环境变量覆盖）
```

**数据表（SQLite，23 表 + chunks_fts 虚拟表）：**

| 领域 | 表 |
|------|-----|
| 配置 | `settings` |
| 任务 | `tasks`、`task_messages`、`task_agent_state`、`skills` |
| 统计 | `llm_usage`（token 用量流水，一调用一行，见 [2.10](2.10token-usage-design.md)） |
| 知识库 | `projects`（含 kind/lib_type/type/stage/company_name/credit_code）、`files`、`images`、`chunks_fts`(FTS5)、`project_base_libs` |
| 报告 | `reports`、`report_sections`、`templates`、`report_logs` |
| Wiki | `wiki_schemas`、`wiki_pages`、`wiki_source_pages`、`wiki_page_sources`、`wiki_page_versions`、`wiki_reviews`、`wiki_change_log`、`wiki_compile_tasks` |
| 活动通知 | `notifications`（终态通知，未读查重）、`model_downloads`（下载状态持久化，崩溃恢复） |

> 向量数据存于 ChromaDB（`data/chroma/`，按 project_id 隔离 collection）；本地模型存于 `data/models/`（bge-m3 等）。

**Schema 迁移：** `database.py` 采用幂等 `_migrate_add_column()` + `CREATE TABLE IF NOT EXISTS`，应用启动时自动补齐列/表，只迁移结构不改用户内容。

### 5.6 升级不覆盖用户数据

| 类型 | 位置 | 升级行为 |
|------|------|----------|
| 应用代码 | `C:\Program Files\InkCube\` | 覆盖更新 |
| 程序资源 | 安装包 `resources/`（模板、工具链） | 随版本覆盖（只读） |
| 用户数据 | `%APPDATA%\InkCube\`（data/、tasks/、models/、skills/） | 永久保留 |

NSIS 配置 `deleteAppDataOnUninstall: false`，卸载重装数据不丢。详见 [0.2](0.2packaging-design.md)。

### 5.7 长时操作生命周期

任务、文件解析、图片描述、Wiki 编译、报告生成、模型下载六类长时操作共享统一状态机与崩溃恢复模型：**DB 是状态源，前端是只读镜像**；启动时扫描 `processing/queued` 记录，超时标记失败、未超时续跑。恢复逻辑分布在 `main.py`（任务 + 报告 + 模型下载）与 `knowledge/task_queue.py`（文件 / 图片 / Wiki 编译）。详见 [0.4](0.4lifecycle-design.md)。

前端反馈侧为**统一后台活动总线（Activity Hub）**：notifications 表持久化终态通知 + `GET /activities/status` 聚合端点 + 前端 ActivityMonitor 单一常驻轮询，分发到 Toast / 侧边栏徽章 / 首页活动区 / 详情页 Tab 角标四个反馈面。功能就绪度与准入引导（Readiness）经 `/health` features 段 + 首启向导 + 入口引导弹层实现，同样见 [0.4](0.4lifecycle-design.md)。

## 6. 功能模块架构

### 6.1 知识库 RAG（`python/knowledge/`）

```
文件上传 → ProcessingPipeline（Docling 解析 → 分块 → bge-m3 向量化 → ChromaDB + FTS5）
        → 图片抽取 → LLM 图片描述（异步，llm/vision）
检索：KnowledgeSearchTool（向量 + BM25 → RRF 融合 → 可选 rerank）
异步：KnowledgeWorker（文件解析 worker + 图片描述 worker，独立并发控制）
```

关键文件：`pipeline.py`（解析管线）、`vector_store.py`（ChromaDB + bge-m3）、`fts_store.py`（FTS5）、`hybrid_retriever.py`（RRF 融合）、`knowledge_search.py`（检索工具）、`task_queue.py`（异步 worker）、`doc_parser.py`、`model_manager.py`、`file_cleanup.py`（图片理解统一走 `llm/vision.py`，2026-10-21 VLM 独立链路删除）。详见 [2.2](2.2knowledge-base-design.md)。

### 6.2 LLM Wiki（`python/wiki/`）

逐文件增量摄入（Per-Source Ingest）：LLM 读取完整原文 → 创建来源页 → 触碰 10-15 个相关页面（实体/概念/主题页）→ 更新 index.md / log.md。连续编译（失败隔离不中断，可随时停止）、Lint 健康检查（结构层 + 语义层）、sweep-reviews、知识图谱（sigma）、页面版本、重复检测与合并、级联删除。关键文件：`ingest.py`、`compiler.py`、`parser.py`、`wiki_graph.py`、`wiki_search.py`、`lint.py` / `semantic_lint.py`、`sweep_reviews.py`、`dedup.py`、`context_budget.py`、`llm_routing.py`、`detect_language.py`、`wiki_enrich.py`、`prompts.py`。详见 [2.6](2.6wiki-design.md)。

> Wiki 通道已接入报告引擎检索主流程——项目存在已完成（compiled / user_edited）Wiki 页面时自动启用（`runner.py` 检测 → `retrieval.py` wiki 通道），采信优先级 Wiki > 知识库 > 互联网（见 [2.6 §8](2.6wiki-design.md)）。

### 6.3 报告生成引擎（`python/report_generator/`）

独立模块（非 Tool/Skill），有状态多步流水线：

```
模板加载(loader) → 归一化(normalizer，多级大纲折叠为两级 + 变量实例化 + foreach 展开)
  → 变量解析(variable_resolver，研究 DAG 拓扑求值)
  → 逐节：检索策略(search_strategy) → 多通道检索(retrieval：knowledge + wiki + internet，通道间/内并行)
          → 知识卡片(card_builder：LLM 提取 + 归因 + 去重 + 充足性评估)
          → 引用注册(registry) → Prompt 构建(prompts) → 生成(runner，两遍执行 + checkpoint)
          → 单节校验(validator)（Token 记录经 llm/usage.py 收口逐调用落库，[2.10](2.10token-usage-design.md)）
  → 全局收尾(finalizer：一致性检查 + 衔接润色 + 引用重排)
  → 渲染导出(renderer：Markdown → docx/pdf)
```

详见 [2.5](2.5report-design.md)。

## 7. 安全考量

| 风险 | 措施 |
|------|------|
| XSS → 本地文件访问 | CSP meta（index.html：`default-src 'self'`）、禁用 nodeIntegration、contextIsolation + contextBridge 隔离 |
| 渲染进程读取任意本地文件 | `inkcube://` 自定义协议仅放行白名单目录：`<dataDir>/files/`（上传与抽取图片）+ `<dataDir>/ppt-library/templates/`（用户模板库：详情页面原型 SVG 与包内资产，2.3 §4.2）+ `resources/skills/ppt-master/templates/`（内置模板，只读展示）（路径归一化后前缀校验，防 `../` 穿越） |
| 页面导航劫持 | `will-navigate` / `setWindowOpenHandler` 拦截应用外导航，一律转交系统浏览器 |
| Python 端口被外部访问 | 仅绑定 `127.0.0.1`；CORS 仅放行 Vite dev server |
| Shell 命令风险 | 域名白名单 + 用户确认（30s 倒计时）+ 危险命令黑名单 |
| Skill 执行风险 | 首次使用确认（60s 倒计时） |
| 任务代码隔离 | 每任务独立 venv（基于 python-build-standalone，懒创建：`create_task` 仅登记路径，首次执行代码/装包/跑 Skill 时经 `ensure_venv` 落盘，纯聊天任务零占用）；uv 缓存指到数据目录同盘（`UV_CACHE_DIR=data/uv-cache`），同版本包硬链接零增量；工作区配额（默认 1GB，可配置） |
| LLM API Key 存储 | 本地 settings（DB），不外传 |
| 用户数据泄露 | 全部本地存储，无遥测 |
