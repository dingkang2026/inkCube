# 便签（Sticky Notes）设计

> 全局速记收件箱：任何页面（含任务执行中）一键调起，随手记一笔，先接住、别丢。
> 定位为项目管理级的轻量捕获层，与拜访/会议纪要（[2.13](2.13meeting-notes-design.md)）为**两个独立功能**，互不依赖。
> 三要素（表结构/数据流/前端交互）见 §2/§3/§4；全局规范见 [0.3](0.3ux-design.md)，活动体系见 [0.4](0.4lifecycle-design.md)。

---

## 1. 决策记录（2026-10-27 brainstorm 收敛）

| 决策点 | 结论 | 落选方案与理由 |
|---|---|---|
| 功能定位 | **全局速记收件箱**：记时不要求归属项目，之后按需归档/转事务 | 项目内轻量记录：便签的价值在「先接住」，强绑项目违背随手记初衷 |
| 与纪要关系 | **两个独立功能**：便签纯文本零 LLM；纪要结构化走 LLM | 一套体系两层：耦合度高、实现风险大；便签仅作纪要输入：纪要独立性受损 |
| 留存策略 | **自由留存，无提醒**：不逼用户处置，出口（归档/转事务/删除）按需使用 | 强制出口+首页提醒：「随手一记」被处置提醒绑架；出口+喂 agent：二期候选，一期不做 |
| 承载形态 | **App 级全局轻抽屉**（TitleBar 顶栏动作钮 → 右侧抽屉，2026-10-27 实施后自 NavTabs 迁入，与通知铃铛同区统一 actionBtn 形态），**不占导航 Tab、无独立页面路由** | 侧栏独立便签页：存在感过重、多一路由；寄生首页输入框：列表管理不便 |
| 调用方式 | 顶栏便签图标 + 应用内快捷键 `Ctrl+Shift+N` | 系统级全局快捷键（globalShortcut + frameless 小窗）：涉及快捷键冲突处理与主进程新窗，列为二期候选 |
| 内容形态 | **纯文本 + 可选颜色点**（2026-10-27 追加裁决）：固定色板单选（黄/红/蓝/绿/紫 + 默认无色），纯视觉标记无语义命名——便签的物理隐喻就是彩色便利贴，零学习成本，语义由用户自赋 | 标签体系/自定义颜色/按色筛选：功能蔓延；纯白无色：丢了便利贴隐喻 |

**轻的不做清单**（实现时对照，防止功能蔓延）：无富文本、无分类、无标签体系、无按色筛选/排序、无自定义颜色、无独立路由页、无 LLM、无解析、无后台活动、无提醒角标、无自动清理。颜色只做视觉标记不建索引维度——便签总量小，扫一眼即得，不需要筛选维度（后续真需要再加，成本低）。

## 2. 表结构

```sql
CREATE TABLE IF NOT EXISTS sticky_notes (
    id          TEXT PRIMARY KEY,      -- 'note_<uuid>'
    content     TEXT NOT NULL,         -- 纯文本
    color       TEXT,                  -- 固定色板枚举：yellow/red/blue/green/purple；NULL = 默认无色
    project_id  TEXT,                  -- 归档后落定的目标项目；NULL = 收件箱未归档
    archived_at TEXT,                  -- NULL = 未归档
    created_at  TEXT NOT NULL,
    updated_at  TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_sticky_notes_updated ON sticky_notes(updated_at DESC);
CREATE INDEX IF NOT EXISTS idx_sticky_notes_project ON sticky_notes(project_id) WHERE project_id IS NOT NULL;
```

读写行为：

| 操作 | 行为 |
|---|---|
| 创建/编辑 | INSERT / UPDATE content/color 与 updated_at；内容不设长度硬限（软限 5000 字符，超出前端提示）；color 仅接受色板枚举值或 NULL，其余值 422 |
| 列表 | 按 updated_at 倒序分页（`limit/offset/has_more/total` 契约，[0.1 §16](0.1dev-guide.md)）；`view=inbox\|archived` 过滤（`archived_at IS NULL / IS NOT NULL`） |
| 归档 | `project_id`/`archived_at` 落定（见 §3 归档路径）；归档后仍可从「已归档」视图查看 |
| 删除 | 物理删除（useConfirm 确认后）；**唯一清理入口即用户显式删除**（自由留存定位，无保留期/自动清理） |

生命周期闭环：行只由用户显式删除；随项目级联——项目删除时已归档至该项目的便签行**不删除**，`project_id` 置 NULL 回收件箱（便签是用户全局资产，项目删除不应连带销毁用户记录；归档产物 md 随项目素材正常级联删除）。

## 3. 数据流

```
[Electron 主进程]
  TitleBar 便签动作钮 / Ctrl+Shift+N ──► 渲染层 StickyDrawer（App 级抽屉，零主进程改动）

[Python FastAPI]  routers/sticky_notes.py（挂 /sticky）
  GET    /sticky/notes?view=inbox|archived&limit&offset   分页列表
  POST   /sticky/notes                                    创建
  PATCH  /sticky/notes/{id}                               编辑内容
  DELETE /sticky/notes/{id}                               删除
  POST   /sticky/notes/{id}/archive                       归档到项目
  POST   /sticky/notes/{id}/to-affair                     转为事务
```

**读路径**：抽屉打开 → `sticky:list` → 首页 50 条，「加载更多」翻页。

**写路径（CRUD）**：`sticky:create/update/delete` → python 端点 → db 同步写 → 返回行；前端本地刷新，无异步活动（便签是全应用唯一纯同步功能）。

**归档路径**（`POST /sticky/notes/{id}/archive`，body: `{project_id}`）：
1. 校验项目存在且未归档（幂等：已归档再调返回 409）
2. 后端将便签内容写为 md 文件（命名 `便签-YYYYMMDD-HHmmss.md`）落入项目素材目录，**内部复用 `POST /projects/{id}/upload` 同一落盘+建 file 行+解析入队逻辑**（python 层函数级复用，非 HTTP 自调）——零新解析通道，解析走现有 files Activity
3. 便签行落 `project_id`/`archived_at`，返回归档结果
4. 前端 toast「已归档至〈项目名〉，正在解析」（解析进度由现有文件活动承载，便签侧零新增轮询）

**转事务路径**（`POST /sticky/notes/{id}/to-affair`，body: `{project_id, due_date?}`）：
1. 复用 affairs 建事务逻辑（`db.create_phase_task`）：`task_type='material'`、`title`=便签首行截断（40 字符）、`description`=全文
2. 便签行**原地留存不标记**（自由留存原则；用户可自行删除）
3. 前端 toast「已创建事务」+ 附「查看」链（`app:navigate-project-tab` detail `{projectId, tab:'affairs'}`）

**IPC 通道**（preload 代理，与端点一一对应）：`sticky:list` / `sticky:create` / `sticky:update` / `sticky:delete` / `sticky:archiveToProject` / `sticky:toAffair`。同变更内全部落地前端消费（§2.9 孤儿通道零容忍）。

## 4. 前端交互

**呈现线框**（抽屉自上而下：头部 / 输入区 / 二分区 toggle / 卡片列表；左侧为被覆盖的当前页面）：

```
┌──────────────────────────────┬───────────────────────────┐
│                              │  便签                  ✕  │ ← 头部
│                              ├───────────────────────────┤
│                              │ ┌───────────────────────┐ │
│   当前页面内容                │ │ 记一笔…               │ │ ← 输入区（焦点自动落此）
│   （保持原状，不被打断）        │ │                 [存]  │ │
│                              │ └───────────────────────┘ │
│                              │  ● 收件箱   ○ 已归档      │ ← 二分区 toggle
│                              ├───────────────────────────┤
│                              │ ┃周三下午和王总茶叙…      ┃ │ ← 便签卡（左缘色条=黄）
│                              │ ┃               10:24     ┃ │
│                              │ ┃ 复制 编辑 归档 转事务 删 ┃ │ ← hover 显操作
│                              │ ├──────────────────────────┤
│                              │ │联系律师看合同条款        │ │ ← 无色默认卡
│                              │ │        加载更多          │ │
└──────────────────────────────┴───────────────────────────┘
```

**组件清单**（组件 × 数据 × 呈现）：

| 组件 | 数据 | 呈现 | 状态 |
|---|---|---|---|
| TitleBar 便签动作钮（StickyNote，与铃铛同区 actionBtn 形态；2026-10-27 自 NavTabs 迁入） | 无 | 顶栏 icon-only 动作钮，点击发 `sticky:toggle-drawer` 内部事件（CustomEvent，kebab-case 惯例） | 恒渲染 |
| `StickyDrawer`（App 级，挂 App.tsx） | sticky:list + 本地 state | 右侧抽屉（useDrawerWidth 统一 60% 可拖动） | open/close；open 时焦点落输入框 |
| 抽屉输入区 | — | 输入框（Enter 存 / Shift+Enter 换行）+ 存储钮 | 有内容可存；空禁用 |
| 二分区 toggle | view state | 「收件箱 \| 已归档」（对齐 AffairsTab 视图切换形态） | 默认收件箱 |
| 便签卡 | note 行 | 左缘颜色条标识（color 映射固定色值，默认色 = 中性边框色）；内容全文 + 相对时间；操作组：复制 / 编辑 / 归档到项目 / 转为事务 / 删除 | inline 编辑态（含色板行：5 色圆点 + 无色，单选即存）；归档/转事务弹项目选择器（转事务附可选截止日） |
| 空态 | — | 「随手记一笔，之后可归档进项目或转成待办」 | 收件箱空 / 已归档空两套文案 |

**状态-界面映射**：

| 状态 | 用户看到 |
|---|---|
| 任意页面按 `Ctrl+Shift+N` / 点顶栏便签动作钮 | 右侧推出便签抽屉，焦点在输入框 |
| 输入 + Enter | 便签卡出现在收件箱顶部（默认无色），输入框清空可连续记 |
| 编辑态点色板圆点 | 颜色即存即生效，卡片左缘色条切换；选「无色」回到默认 |
| 点「归档到项目」选项目 | toast + 卡片移入「已归档」视图；「已归档」视图卡片显示「→ 项目名」角标 |
| 点「转为事务」选项目（+可选截止日） | toast「已创建事务」；卡片原地不动（自由留存） |
| 删除 | useConfirm 确认后卡片移除 |

**关键交互规则与不变量**：
- 抽屉打开不打断当前页面状态（浮层，含任务页）；任务页内每条便签「一键复制」供粘入任务对话输入框。
- 应用内快捷键 `Ctrl+Shift+N` 在输入框聚焦时同样生效（再次按下关闭抽屉，toggle 语义）。
- 归档/转事务的目标项目选择器复用现有项目选择组件（`limit=0` 全量拉取）。
- 双语 i18n 全套（`nav.stickyNotes` / `sticky.*`），zh-CN 与 en-US 同步交付。

## 5. 验收标准

1. `node scripts/orphan_channel_audit.js` 四组为 0（六通道 + 六端点全链消费）
2. `npx tsc --noEmit` + `npm run build` + `npx vitest run`（含 `StickyDrawer.test.tsx`：创建/归档/转事务/删除正常与异常路径）+ `pytest python/tests/ -v`（含 `test_sticky_notes.py`：CRUD/归档幂等/转事务/分页契约）全绿
3. `npm run dev` 运行验证：任意页面调起抽屉、任务页内调起不中断任务、归档后素材 Tab 可见解析中的 md 文件
4. 双语齐全，无硬编码文案
