# Token 用量统计与呈现（token-usage）设计文档

> **概述**：本文档定义 LLM/VLM token 用量的统计与呈现设计。LLM 出口已统一为 `chat_full` / `chat_stream`（[llm/client.py](../python/llm/client.py)）+ 独立 `VLMClient`（[knowledge/vlm_client.py](../python/knowledge/vlm_client.py)），本设计在其上建立**单一收口的用量记录层**：每次 API 调用一行精确 usage（API 返回值，禁止估算）落 SQLite `llm_usage` 表，聚合查询覆盖任务 / 每次对话 / 图片描述 / Wiki / 报告 / 填表 / RAG 问答七个业务维度与全局时间维度。呈现侧：任务气泡操作行（与复制同行）与 RAG 气泡操作行显示每轮用量；任务列表行 / 项目列表行 / 项目详情头部显示累计；新增 App 级底部状态栏（纯全局分段）；设置页新增「用量统计」tab 提供时间维度下钻。本文覆盖：决策记录（§1）、总体架构（§2）、表结构（§3）、后端设计（§4）、数据流（§5）、前端交互（§6）、边界与取舍（§7）、测试计划（§8）、实施顺序（§9）。
>
> 关联：LLM 统一出口与管线级模型路由见 [llm/routing.py](../python/llm/routing.py)（`_TASK_MODEL_KEYS`，模型覆盖发生在构造 client 前）；长时活动统一模型与轮询纪律见 [0.4](0.4lifecycle-design.md)（本设计的用量属页面明细查询，**不新增轮询、不注册 Activity**）；报告生成现状见 [2.5](2.5report-design.md)（§3.8.7 TokenTracker 由本设计迁移收编）。

## 1. 决策记录

2026-10 方案讨论收敛结论：

| 决策点 | 结论 | 落选方案与理由 |
|---|---|---|
| 数据精确性 | **只记录 API 返回的 usage 精确值，禁止任何估算**（含按字符折算） | 启发式估算：与模型/语言相关，数字失真（开发规范：数值统计必须精准） |
| 记录收口 | **client 内部收口**：`chat_full`/`chat_stream`/`VLMClient` 内部各 1 处记录；业务侧只 push 上下文 | 20+ 调用点各自埋点：碎片化、易漏、未来新增调用不自动纳管（同 §2.7 防碎片化精神） |
| 上下文传递 | **contextvar 环境上下文**（async 原生隔离；线程入口各自 push） | 改 `chat_full` 签名传参：25+ 调用点全改，接口污染 |
| 报告模块 | **迁移单源**：移除 `TokenTracker` / `reports.token_usage` 列 / `token_usage.json` 产物，明细改查 `llm_usage` | 保留并行：两份 token 数据源，违反单源与死代码纪律 |
| 全局入口 | **设置页新 tab「用量统计」**（复用 SettingsNav） | 独立导航页：主导航膨胀；Home 卡片：放不下时间维度下钻 |
| 费用换算 | **本期不做**（严格 token 口径） | 单价配置：各厂商计价规则（缓存/阶梯）不一、单价需人工维护，复杂度与收益不成比例 |
| 任务轮呈现 | **assistant 气泡下方操作行（时间+复制同行）**，`↑输入 ↓输出` | 任务页头部集中展示：脱离对话上下文，不直观 |
| 项目维度呈现 | **列表行小字 + 详情头部徽章组合** | 仅状态栏上下文段（已否决：状态栏保持纯全局）；仅统计页下钻：不显眼 |
| 状态栏模型段 | **`N 个模型`**（本周期实际用过的模型数，点击跳统计页 by_model） | 单一模型名：多管线覆盖模型下「当前模型」语义不成立；默认模型+tooltip：信息隐蔽 |
| 图表实现 | **内联 SVG 柱状图**（零新依赖） | 引入图表库：打包体积 + 依赖管理成本，数据量级不值 |
| 刷新机制 | **事件驱动 + 窗口聚焦自愈，零新增轮询**（§5.5） | 定时轮询：违反 §2.7 轮询清单不增长；仅手动刷新：状态栏数字长期过期 |

## 3. 表结构

### 3.1 llm_usage 表（新增）

```sql
CREATE TABLE IF NOT EXISTS llm_usage (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    ts TEXT NOT NULL,                   -- ISO 本地时间（与库内 created_at 口径一致，按天分组用 date(ts)）
    source TEXT NOT NULL,               -- task / chat / vlm / wiki / report / form / system（§3.3）
    purpose TEXT,                       -- 调用用途细分（§3.3；报告沿用原 TokenTracker call_type 口径）
    task_id TEXT,                       -- 任务场景：task id（round 的归属键）
    round_id TEXT,                      -- 任务「每次对话」= agent 一次 run 的 uuid，同轮多次调用共享
    project_id TEXT,                    -- 项目场景
    entity_id TEXT,                     -- report_id / compile_task_id / fill_id / image_id / file_id
    model TEXT NOT NULL,                -- 实际生效模型（管线 get_task_settings 覆盖后的最终值）
    mode TEXT NOT NULL,                 -- full / stream / vlm
    prompt_tokens INTEGER NOT NULL DEFAULT 0,
    completion_tokens INTEGER NOT NULL DEFAULT 0,
    total_tokens INTEGER NOT NULL DEFAULT 0,
    detail TEXT                         -- JSON 扩展位（如报告 section_id），避免加列蔓延
);
CREATE INDEX IF NOT EXISTS idx_llm_usage_ts      ON llm_usage(ts);
CREATE INDEX IF NOT EXISTS idx_llm_usage_source  ON llm_usage(source, ts);
CREATE INDEX IF NOT EXISTS idx_llm_usage_task    ON llm_usage(task_id, round_id);
CREATE INDEX IF NOT EXISTS idx_llm_usage_project ON llm_usage(project_id, ts);
CREATE INDEX IF NOT EXISTS idx_llm_usage_entity  ON llm_usage(entity_id);
```

**读写行为**：

| 项 | 约定 |
|---|---|
| 写入 | 仅 client 记录点（收口层），同步单条 INSERT（SQLite 单机微秒级）；**append-only，无 UPDATE**；记录失败仅 `logger.error`，绝不影响业务主流程 |
| 读取 | 全部聚合 SELECT（by_day / by_source / by_model / by_project / task rounds / entity 汇总），无缓存层——数据即查即准，刷新机制（§5.5）因此无需失效管理 |
| 数据量 | 任务一轮 5~30 行、VLM 一图一行，单机年量级 ~10⁵ 行，毫秒级聚合，无归档需求 |
| 定位 | 全应用 token 用量**唯一数据源**；报告 section 级明细也由本表承载（§4.4） |

### 3.2 既有表改动

| 表 | 改动 | 说明 |
|---|---|---|
| `reports` | **删除列 `token_usage`**（原 TEXT JSON 汇总，前端从未消费） | SQLite 3.35+ `ALTER TABLE … DROP COLUMN`（实施时以运行时 sqlite3 版本验证；不支持则按该表 DDL 重建表迁移）。同步删除 `update_report_token_usage()`（[database.py](../python/db/database.py)）及其调用 |

### 3.3 source / purpose 取值枚举

| source | 业务 | purpose 取值 | 上下文键 |
|---|---|---|---|
| `task` | 任务执行 | 轮级统一环境不细分（planner / compact / fix 共享轮上下文，purpose 为 NULL；如需细分将来在各子调用点套 `push_purpose`，表结构已支持） | task_id + round_id |
| `chat` | 知识库问答（项目 + 基础库） | `rag` | project_id（可选 file_id → entity_id） |
| `vlm` | 图片描述 | `describe` | project_id + entity_id=image_id |
| `wiki` | Wiki 管线 | `ingest` / `lint` / `dedup` / `enrich` / `ledger_parse` / `ledger_pulse`（脉搏 AI 状态句，实现在 ledger_service） | project_id + entity_id（file_id / compile_task_id） |
| `report` | 报告 | `extract`（模板提取，发生在模板保存前无 entity_id）/ `variable_resolution` / `retrieval`（检索内部全部 LLM 调用统一口径，detail=section_id）/ `generation`（detail=section_id）/ `digest` / `extract_numbers` | project_id + entity_id=report_id |
| `form` | 填表 | `analyze` / `fill` | project_id + entity_id（template_id / fill_id） |
| `system` | 系统杂项 | **预留**（盘点确认 affairs / ledger pulse 均无独立 LLM 出口，脉搏句归 wiki/ledger_pulse；当前无调用点） | 无 |
| `meeting_note` | 拜访/会议纪要结构化（LLM 单次整理，2026-10-27） | NULL（单次调用无细分） | project_id（纪要行为向导中间态、confirm 后删行，**不带 entity_id**防 entity 聚合孤儿；[2.13](2.13meeting-notes-design.md)） |

未知调用（漏 push 上下文）落 `source='other'` 并 `logger.warning`——漏埋点可观测，统计不缺账。`test_connection` / `probe` 探针调用在 client 内不经过记录点，天然不计。

## 4. 后端设计

### 4.1 llm/usage.py（记录层，新模块）

```python
# 核心 API（与实现一致）
@dataclass(frozen=True)
class UsageContext:
    source: str = "other"; purpose: str | None = None
    task_id: str | None = None; round_id: str | None = None
    project_id: str | None = None; entity_id: str | None = None
    detail: dict | None = None

push_context(ctx)          # @contextmanager：业务入口 with 用（短代码块）
push_purpose(purpose, detail=None)  # @contextmanager：既有环境上仅覆盖 purpose/detail（报告调用点）
set_context(ctx) / reset_context(token)  # token 式手动 push（路由层 async for 等过长代码块，finally reset）
record(model, mode, usage) # LLMClient/VLMClient 出口调用；无 sink/无 usage 不落库
configure(sink)            # main.py 组装期注入 db.insert_llm_usage
```

- **分层约束**：`llm/usage.py` 零 DB 依赖（sink 函数注入，[main.py](../python/main.py) 组装期 `usage.configure(deps.db.insert_llm_usage)`），`llm/` 模块保持「无 agent/knowledge/db 依赖」的既有分层。
- **record 行为**：无 sink（未注入/测试环境）或 usage 缺失 → 不落库；落库异常捕获并 `logger.error`（纵深防御，正确性根因 = INSERT 本身不会失败）。
- **线程边界**：contextvar 不跨线程自动传播——在线程池执行的同步入口（如 `ledger_service.on_compile_complete_sync`）在**线程函数体内**自行 push，不依赖调用方环境。

### 4.2 client 接入点（各 1 处）

| 出口 | 接入点 | 说明 |
|---|---|---|
| `chat_full` | [llm/client.py](../python/llm/client.py) 响应解析后 | usage 必有，直接 record（mode='full'，model=self.model） |
| `chat_stream` | usage chunk 到达处（`{"type":"usage"}` yield 前） | usage 采集不依赖 chunk 形态：OpenAI 官方为独立 `choices=[]` usage-only chunk；智谱 BigModel/DeepSeek 等兼容端点附在末个带 choices 的 chunk（glm-5.3 实测 2026-10-16），两种形态均捕获。端点整体无 usage chunk → **不落库**（宁缺勿估），`logger.warning` 提示该端点不参与统计 |
| `VLMClient._call_external_api` | [knowledge/vlm_client.py](../python/knowledge/vlm_client.py) 响应解析 | **改造**：提取 `data["usage"]`（GLM-4V OpenAI 兼容响应含 usage，现状被丢弃）随结果返回并 record（mode='vlm'） |

runner 内 5 处 `self.token_tracker.record(sid, call_type, usage)` 改为调用点外层 purpose 上下文覆盖（`with push_purpose('generation', detail={'section_id': sid})` 模式），section_id 写 `llm_usage.detail`。报告的 by_type / by_section 还原路径：`WHERE entity_id=? GROUP BY purpose` / `GROUP BY json_extract(detail,'$.section_id')`。checkpoint、产物、DB 列清理见 §3.4。

## 5. 数据流

### 5.1 写路径（记录）

```
业务入口 push_context(UsageContext)            ← 10 处，一次性
  └→ contextvar（async 原生隔离；线程入口体内 push）
      └→ LLMClient.chat_full / chat_stream / VLMClient（收口点）
            └→ usage.record(model, mode, usage)
                  └→ sink = db.insert_llm_usage（main.py 注入）
                        └→ INSERT llm_usage（失败仅日志）
```

### 5.2 读路径（呈现数据）

```
StatusBar            ─ IPC usage:summary ─→ GET /usage/summary           ─┐
设置-用量统计 tab     ─ IPC usage:summary ─→ GET /usage/summary?range_key=… ├→ 聚合 SELECT llm_usage
项目详情徽章          ─ IPC usage:summary ─→ GET /usage/summary?project_id=│
TaskItem / ProjectSidebar 行 ─ 既有列表 IPC ─→ 既有端点 + 聚合字段      ─┤
报告/填表/编译卡片行   ─ 既有列表 IPC ─→ 既有端点 + entity 聚合字段  ─┘
TaskItem 行下钻（UsageRounds 展开）─ IPC usage:taskDetail → GET /usage/task/{id}
任务气泡行（历史）    ─ 既有 tasks:listMessages ─→ metadata.usage
任务气泡行（实时）    ─ 任务 SSE usage 事件（§5.3）
RAG 气泡             ─ knowledge:chat / baseLib:chat 响应体 usage
```

### 5.3 事件路径（零新增轮询）

| 事件 | 载体 | 产生点 | 消费点 |
|---|---|---|---|
| 任务轮 usage | 任务 SSE 流内事件（done 前） | task_agent `run()` 收尾 | useTaskChat → 气泡立即渲染 + dispatch `app:usage-changed` |
| RAG usage | chat HTTP 响应体 | rag.ask | ProjectChatPanel / BaseLibDetailPage → 气泡渲染 + dispatch |
| 活动终态 | activity stream（已有 SSE，Electron 转发 `activity:stream`） | activity_events | ActivityContext.feed 出现新终态条目 → dispatch `app:usage-changed` |
| `app:usage-changed` | window CustomEvent（沿用 `app:tasks-changed` 惯例，纯前端） | 上三行 3 个发信点 | StatusBar / ProjectSidebar / 项目徽章 / 打开中的统计页；**收信端 1.5s 去抖合并**（批量图片描述 N 张终态 → 1 次重取）；不可见组件忽略 |

### 5.4 刷新机制（分级）

| 级别 | 呈现位 | 时机 |
|---|---|---|
| L1 流内实时 | 任务气泡行 / RAG 气泡 | 数据随流/响应自然到达，无刷新机制 |
| L2 事件驱动 | StatusBar / 项目行 / 详情徽章 / 统计页 | 挂载 + `app:usage-changed`（去抖）+ 窗口 focus/visibilitychange；活动数段直连 `useActivity()` 心跳 |
| L3 操作驱动 | TaskItem 行内小字 | 本任务轮完成时现有 `loadTasks` 钩子顺带刷新；后台其它任务的行数字容忍到下次列表刷新（取舍见 §7） |

**自愈设计**：`today` 语义由后端每次聚合计算（无缓存层），任何重取天然正确；窗口聚焦重取覆盖午夜日期翻转 / 长时间挂起 / SSE 瞬断丢信号三种过期场景。信号是体验加速器，不是正确性依赖——错过信号最迟在下次聚焦/打开自愈。

### 6.2 StatusBar 分段规格（左→右）

| 段 | 内容 | 点击行为 |
|---|---|---|
| 今日段 | `今日 ↑A ↓B` | 跳设置-用量统计 |
| 总计段 | `总计 N tokens · M 次调用` | 同上 |
| 活动段 | `N 个活动进行中` | 跳首页活动区 |
| 模型段 | `N 个模型` | 跳设置-用量统计（by_model 明细） |
| 版本段 | 应用版本号（右端，静态） | 打开关于对话框 |

数字格式：紧凑（`1.2k` / `3.4M`），tooltip 完整千分位值。**状态栏保持纯全局，不放项目维度**（决策记录）。

### 6.3 状态-界面映射

| 状态 | 用户在哪里看到什么 |
|---|---|
| 无任何用量数据 | 状态栏今日/总计段显示 `0`；统计页空态文案「暂无用量数据」；气泡无 usage（历史消息）不渲染该小字 |
| 轮进行中 | 气泡不显示数字（轮汇总未产生）；流式结束后随 usage 事件出现 |
| 轮内部分调用无精确 usage（端点不支持 include_usage） | 气泡显示已知部分的合计，无估算值；该端点在日志中有覆盖率告警 |
| 轮次明细展开（TaskItem UsageRounds） | 展开中首次取数显示「加载中...」；无轮次记录显示「暂无轮次记录」；取数失败显示「轮次用量加载失败」（再次点击重试）；数据行含轮次号 / tokens / 调用次数 / 模型 |
| 加载中 | 统计页骨架/空态；状态栏静默保留上次值（底栏不闪烁） |
| Python 服务不可用 | 状态栏用量段保留上次值，不报错弹层（明细查询降级，与 LogViewer 同水位） |

### 6.4 关键交互规则与不变量

1. **零新增轮询**：用量刷新仅有事件驱动与打开/聚焦加载；§0.4 轮询清单不增长。
2. **气泡数字 = 该轮全部 LLM 调用汇总**（FC 迭代 + planner + 压缩 + 修复），与 `llm_usage` 按 round_id 聚合一致（同一数据源两种投影，不允许前端二次估算）。
3. **精确值原则贯穿呈现**：任何界面不出现推算/折算数字；无精确数据的调用不计入。
4. i18n：全部新文案中英双语（`usage.*` / `settings.nav.usage` 命名空间）。
5. StatusBar 挂载于 App 根 flex（`.app-layout` 之后），布局变化不侵入既有页面；全屏/沉浸模式（wiki-immersive）下保持可见（底栏属于应用 chrome）。

## 7. 边界与取舍

| 边界 | 处理 | 理由 |
|---|---|---|
| 流式无 usage chunk（端点不支持 include_usage；末 chunk 附带 usage 的兼容形态已覆盖，仅整体无 usage 才触发） | 不落库，日志告警 | 宁缺勿估（精确值原则） |
| 取消/断流（usage chunk 未到达即中断） | 该次调用不落库 | API 可能已计费但无精确值可取 |
| 失败调用（4xx/5xx） | 不落库（无 usage） | 同上 |
| 探针调用（test_connection / probe） | 不经过记录点，天然不计 | 非业务消耗 |
| 后台任务完成时任务列表行数字滞后 | 容忍到下次 `loadTasks` | 强刷打断滚动/分页；行内数字是累计口径非实时承诺（tooltip 注明），影响可控 |
| 跨天 / 长挂起过期 | 窗口聚焦重取自愈 | 后端实时聚合无缓存，重取即正确 |
| 数据清理 | 不纳入「数据管理」清理类目 | 单机 10⁵ 行级，无清理诉求（不预留半成品入口） |
