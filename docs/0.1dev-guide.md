# 开发指南

> 版本: 1.0.0 | 更新日期: 2026-10-02 | 状态: 与代码对齐
>
> 架构总览见 [0.0architecture.md](0.0architecture.md)；打包细节见 [0.2packaging-design.md](0.2packaging-design.md)。

## 环境要求

### 必需

| 工具 | 版本 | 说明 |
|---|---|---|
| Node.js | >= 20 | 推荐 LTS（开发使用 npm） |
| Python | 3.12 | 通过 Conda 管理 |
| Conda | miniconda3 | [下载地址](https://docs.conda.io/en/latest/miniconda.html) |
| Git | 任意 | 克隆仓库 |

### 可选（打包时需要）

打包无需本机安装额外工具：uv 由 `scripts/prepare-tools.ps1` 自动下载，后端依赖装配与安装包构建由 `scripts/build-installer.ps1` 一键完成（方案 B，无 PyInstaller，见 [0.2 §8-9](0.2packaging-design.md)）。

## 国内环境配置

国内网络下安装和打包可能因 GitHub 资源下载缓慢而卡住，建议设置以下镜像：

```bash
# npm 镜像（所有平台通用）
npm config set registry https://registry.npmmirror.com
```

设置镜像环境变量（按你的终端选择对应语法）：

**PowerShell：**

```powershell
$env:ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/"
$env:ELECTRON_BUILDER_BINARIES_MIRROR="https://npmmirror.com/mirrors/electron-builder-binaries/"
```

**CMD（命令提示符）：**

```cmd
set ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/
set ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/
```

**Bash（Git Bash / Linux / macOS）：**

```bash
export ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/
export ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/
```

> 以上变量仅对当前终端窗口生效。设置后执行 `npm install` 或 `npm run pack` 即可。下载一次后会缓存到本地，后续无需重复设置。

## 开发安装

### 1. 克隆仓库

```bash
git clone https://github.com/your-org/inkcube.git
cd inkcube
```

### 2. 安装前端依赖

```bash
npm install
```

### 3. 创建 Python Conda 环境

```bash
conda create -n inkcube python=3.12 -y
conda activate inkcube
```

### 4. 安装 Python 依赖

```bash
pip install -r python/requirements.txt
```

依赖分组（详见 `python/requirements.txt`）：

| 分组 | 主要依赖 |
|---|---|
| Web 框架 | `fastapi`、`uvicorn[standard]`、`httpx`、`pydantic`、`python-multipart` |
| 校验 | `jsonschema`（模板结构校验） |
| 向量与 Embedding | `chromadb`、`FlagEmbedding`（bge-m3）、`numpy` |
| 文档解析 | `docling`、`python-docx`、`Pillow` |
| OCR | `rapidocr-onnxruntime` |
| 模型下载 | `huggingface_hub`、`modelscope`、`platformdirs` |
| 异步与网络 | `aiohttp`、`html2text` |
| 测试 | `pytest` |

> `FlagEmbedding`/`chromadb`/`docling` 首次导入会拉取本地模型；生产环境已强制 `TRANSFORMERS_OFFLINE=1`（见 `python/main.py`），开发环境首次运行需联网下载 bge-m3。

### 5. 启动开发模式

```bash
npm run dev
```

该命令通过 `concurrently` 同时启动：
- Vite 开发服务器（`http://localhost:5173`）
- Electron 桌面窗口（`wait-on` 等待 Vite 就绪后自动打开）
- Python FastAPI 后端（由 Electron 自动管理，随机端口）

## npm 脚本一览

| 脚本 | 作用 |
|---|---|
| `npm run dev` | 启动完整开发栈（Vite + Electron，Python 由 Electron 拉起） |
| `npm run dev:vite` | 仅启动 Vite 开发服务器 |
| `npm run dev:electron` | 仅启动 Electron（等待 Vite 就绪） |
| `npm run python:dev` | 在 `127.0.0.1:8765` 单独启动 uvicorn（热重载） |
| `npm run python:debug` | 以 debugpy 监听 5678 启动后端（等待调试器接入） |
| `npm run dev:debug` | 三进程联调（python:debug + Vite + Electron） |
| `npm run build` | 前端构建（`vite build` → `dist-renderer/`） |
| `npm run pack` | 构建前端 + `electron-builder` 生成当前平台安装包 |

## 单独启动 Python 后端

```bash
npm run python:dev
```

这会在 `127.0.0.1:8765` 启动 uvicorn 并开启热重载。

## PyCharm 调试

开发时可以分两步启动，手动运行 Python 后端以便在 PyCharm 中直接 Debug。

### 第一步：在 PyCharm 中配置 Run/Debug

1. Run → Edit Configurations → + → Python
2. 填写以下信息：
   - **Script path**: 选 `Module`，填 `uvicorn`
   - **Parameters**: `main:app --host 127.0.0.1 --port 8765`
   - **Working directory**: `<项目路径>/python`
   - **Python interpreter**: 选择 `inkcube` conda 环境
   - **Environment variables**: 添加 `PYTHONUNBUFFERED=1`
3. 点击 **Debug** 按钮（虫子图标），即可打断点、单步调试

### 第二步：启动 Electron 前端

直接启动即可，Electron 会自动检测到已运行的 Python 实例并连接：

```bash
npm run dev
```

> 生产环境不受影响——未检测到已运行的 Python 时，Electron 会自动启动后端。

## Conda 路径说明

开发模式下，Electron 按以下默认路径查找 Conda 环境。如果你的 Conda 安装在其他位置，需要修改 `electron/python-manager.js` 中的 `condaBase` 变量。

| 平台 | 默认路径 |
|---|---|
| Windows | `%USERPROFILE%\.conda\envs\inkcube\` |
| macOS / Linux | `/opt/conda/envs/inkcube/` |

## 测试与验证

按层级执行验证（详见 `.qoder/rules/coding-habits.md`）：

| 层级 | 命令 | 说明 |
|---|---|---|
| Python 语法 | `python -m py_compile <file>` | 单文件语法检查 |
| Python 单测 | `python -m pytest python/tests/ -v` | 报告引擎/模板/Wiki DB/Activity Hub/Readiness/思考参数等单测 |
| TypeScript 类型 | `npx tsc --noEmit` | 全量类型检查，无产物 |
| 前端构建 | `npm run build` | 确认 Vite 构建通过 |
| 完整栈运行 | `npm run dev` | 启动 Vite + Electron + Python，确认无启动报错 |

> Python 测试文件位于 `python/tests/`，命名 `test_<module>.py`，使用 `pytest`（异步用例统一以 `asyncio.run` 驱动，不依赖 pytest-asyncio），以 mock/fixture 隔离外部服务。

## 打包发布

> **重要**：后端依赖（torch/docling 等二进制 wheel）与工具链均为平台绑定，必须在目标平台上构建。例如，打 Windows 安装包需要在 Windows 上执行，打 macOS 安装包需要在 macOS 上执行。

### 1. 准备工具链

```powershell
.\scripts\prepare-tools.ps1
```

下载 uv / rg / ruff / pandoc / python-build-standalone 到 `resources/tools/`，并生成 `tool-versions.json`。详见 [0.2 §8](0.2packaging-design.md)。

### 2. 装配 Python 后端（代码 + site-packages）

方案 B（0.2 §9）：不使用 PyInstaller，改为拷贝后端代码并用 uv 按 `requirements.txt` 装配干净依赖到 `resources/python-backend/site-packages/`。

```powershell
robocopy python resources\python-backend /E /XD __pycache__ tests data /XF *.pyc
resources\tools\uv.exe pip install --python resources\tools\python-build-standalone\python.exe --target resources\python-backend\site-packages -r python\requirements.txt
```

> 以上两步已包含在 `build-installer.ps1` Step 2 中，单独执行时可手动运行。

### 3. 打包 Electron 应用

```bash
npm run pack
```

该命令先执行 `vite build` 构建前端，再调用 `electron-builder` 生成当前平台的安装包。推荐用一键脚本 `powershell -ExecutionPolicy Bypass -File .\scripts\build-installer.ps1`（prepare-tools + 依赖装配 + electron-builder 全流程）。

如需指定目标平台（electron-builder 支持交叉打包）：

| 命令 | 目标平台 |
|---|---|
| `npx electron-builder --win` | Windows `.exe` (NSIS) |
| `npx electron-builder --mac` | macOS `.dmg` |
| `npx electron-builder --linux` | Linux `.AppImage` |

> 注意：虽然 electron-builder 可以交叉打包，但 Python Agent 二进制必须匹配目标平台。交叉打包时，需要提前准备好目标平台的 `inkcube-agent` 并放到 `resources/python/` 目录。

打包产物位于 `dist/` 目录。

## 项目结构

```
inkcube/
├── electron/                  # Electron 主进程
│   ├── main.js                # 入口：创建窗口、管理 Python 进程
│   ├── preload.js             # contextBridge 通用 invoke 代理
│   ├── python-manager.js      # Python 子进程生命周期管理
│   ├── ipc-handlers.js        # IPC 通道注册，代理到 Python HTTP API
│   ├── tool-initializer.js    # 首次启动工具链解压/初始化
│   ├── mermaid-renderer.js    # Mermaid 离屏渲染
│   └── log-utils.js           # 统一日志（写入共享 app.log）
├── src/                       # React 前端
│   ├── App.tsx                # 根组件：导航、全局轮询、状态编排
│   ├── types.ts               # 全局 TypeScript 类型
│   ├── components/            # 通用组件（layout / icons / Markdown / Mermaid / ConfirmDialog）
│   ├── features/              # 业务模块
│   │   ├── home/              # 首页（服务状态卡 + 进行中/最近动态活动区）
│   │   ├── task/              # 任务智能体
│   │   ├── knowledge/         # 知识库
│   │   ├── project/           # 项目详情（四 Tab）+ 基础库 + Wiki/报告
│   │   ├── settings/          # 设置
│   │   ├── activity/          # Activity Hub（ActivityMonitor 单一常驻轮询 + ActivityContext）
│   │   ├── readiness/         # 功能就绪度（useFeatureGuard 入口引导弹层 + 缓存）
│   │   └── onboarding/        # 首启向导（一次性、全程可跳过）
│   ├── hooks/                 # 通用 hooks
│   ├── i18n/                  # 中英双语
│   └── styles/                # 全局样式 + CSS 变量主题
├── python/                    # Agent 后端
│   ├── main.py                # FastAPI 入口 + lifespan（启动恢复/预置初始化）
│   ├── deps.py                # 共享依赖（db / task_agent / worker / template_loader）
│   ├── schemas.py             # Pydantic 请求模型
│   ├── errors.py              # 统一异常体系
│   ├── readiness.py           # 功能就绪度模型（依赖矩阵 + ensure_ready 入口校验）
│   ├── watchdog.py            # 父进程看门狗
│   ├── routers/               # health/models/settings/skills/system/tasks/knowledge/wiki/reports/activities
│   ├── agent/                 # task_agent（FC 循环）/ llm_client / context_manager
│   ├── skills/                # Skill 框架（loader/parser/protocol/registry/context）
│   ├── tools/                 # 20+ 内置工具
│   ├── knowledge/             # RAG 管线
│   ├── wiki/                  # LLM Wiki
│   ├── report_generator/      # 报告生成引擎
│   ├── llm/                   # OpenAI 兼容客户端
│   ├── db/                    # database.py（SQLite）+ wiki_seed.py
│   ├── tests/                 # pytest 单元测试
│   └── requirements.txt
├── resources/                 # 打包资源（python 二进制 / tools 工具链 / templates 模板）
├── scripts/                   # prepare-tools.ps1 / build-installer.ps1
├── docs/                      # 设计与开发文档
├── electron-builder.yml       # Electron 打包配置
├── inkcube-agent.spec         # PyInstaller 配置
├── vite.config.ts / tsconfig.json
└── package.json               # 项目依赖与脚本
```

## 数据存储

| 数据 | 位置 |
|---|---|
| SQLite 数据库 | 开发：`python/data/inkcube.db`；生产：`%APPDATA%/InkCube/data/inkcube.db`（Windows）|
| | macOS：`~/Library/Application Support/InkCube/data/`；Linux：`~/.config/InkCube/data/` |
| 向量索引 | `data/chroma/`（ChromaDB，按 project_id 隔离 collection） |
| 本地模型 | `data/models/`（bge-m3 等） |
| 任务工作区 | 生产：`%APPDATA%/InkCube/tasks/`（每任务独立 venv + workspace） |
| 日志 | `data/logs/app.log`（Python logging + Electron log-utils 共享，5MB×3 轮转） |

> 可通过环境变量 `INKCUBE_DATA_DIR` 覆盖数据目录（见 `python/main.py::get_data_dir`）。程序升级时只替换应用代码，不触及用户数据目录。

## 默认配置

首次启动使用以下默认配置（可在设置面板中修改，存于 SQLite `settings` 表）：

| 参数 | 默认值 |
|---|---|
| API 地址 | `https://open.bigmodel.cn/api/paas/v4/` |
| 模型 | `glm-4-flash` |
| Temperature | 0.7 |
| Max Tokens | 8192 |
| VLM 模型 | `glm-4v`（图片描述） |
| 思考深度 | `low`（reasoning_effort，最低档省 token；可在设置中调档 / 清空 / 自由 JSON 覆盖） |

> 默认使用智谱 AI GLM-4-Flash。你可以在设置中切换为任何兼容 OpenAI API 格式的模型；VLM 用于知识库图片描述。
