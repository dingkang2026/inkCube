## 1. 背景与定位

### 1.1 重构动机

现状（2.1 §1.2）：「报告生成引擎是墨方的核心功能，重中之重」，项目页以「收集资料 → 知识编译 → 生成报告」为主线，Wiki 是四 Tab 之一、定位为报告供料管道。

重构认知：**「写报告」是阶段性的，「与项目知识共处」是常态的**。目标用户（招商/投资经理）的真实旅程按时期展开——前期收集资料、交叉核对、产出报告；后期（陪跑期）月报/季报/年报滚动上传、跟踪里程碑与风险、按周期办事。当前信息架构把常态价值（阅读/治理/沉淀/例行事务）折叠成第二 Tab，把阶段性价值（报告）放在动线终点当唯一目标，且对「多项目并行、谁该办什么」的跨项目视角零承载。

### 1.2 生命周期的产品定义

**生命周期 ≠ 阶段标签，生命周期 = 时期 × 该时期的任务**：

```
时期(Phase)      —— 项目在哪一段：前期接触 → 推进中 → 已落地（复用现有 stage）
时期任务(Playbook) —— 这段时期该做什么：收集什么资料、产出什么报告、什么节点
周期事务(Rhythm)  —— 后期的例行节奏：月报/季报/年报/申报窗口，有频率有截止日
```

### 1.3 设计原则

| # | 原则 | 含义 |
|---|------|------|
| 1 | 自动化优先、配置可选、行业知识内建 | 模板自动带入零配置可用；用户是「确认者与补充者」，不是「设置者」 |
| 2 | UI 稳定、智能渐进 | 脉搏带规则拼接起步，AI 状态句后置换生成逻辑，下层 Tab 纹丝不动 |
| 3 | 单一信息架构，分层不重复 | 脉搏带=状态感知（计数/跳转），知识总览=内容消化（阅读），首页=跨项目聚合 |
| 4 | 不新增轮询 | 任务数据打开时拉取 + 操作后刷新 + 全局心跳边沿补拉（0.4 §3.1 轮询清单不增长） |
| 5 | tab key 稳定 | 现有 `wiki` key 与导航信号映射不动，仅改显示名；新增 `affairs` key |

### 2.3 项目脉搏带（PulseBar）

**职责**：状态感知层——回答「这个项目现在有什么需要我处理」，跨 Tab 聚合、零阅读负担、点击即跳转。

| 组成 | 内容 | 数据源 | 点击行为 |
|---|------|--------|---------|
| 状态句 | 阶段 + 最高优先级信号一句话（规则拼接，v1） | 同 chips | — |
| chip 矛盾 | 待裁决矛盾数 | `wiki:listReviews`（pending contradiction） | → 知识 Tab 治理工作台 |
| chip 缺口 | data-gap/missing-page 待处理数 | `wiki:listReviews` | → 知识 Tab 治理工作台 |
| chip 待编译 | pending_compile_count | 项目对象（已有） | → 知识 Tab 触发编译 |
| chip 应办 | open 且逾期/本周到期任务数 | `affairs:listByProject`（新增，§4/§5） | → 事务 Tab |
| chip 报告 | 生成中报告数 | 全局心跳 byProject.reports（已有） | → 报告看板 |

- 可折叠，折叠偏好持久化（localStorage，per 项目）
- 每 chip 必带 tooltip（title，中英双语，无培训整改 2026-10-23）：解释「这是什么、点击会发生什么」（如待汇编 →「有资料还没整理进知识页，点击开始汇编；汇编进行中则点击查看进度」），禁止裸计数 chip
- 二期起状态句纳入周期事务文案（「月报已逾期 3 天」）；四期 AI 化（§8）

## 3. 时期任务模型

### 3.1 概念分层

| 层 | 承载 | 说明 |
|---|------|------|
| 时期 Phase | 复用 `projects.stage`（before/during/after；general 为 none） | 阶段 pill 切换 = 任务集开关：切到哪段，哪段任务展开；历史时期任务可回看不删除 |
| Playbook 模板 | `playbook_templates`（§4.1，种子化） | 类型 × 时期的任务模板，行业惯例兜底；生成的是**实例**，项目内调整不回写模板 |
| 任务实例 | `phase_tasks`（§4.2） | 项目内真实任务，四类（§3.4）；脉搏带/事务 Tab/首页待办的唯一数据源 |

### 3.2 事项来源（四来源分工）

| 来源 | 角色 | 时机 | 用户成本 |
|---|---|---|---|
| 模板带入 | 默认底座 | 新建项目自动铺入全时期实例（**按时期激活**：非当前时期任务 `pending_activation`，不展示不提醒） | 零 |
| 新建时轻调整 | 可选确认 | 创建向导选定类型后展示一行「已按 XX 带入 N 项任务与月报节奏 → 调整」；抽屉内可勾删/改周期参数；不点即默认 | 不点就跳过 |
| 项目内自建 | 个性化补充（**主路径**） | 事务 Tab 随时新建：一次性任务（截止日）或周期事务（节奏） | 随时 |
| 智能建议 | AI 兜底「怕漏」（四期） | 事件驱动候选：风险台账新增诉讼 → 建议跟进任务；里程碑显示已投产 → 建议激活投后节奏 | 一键采纳/忽略 |

**创建向导不加步数**：新建那一刻用户认知最少，配置靠后（自建 + 调整）；带入靠模板兜底。

### 3.3 Playbook 预置模板（种子化完整清单）

按类型 × 时期种子化（对齐 `wiki_schemas` 的启动幂等模式），应用更新可迭代行业最佳实践。字段口径：**截止规则** `+N` = 进入该时期后 N 天（`due_offset_days`）；周期任务写节奏（`recurrence_rule`）；「手动」= 用户自定日期（milestone/recurring 外默认）。**自动完成匹配**：资料/周期类 = 文件名关键词（`{"on":"file_parsed","match":"..."}`）；报告类 = **报告标题关键词**（`{"on":"report_completed","match":"title~..."}`，实例可改，匹配不到走手动）；「手动」= 无自动完成。实例另可配**项目产出规则**（2026-10-28 产出维度，§5.4：`{"on":"output_completed","match":"..."}`，不限任务类型，经 6.1.7 表单匹配来源下拉落规则）；种子本身不含此规则。

### 3.4 任务类型与完成闭环

| task_type | 说明 | due 语义 | 完成方式 |
|---|---|---|---|
| material | 资料收集 | 截止日（可空） | **自动**：关联文件解析完成（`file_parsed` 事件，匹配规则 §5.4）；实例可改配**项目产出规则**（`output_completed`，不限类型）；兜底手动打勾 |
| report | 报告产出 | 截止日（可空） | **自动**：报告终态 completed 且**标题匹配**任务 `auto_complete.match` 关键词（如「尽调」），匹配不到走手动——避免首个任意报告终态误勾全部报告任务；实例亦可改配产出规则；手动 |
| milestone | 节点 | 固定日期 | 手动；可配产出规则（产出标题命中即闭环，2026-10-28）；四期支持从里程碑台账提取建议 |
| recurring | 周期事务 | 每期截止日（节奏推导） | **自动**：本期关联文件解析完成即本期闭环；实例可改配产出规则；手动确认兜底 |

不变量：自动完成幂等（`completed_by='auto'` 只写一次）；手动打勾/回退始终可用。

### 3.5 周期节奏规则

- 节奏定义：`{freq: monthly|quarterly|yearly, due_day: 1-31|季末|日期}`，存于实例 `recurrence_rule`（JSON）
- **每期一条实例**：`occurrence_key` 标记期次（如 `2026-10`），UNIQUE(project_id, template_id, occurrence_key)；「9 月月报已逾期」是一条具体任务，聚合/日历/逾期判定直读，无运行时计算
- 期次滚动生成：任务服务在应用启动 + 每日首次活动心跳时，为 open 节奏预生成下 1 期；缺失期次补生成（**限当前节奏格式**——改节奏后旧格式实例保留不参与起点计算，跨格式混排从根上消灭；起点只取现存最早同格式实例，**不回退到当期之前**）并按截止日标记逾期。**出生前期次不生成（2026-10-24 裁决）**：铺入/激活/自建时当期截止日已过的，该期不铺出（不算缺失、不产生出生即逾期），首个实例从下一个未来期次开始；已跳过/已删除的过去期次同理不重建（删除是用户明确意愿）
- 漏收期留缺口标记（逾期实例未完成即缺口），历史补传 = 上传后自动或手动完成对应期次实例

## 4. 表结构

### 4.1 playbook_templates 表（种子化）

```sql
CREATE TABLE IF NOT EXISTS playbook_templates (
    id TEXT PRIMARY KEY,              -- 'playbook_recruitment_after_monthly_report'
    project_type TEXT NOT NULL,       -- recruitment | investment | general
    phase TEXT NOT NULL,              -- before | during | after（general 单时期用 before）
    task_type TEXT NOT NULL,          -- material | report | milestone | recurring
    title TEXT NOT NULL,              -- 「上传 9 月月报」→ 实例化时渲染期间变量
    description TEXT DEFAULT '',
    due_offset_days INTEGER,          -- 相对进入时期的截止天数（material/report/milestone）
    due_date_fixed TEXT,              -- 固定日期（milestone 用，如申报窗口）
    recurrence_rule TEXT,             -- JSON：{"freq":"monthly","due_day":15}（recurring）
    auto_complete TEXT,               -- JSON：{"on":"file_parsed","match":"filename~月报"}
    position INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX idx_playbook_type_phase ON playbook_templates(project_type, phase, position);
```

读写行为：启动时 `seed_playbook_templates()` 幂等种子化（INSERT OR REPLACE，对齐 `seed_wiki_schemas` 模式，[2.6 §3.1](2.6wiki-design.md#31-wiki_schemas-表)）；运行期只读。启动挂钩：与 `seed_wiki_schemas()` 同一启动序列调用，顺序：建表迁移 → seed_playbook_templates → migrate_backfill_playbooks（存量回填，依赖模板已就位）→ 其余启动流程。

### 4.2 phase_tasks 表（项目任务实例）

```sql
CREATE TABLE IF NOT EXISTS phase_tasks (
    id TEXT PRIMARY KEY,
    project_id TEXT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
    phase TEXT NOT NULL,              -- 所属时期
    task_type TEXT NOT NULL,          -- material | report | milestone | recurring
    title TEXT NOT NULL,
    description TEXT DEFAULT '',
    template_id TEXT,                 -- 来源模板 id；用户自建为 NULL
    status TEXT NOT NULL DEFAULT 'open',
        -- open | done | skipped | pending_activation（未到时期的模板带入实例）
    occurrence_key TEXT,              -- 周期期次 '2026-10'；非 recurring 为 NULL
    due_date TEXT,                    -- 一次性截止日；recurring 为该期截止日
    recurrence_rule TEXT,             -- JSON（recurring，冗余存便于滚动生成下期）
    auto_complete TEXT,               -- JSON（自模板继承）
    linked_entity_type TEXT,          -- file | report | ppt | form_fill（自动完成关联，后两者为 2026-10-28 产出维度）
    linked_entity_id TEXT,
    completed_at DATETIME,
    completed_by TEXT,                -- auto | manual
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(project_id, template_id, occurrence_key)
);
CREATE INDEX idx_phase_tasks_project ON phase_tasks(project_id, status, due_date);
CREATE INDEX idx_phase_tasks_due ON phase_tasks(status, due_date);
```

| 列 | 读写行为 |
|----|---------|
| status | `pending_activation`：时期未到的模板带入实例——不计入应办/脉搏带/首页待办；阶段切换时该时期实例激活为 open |
| occurrence_key | 周期幂等键；滚动生成器冲突即跳过（INSERT OR IGNORE 语义） |
| linked_entity_* | 自动完成匹配载体：material 任务在用户手动关联文件后由事件匹配；match 规则未命中时保留手动路径 |
| template_id | 实例与模板解耦：模板更新不影响已生成实例；改实例不回写模板 |

| 动作 | 路径 | 说明 |
|---|---|---|
| 新建项目铺 Playbook | `POST /projects`（已有端点扩展） | 项目创建成功后同步铺入全时期实例（当前时期 open、其余 pending_activation）+ 置 `playbook_seeded=1`；recurring 首期 = 首个未过期期次（当期已过 → 下一期，§3.5）；事务性：任务插入失败回滚整个创建 |
| 存量项目回填 | 应用启动 `migrate_backfill_playbooks()` | 对 `kind='project'` 且 `playbook_seeded=0` 的项目铺入（当前时期 open、其余 pending_activation；recurring 首期规则同上）+ 置 1；幂等：标记列防重入（用户删光任务不重铺）|
| 新建向导「调整」 | `POST /projects/{id}/tasks` 批量删除/修改 | 可选步骤，抽屉操作 |
| 任务 CRUD | `POST/PATCH/DELETE /projects/{id}/tasks[/{task_id}]` | 自建/编辑/打勾/跳过/删除；经 IPC `affairs:create/update/delete` |
| 阶段切换 | `PATCH /projects/{id}`（已有） | 服务端**先激活**该时期 pending_activation 实例 → open（单事务，失败上抛 500 且 stage 保持旧值），成功后写入 stage；原时期 open 任务保留（review M-2：先激活后写 stage，不留中间态）；recurring 实例按当期算 occ/due，当期已过 → 直接取下一期（2026-10-24 裁决：激活不产出出生即逾期实例） |
| 周期滚动 | 服务端定时（启动 + 每日首次心跳） | 预生成下期 + 补缺口期（限当前节奏格式；改节奏仅影响未来期次，旧格式实例保留不回铺；起点不早于现存最早实例——已跳过/已删除的过去期次不重建），INSERT OR IGNORE |
| 存量清理 | 应用启动 `initialize()` 内数据修复 | 一次性删除出生即逾期存量：`recurring + open + due_date < '2026-10-22'`（周期功能上线前不存在合法 open recurring 逾期，零误伤）；幂等：删过即无命中（2026-10-24 裁决落地） |

### 5.4 事件路径（完成闭环）

```
文件解析完成（KnowledgeWorker，已有事件点 0.4）
  → 任务服务监听：匹配该项目 open 的 material/recurring 实例
     （匹配规则 auto_complete.match：文件名模式 / 手动关联 linked_entity_id）
  → 命中 → status=done, completed_by=auto, completed_at=now（幂等：已 done 跳过）
  → 心跳事件 → 打开中的事务 Tab / 脉搏带 / 首页待办边沿刷新

报告终态 completed（2.5 已有事件点；reports.py 声明点旁直调）
  → 双扫（2026-10-28 产出维度扩扫）：存量 report_completed 仅 report 实例
     （§3.3 种子契约不动）+ output_completed 不限 task_type → done

产出终态 completed（2026-10-28 产出维度：PPT/填表接入）
  → ppt_service 7 处 completed 声明点旁经模块级 helper 直调
     on_ppt_completed；forms.py 填表完成声明点旁直调 on_form_fill_completed
  → 按产出标题匹配 open 实例的 output_completed 规则（标题关键词 | 分隔，
     语义与 report_completed 同款）→ 不限 task_type → done
```

异常语义：匹配与打勾失败仅记日志（`app.log`），不阻塞解析/报告/产出主流程；任务保持 open 由手动兜底——**闭环是增强，不是依赖**。

**实施裁决（二期计划前置调研，2026-10-09 代码实证落定）**：

| 裁决点 | 实证 | 裁决 |
|---|---|---|
| 事件消费形态 | `activity_events` 为「notifications 存储 + SSE 推送」模型，无进程内回调注册机制；文件解析成功 = `complete_file`（task_queue 解析成功处）、报告完成 = `complete_report`（reports.py 生成完成处）、PPT 完成 = `complete_ppt`（ppt_service 7 处）、填表完成 = `complete_form_fill`（forms.py）显式声明 | 任务服务在终态声明点旁**直调**（`affairs_service.on_file_parsed / on_report_completed / on_ppt_completed / on_form_fill_completed`），try/except 包裹仅记日志，与「全部直调点」既有惯例一致，不引入新事件机制 |
| 滚动生成器触发 | 唯一心跳端点 = `GET /activities/status`（0.4 全局心跳，前端 30s 轮询）；启动序列 = lifespan → ensure_preset_base_libs → seed_wiki_schemas | lifespan 启动 roll 一次 + `/activities/status` 入口 check-date roll（内存 `last_roll_date`，跨日即滚，幂等；复用既有心跳，不新增轮询端点） |
| 项目创建挂钩 | `POST /projects`（knowledge.py create_project → db.create_project） | 创建成功后同步铺入任务实例，与创建同事务（任务插入失败回滚创建，§5.3）；存量回填走启动迁移 `migrate_backfill_playbooks`（紧跟 seed 之后） |
| seed 模式 | `db.seed_wiki_schemas`（database.py，INSERT OR REPLACE 幂等） | `seed_playbook_templates` 同款实现，启动序列插在 seed_wiki_schemas 之后、回填之前 |

```
│ ⚠ 收集尽调材料清单                              │
│ 截止 10-12 · 逾期 3 天                          │
│ 完成规则：文件名含「尽调」（可改，经 6.1.7 表单）      │
│ 上传请前往「资料」Tab，解析完成后自动完成本任务        │

└───────────────────────────────────────┘
```

报告类任务抽屉按钮含「发起报告」→ 报告 Tab（裁决 7）；材料类**不内置上传按钮**（裁决 9，2026-10-10：抽屉显示上传引导文案，上传动线收口在资料 Tab，解析终态事件自动完成本任务，避免抽屉内嵌文件选择器）；节点类无上传区，完成靠手动定日期/打勾；done/skipped 实例首按钮为「恢复」（→ open）。done 实例 meta 行在截止日旁显示「完成于 YYYY-MM-DD」（manual/auto 统一口径，取 completed_at；auto 来源叠加「（自动）」标注，收编原 rule 区 auto_done 专属标注——2026-10-28 补齐，此前手动完成的任务无完成时间可看）。完成规则区按 `auto_complete.on` 分流文案（2026-10-28 产出维度）：`file_parsed` 显示文件名规则；`output_completed` 显示「产出标题含「…」的报告、PPT 或填表完成后自动完成」；`report_completed` 显示报告标题规则。

#### 6.1.7 任务新建 / 编辑 / 删除 / 跳过（CRUD 交互）

编辑收口在事务 Tab（决策 10：首页只读直达）；新建与编辑共用同一表单（弹窗，0.3 §4.2 全局弹窗风格），执行抽屉是查看与操作的载体：

```
┌─ 任务表单弹窗（新建/编辑共用）──────────────┐
│ 标题  [____________________]                │
│ 类型  [资料 ▾]（资料/报告/节点/周期事务）        │
│ 截止  [2026-10-20]（节点可空 = 手动定）         │
│ ── 选「周期事务」时切换为 ──                  │
│ 频率  [每月 ▾]  每期截止 [15 日 ▾]             │
│ 完成匹配  [上传文件▾] [文件名含「月报」]（资料/周期可设）│
│           来源二选一：上传文件/项目产出（2026-10-28）    │
│           产出=报告/PPT/填表标题命中即闭环（§5.4）        │
│                     [取消]  [创建/保存]       │
└─────────────────────────────────┘
```

| 操作 | 入口 | 形态与规则 |
|---|---|---|
| 新建 | 时期看板 / 日历「+ 添加任务」 | 上表单弹窗；创建即 open、归当前时期；类型选「周期事务」时切换为节奏字段（频率+每期截止），保存即生成首个未过期期次（当期已过 → 下一期，§3.5；后续期次由滚动生成器接管）；完成匹配词规则见下方说明 |
| 编辑 | 执行抽屉「编辑」按钮 | 抽屉内容切换为上表单（预填）；保存即改实例——**不回写模板**（§6.4-2）；recurring 改节奏仅影响未来期次（按新节奏从当期起铺，旧格式历史期次保留不回铺），已完成期次不动 |
| 删除 | 执行抽屉底部「删除」（红字） | `useConfirm(danger)` 确认（0.3 §4.2）；模板带入实例删除后**不重铺**（`playbook_seeded` 防重入，§4.3） |
| 跳过 / 恢复 | 执行抽屉「跳过」/「恢复」 | 无确认、可逆；打勾/跳过/恢复均 Toast 反馈（§6.4-9） |

完成匹配词对可自动完成的场景开放（`file_parsed` 闭环覆盖资料与周期事务两类，新建与编辑均可设——2026-10-22 放开手动新建资料任务入口：此前仅新建「周期事务」/编辑带规则实例可设，后端 `on_file_parsed` 本就支持 material+file_parsed（模板种子同链），入口不对称致「模板任务能自动完成、手动任务不能」）；**匹配来源下拉二选一（2026-10-28 产出维度）**：「上传文件」落 `file_parsed`（按文件名匹配）/「项目产出」落 `output_completed`（按报告/PPT/填表标题匹配，§5.4），编辑时按既有 `auto_complete.on` 回填来源，切任务类型清空残留词并重置来源；**清空保存 = 移除该实例的自动完成规则**（`auto_complete=null`，退回手动完成）；`report_completed` 规则（报告类）不在表单展示、原样保留（§6.4-1 实例与模板解耦）。

时期看板头部布局补充：「7 项任务 · 2 项本周到期　[显示已跳过 ☐]　[+ 添加任务]」——开关仅在存在 skipped 实例时显示；日历视图「+ 添加」同表单，日期格定位预填截止日。

### 6.4 关键交互规则与不变量

1. tab key `wiki` 不变、`affairs` 新增；`app:navigate-project-tab` 映射表只增不改
2. 任务实例与模板解耦：改实例不回写模板；模板更新不重铺已有项目
3. 阶段切换不删除历史时期任务；回退时期仅展开视图，不激活已过时期任务
4. 周期任务每期一条实例，`occurrence_key` 幂等
5. 自动完成幂等（completed_by=auto 只写一次）；手动操作永远可用
6. 不新增轮询端点：任务数据 = 打开时拉取 + 操作后刷新 + 心跳边沿补拉（0.4 §3.1 验收信号）
7. Chat 面板与 Wiki 预览互斥语义不变（2.1 §6.3）；任务执行抽屉复用同款交互模式（拖宽/遮罩收起/与 Chat 互斥）；mousedown 起于 panel 内（拖宽/正文选字）而松手落遮罩的浏览器合成 click 不触发收起（2026-10-25 修，suppressClick 守卫，与 ScheduleDrawer 同款）
8. 新增 UI 文案 i18n key 前缀：`pulse.*`（脉搏带）/ `affairs.*`（事务 Tab）/ `homeTodo.*`（首页工作台），中英双语进语言包，组件内零硬编码（0.3 §5）
9. 操作反馈复用全局通道（0.3 §4.2/§4.5）：打勾/跳过 → Toast；删除任务 → `useConfirm(danger)`；不新造反馈组件

## 10. 关键设计决策

| # | 决策 | 理由 |
|---|---|---|
| 1 | 报告产出以模板驱动为准，**不做**「基于单页生成报告」入口 | 与 2.5 模板+知识源检索模型不匹配（用户裁决） |
| 2 | tab key `wiki` 不变仅改显示名 | tabSignal/角标/活动跳转映射零改动，回归面最小 |
| 3 | 脉搏带独立于知识总览，不合并 | 状态感知（计数跳转）≠ 内容消化（阅读）；合并必致信息过载 |
| 4 | 事务独立 Tab 而非知识内视图 | 生命周期是独立心智；日历需要横向空间 |
| 5 | 任务=实例、模板=种子、不回写 | 项目是活的，模板是标准；避免双向同步复杂度 |
| 6 | 周期任务每期一条实例（occurrence_key） | 聚合/日历/逾期判定直读，无运行时展开计算 |
| 7 | 完成闭环走事件监听，不轮询 | 0.4 轮询清单不增长；闭环失败有手动兜底 |
| 8 | Playbook 零配置带入 + 按时期激活 | 新建时认知最少不宜配置；一次性涌出即噪音墙 |
| 9 | 脉搏带规则拼接起步，AI 后置 | UI 稳定智能渐进；AI 状态句只换生成逻辑 |
| 10 | 首页待办只读 + 直达，不做编辑 | 编辑收口在事务 Tab，避免双入口状态漂移 |
