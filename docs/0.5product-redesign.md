## 1. 产品定位（补全版）

### 1.1 一句话定位

> 墨方是招商/投资经理的**项目工作台**：把「收集信息 → 整理 → 填表/写报告」交给 agent，
> 把人的时间还给**判断**，让一个人能同时跟进更多项目，且私有数据不出域。

### 1.2 用户画像：招商/投资经理的一天

| 时段 | 场景 | 现状痛点 | 墨方对应能力 |
|------|------|----------|--------------|
| 早晨到岗 | 盘点今天：哪些项目有事？逾期了什么？昨晚世界发生了什么？ | 打开 N 个系统/群/表格逐个翻 | 首页「今日概览 + 待办 + 动态」 |
| 上午 | 领导/客户临时要某企业情况 | 手工查天眼查/企查查/搜索引擎，粘贴拼报告 | 任务 agent + browser-fetch + 报告生成 |
| 上午 | 项目企业出了新闻（负面/竞品动作） | 被动等别人转告，滞后 | 舆情/竞品监控（E3 定时任务） |
| 下午 | 填政府/内部系统表格、写周报月报 | 重复搬运信息到固定格式 | 填表 forms + 报告 reports + PPT |
| 下午 | 新项目立项/新线索初筛 | 开 Word 建目录、找模板 | 项目模板（招商/投资类型+阶段+预置结构） |
| 随时 | 对上汇报/横向共享 | 打包发邮件、截图拼文档 | 项目导出、报告导出、Wiki |
| 深度工作 | 尽调、估值、投决材料 | 方法论在脑子里，产出靠熬夜 | primary-market-skill（尽调清单/投行文书/建模） |

### 1.3 价值主张（五层，按用户可感知排序）

| 层 | 主张 | 用户可感知的证据 |
|----|------|------------------|
| 效率 | 重复劳动自动化 | 模板任务一次点击发起；报告/填表自动生成 |
| 覆盖 | 更多项目、不漏事、不漏动态 | 首页跨项目待办聚合；卡片墙新动态标记 |
| 专业 | 内置投研/招商方法论 | primary-market-skill 尽调/文书/建模能力 |
| 安全 | 私有数据不出域 | 本地模型 + 本地存储；外发动作显式可见 |
| 共享 | 信息可控流转 | 项目导出、报告/PPT 导出 |

### 1.4 反面清单（产品不做什么）

- 不做通用聊天陪聊；每次对话都应服务「项目/信息/文书」场景。
- 不做云同步与协作编辑（共享靠导出，安全边界优先）。
- 不自动外发任何数据；所有对外动作（导出/上传）显式触发。
- 不在首屏堆系统诊断信息（服务状态属于设置页与状态栏）。

### 1.5 「工程成果 → 产品」差距标准（整改验收的元标准）

| # | 工程成果的样子（现状病症） | 产品的样子（整改后） |
|---|---------------------------|---------------------|
| 1 | 首屏第一屏是 LLM/VLM/Embedding 服务卡 | 首屏回答「我今天该关注什么」 |
| 2 | 空状态是一句静态文案（欢迎页/无Feed） | 空状态 = 引导下一步动作（建项目/跑模板） |
| 3 | 示例用程序员语言（斐波那契/Flask） | 示例/模板用用户语言（企业信息/舆情/报告） |
| 4 | 能力埋在功能深处（skill/报告/填表无入口暗示） | 门面页表达能力边界：「我能帮你做这些」 |
| 5 | 快捷入口是导航（「打开任务」） | 快捷入口是动作（「新建任务」「新建项目」） |
| 6 | 新用户 Aha 路径 >5 步且无引导 | 零项目 3 步建项目；2 步发起第一个模板任务 |
| 7 | 界面文案混杂系统概念 | 全部用户语言 + i18n 双语 |

## 3. 现状诊断

| 页面 | 现状组成 | 核心问题 |
|------|----------|----------|
| 首页 | 服务状态4卡 → 进行中 → 今日待办 → 近期日历 → 卡片墙+动态流 → 快捷入口 | ①首屏被系统诊断占据 ②快捷入口是导航不是动作 ③情报线零承载 ④无今日概览 |
| 项目欢迎页 | 零项目：一句静态欢迎文案；有项目：自动选中第一个项目，永不显示 | ①零项目态无引导（不建项目、不讲能力）②toggle 取消选中被自动选中顶回（交互失效）③与 OnboardingWizard 职责断档 |
| 任务欢迎页 | 扳手图标 + 「编写和执行代码、操作文件」+ 斐波那契/CSV/Flask 三示例 | ①示例是程序员语言，对目标用户是错位信号 ②能力表达是系统视角 ③与项目内对话面板无模板共享 |

## 4. 整改设计

### 4.1 全局产品化原则（对所有页面生效）

| 原则 | 规则 |
|------|------|
| 用户语言 | UI 与门面文案禁止出现 LLM/VLM/Embedding/parsing 等系统词；需要时用「智能引擎/理解/检索」等表述，技术名词仅存于设置页与日志 |
| 空态即引导 | 每个空状态必须回答：「这是什么 + 我下一步该点哪里」，并给出可点击动作 |
| 动作优先 | 门面快捷入口一律为动词（新建/发起/上传），导航交给侧栏 |
| 场景示例 | 一切示例/模板文案取自 §1.2 用户场景，禁用程序员示例 |
| 产出可见 | 任务/报告/填表的产出必须在首页或项目层有「新产出」路径，不允许产出后无声 |
| 双语对齐 | 所有新增文案 zh-CN/en-US 同步（§2.3） |

### 4.2 首页

**现状 → 目标**（自上而下）：

| 区块 | 现状 | 目标 | 变更 |
|------|------|------|------|
| ① 今日概览条 | 无 | **晨会英雄区 `MorningHero`**（V2-E1b 2026-10-24 升格，[0.6 §3.1①](0.6v2-ux-redesign.md)）：大字日期问候 + 晨报句「今天 N 场跟踪、X 条新情报、Y 项待办」+ KPI 行内文本链（项目/逾期/今日/进行中，点击滚动锚点） | 已替代概览条（E1b：HomeOverviewBar 全链退役，KPI 锚点行为保留；数据同源 dueData + useActivity，零新增轮询） |
| ② 服务状态 | 4 卡置顶 | **移出首页**，升级为 App 级 `SystemAlerts` 统一告警区（TitleBar 之下全局可见，服务异常红条与杀软授权橙条同区同视觉语言，点击进设置，正常时完全不可见；2026-10-18 首页打样修订，原「首页顶部横幅」并入告警区） | 迁移 |
| ③ 进行中活动 | 有，空闲隐藏 | 保留；无活跃活动时显示空态占位（2026-10-18 用户裁决：首页空数据模块保留显示） | 空态化调整 |
| ④ 今日待办 + 近期日历 | 有，空隐藏 | 保留；无数据时显示空态占位（同上裁决） | 空态化调整 |
| ⑤ 项目卡片墙 | 健康+阶段+下一事务+台账摘要 | 保留；**E2 增加「新产出」角标**（任务/报告完成后 24h 内未查看） | 增强 |
| ⑥ 今日情报速览 | 无 | 跨订阅期次时间流（未读优先，收件箱摘要，「查看全部」进情报中心，详见 [2.11 §8](2.11scheduled-task-design.md)）；已随 E3 落地；V2-E1a T10 上移主列顶部 + 空态引导（[0.6 §3.2](0.6v2-ux-redesign.md)） | 已落地（E3 + V2-E1a T10） |
| ⑦ 快捷动作 | 「打开任务/打开项目」两张导航卡 | 改为动作卡：**新建任务 / 新建项目**（直接唤起对应流程） | 改造 |
| ⑧ 动态流 feed | 有 | 保留 | 不变 |

布局（目标；2026-10-18 首页打样修订为**全宽 dashboard 网格**；V2-E1b ① 升格英雄区）：晨会英雄区（①，全宽，日期问候+晨报句+KPI 行内链）→ 主列（③ 进行中 → ④ 今日待办+近期日历 → ⑤ 项目卡片墙 auto-fill 自适应列）+ 侧列（⑧ 动态流 → ⑦ 快捷动作，固定 ~340px）；② 告警条渲染于 App 级 `SystemAlerts`，不在首页内容流；⑥ 情报速览（E3）落地时入侧列顶部。窄屏（<1100px）侧列并入底部退化单列。⑥ 居侧列顶位：早晨盘点动线「先看昨晚世界（情报），再排今天安排（待办）」（2026-10-19 用户裁决：清理原「置于待办/日历之前」残句与「入侧列顶部」主句的矛盾，保留动线理由）。

**交互规则**：
- 英雄区 KPI 行内链各自可点（E1b 概览条四段升格为行内文本链，锚点行为保留）：项目数→卡片墙锚点；逾期/今日→待办列表锚点；进行中→活动区锚点。
- 服务异常告警条与杀软授权条同处 App 级 `SystemAlerts`（`src/components/layout/`），同一数据源（`system:getHealth`）：挂载拉一次 + `app:health-changed` 事件边沿（设置保存成功）/窗口 focus 重拉，零新增轮询（0.4 §8.1）。首页不再拉取健康态。
- 新建任务卡：唤起侧栏任务列表的「新建」流程（复用 `handleCreateTask`）；新建项目卡：唤起项目创建向导（复用 ProjectList 创建模态，与 §4.3 引导共用）。

### 4.3 项目欢迎页

**职责重定义**：零项目的「第一个项目引导」，有项目时不可见（保持自动直达，这是对的）。

| 现状 | 目标 |
|------|------|
| BookOpen 图标 + 「欢迎使用知识库」+ 一句静态描述 | **三步开始**引导卡：① 选项目类型（招商 Factory / 投资 DollarSign / 通用 FolderOpen，复用 `PROJECT_TYPE_CONFIG`）② 命名创建（复用 `knowledge:createProject`）③ 创建后直达项目详情并高亮「上传第一批资料」/「发起第一个任务」入口 |

交互规则：
- 类型选择卡带一句话场景描述（如招商：「项目落地全流程管理：线索→洽谈→签约→开工」；投资：「投前尽调到投后跟踪」）。
- 创建成功后沿用现有自动选中逻辑进入详情页，onboarding 气泡提示第一批动作（气泡为一次性，localStorage 记忆）。
- 修复 toggle：`handleProjectSelect` 再次点击已选项目 → 清空选中回到欢迎态时，自动选中 effect 不得立即顶回（增加「用户显式取消」标记，仅当切换导航或重新选择时清除，见 §6 数据流）。
- 「新建项目」按钮仍保留在侧栏 ProjectList 顶部，欢迎页大卡与它是同一流程的两个入口。
- 视觉落地（2026-10-19 打磨）：引导卡在页面水平垂直居中（`KnowledgePage pageWelcome`，与任务欢迎页一致）；步骤头用 accent 圆形数字徽章（`stepNum` 20px）替代文案内嵌①②字符（双语 i18n 文案已去前缀，FirstProjectHint 的③同源清理）；创建按钮全宽与输入框对齐；侧栏「导入项目包」并入「新建项目」主钮右侧小图标钮（`newBtnRow` = 主钮 + 36px Upload 图标钮，与 TaskList `newDirBtn` 同构；导入进行中显示旋转 Loader，进度经 title 回显），「新建项目」保持 accent 虚线主导不动（2026-10-19 用户裁决：独立导入钮与新钮重视觉权重难区分，采纳任务侧栏既有同构模式）；引导卡容器宽度与任务欢迎页统一 720px，类型卡与模板卡同一规格（padding 16 / 卡距 12 / hover accent 边框+浮起，选中态 bg-selected 恒区分于 hover）。

- 文件上传/拖放零任务态可用（2026-10-21 用户裁决，「上传即建任务」）：上传钮仅受生成中门控；零任务态点击上传/拖放文件 → 先经 App 层 `ensureTask`（与发送共用同一建任务链路）建任务 → 文件挂新任务工作区（`tasks:pickAndUpload`/`tasks:uploadFiles` 仍需 taskId，「文件必须落任务工作区」约束不变）；建任务失败 toast 反馈，句柄为 null 时不上传。拖放真实路径经 preload `webUtils.getPathForFile` 换取（修复：Electron 32+ 移除 `File.path`，原实现读取恒 undefined → 静默 return，拖放在有/无任务态均失效）；拖入无磁盘路径的虚拟文件（如网页图片）toast 提示改用附件按钮。
- 粘贴截图直传（2026-10-21；同日 review 修复 M1-M3）：任务聊天输入框 Ctrl+V 粘贴剪贴板截图（Win+Shift+S / 微信 / QQ 等截图工具产物）→ 仅拦截 image/* 项（其余粘贴行为不变）转 base64 走 `tasks:uploadClipboardImage` 字节通道——剪贴板图片无磁盘路径，`webUtils.getPathForFile` 不适用；main 进程解码后与磁盘上传共用同一 multipart 构造（`_postMultipartFiles`）与 python 端点（落盘 + 注入系统通知，agent 可用 vision 工具解析）；自动命名经 `clipboard-image-name.js` 纯函数：毫秒时间戳（`clipboard-YYYYMMDD-HHmmss-SSS.ext`，端点同名覆盖写，秒级命名在同秒多图/连续粘贴时静默丢图）+ JPEG 魔数嗅探（FF D8）定扩展名（恒 .png 会把 JPEG 字节谎报为 PNG 被 vlm 严格端点拒收）；40MB base64 护栏为该路径唯一尺寸限制（解码 ≤30MB 触不到端点 50MB 校验），护栏拒绝与 python 200-错误体（`{error, code}` resolved 值）前端判 error 转 toast 不静默；零任务态同样先经 `ensureTask` 建任务。
- 点击模板 → prompt 预填输入框，同时输入框上方出现**占位符表单**；用户补齐后发送。**模板不直接发送**（模板是半成品 prompt）。

## 5. 数据结构

> 项目未上线无存量数据，无迁移负担（§一、操作纪律）。

**E1 不新增任何表**：内置模板走 i18n JSON（与现有文案同管理），模板清单为前端常量数组。

**E2 新增表 `task_templates`**（自定义模板持久化）：

```sql
CREATE TABLE task_templates (
  id          TEXT PRIMARY KEY,      -- 'tpl_custom_<uuid>'
  scope       TEXT NOT NULL,         -- 'global' | 'project'
  project_id  TEXT,                  -- scope='project' 时必填
  category    TEXT NOT NULL,         -- info_gather|monitor|industry|report_invest|office
  title       TEXT NOT NULL,
  prompt      TEXT NOT NULL,         -- 含 {占位符}
  builtin     INTEGER NOT NULL DEFAULT 0,  -- 0=自定义；内置行不落库（始终以 i18n 为准）
  pinned      INTEGER NOT NULL DEFAULT 0,
  created_at  TEXT NOT NULL,
  updated_at  TEXT NOT NULL
);
CREATE INDEX idx_task_templates_scope ON task_templates(scope, project_id);
```

读写行为：内置模板（i18n 常量）+ 自定义模板（表）在 IPC 层合并返回；内置模板 pinned 可写（落库 upsert 一行 builtin=1 记录置顶态）。

**「新产出」标记（E2）**：不新增表。从 Activity feed 终态事件派生（completed 且 entity 属于该项目且 created_at < 24h 且未点击），消费端派生，零写入。

### 7.3 关键交互规则与不变量

- 模板点击只改输入框内容，绝不自动发送。

- 占位符未填齐时发送按钮不禁用（用户可能有意留白让 agent 追问），但发送前 toast 提示「模板中还有未填写项」一次。
- 占位符表单联动不变量（2026-10-20）：变量按名去重、填一次全量替换；手动编辑输入框即接管（表单隐藏，联动不回退）；重选模板重置表单，发送成功后清空。
- 「显式取消」不变量：用户在侧栏点击已选项目取消选中后，同一导航会话内不再自动选中；切换 NavTab 或新选择后守卫复位。
- 首页所有区块空态遵循 §4.1；进行中/待办/日历空数据时保留区块显示空态占位（2026-10-18 用户裁决「首页空数据模块保留显示」，推翻原「空即隐藏」条款；服务异常横幅除外——正常时不渲染，异常告警消失是正确行为）。
