### 2.2 InkCube 两路由映射（修正 2.3 §1.2）

| InkCube 功能 | 承载路由 | 说明 |
|---|---|---|
| 报告 → PPT（E1） | **Generate Default** | 唯一带完整持久规划 + 两阶段门禁 + 可恢复的路由 |
| 模板生成/编辑（E2） | **Create Template** | 产物进 ppt-master 库，经注册后 Generate 可选用 |
| 不暴露 | quick / beautify / image-to-pptx / template-fill | 见下「排除理由」（成品增强 Native Enhance 曾接入，2026-10-28 全链下线） |

**排除理由（写死，防止实施时走偏）**：

- **quick-generate 排除（硬性）**：无 `design_spec.md`/`spec_lock.md`、无 confirm_ui、无恢复记录——上下文丢失即整轮重启。InkCube 是 40 分钟级后台长任务，不可接受。**InkCube 所有 Generate 调用必须走 Default**（`svg_to_pptx.py` 不带 `--quick-generate`）。
- **template-fill / beautify / image-to-pptx 暂不暴露**：输入是「用户自己的 PPTX」，与 InkCube「报告→PPT」主场景不符；若未来要做「改排版」形态再评估 beautify。

### 3.2 端到端命令链（InkCube 任务编排者视角）

```bash
# ① 建项目（InkCube prepare 阶段系统执行，非 agent；目录名 ppt_project_ppt169_<YYYYMMDD>
#    带后缀与全链锚定一致——agent 自行 init 会被 cli 追加后缀致锚定错位，§3.1 修订）
python3 scripts/project_manager.py init ppt_project_ppt169_<YYYYMMDD> --dir <workspace> --format ppt169
# ② 导入素材（md 原样进 sources/；图片库选中图导出后进 images/）
python3 scripts/project_manager.py import-sources <project> <report.md> <images...>
# ③【模板模式】服务端预写 confirm_ui/template_options.json + agent 写 recommendations.stage1.json
# ④ 启动门禁（§5）
# ⑤【模板选中后】安装 + handoff：
python3 scripts/svg_quality_checker.py <root>/templates --template-mode   # 只读校验
#   （复制 roster/spec → agent 写安装回执 → ）
python3 scripts/confirm_ui/server.py <project> --complete-template-selection
# ⑥ agent 写 recommendations.stage2.json → 用户最终确认（result.json stage=final）
# ⑦ Strategist 产出 design_spec.md + spec_lock.md（LLM 工作，无 CLI）
# ⑧ Executor 逐页 svg_output/page_NN.svg（LLM + svg_position_calculator 等辅助）
# ⑨ 导出三连（串行，任一失败即停）：
python3 scripts/total_md_split.py <project>      # 仅备注启用时
python3 scripts/finalize_svg.py <project>        # svg_output → svg_final
python3 scripts/svg_to_pptx.py <project>         # svg_output → exports/*.pptx
```

### 3.3 flat 与 structured 导出（结构化模板的最终形态）

`svg_to_pptx.py` 按 Strategist 派生的 `template_reuse_scope` 决定 PPTX 结构：

| 模式 | 触发 | PPTX 形态 |
|---|---|---|
| `flat` | 自由设计 / Brand-only / Style-only（scope=style） | 单 Master + Blank Layout，全部对象 Slide-local |
| `structured` | 选中 Layout/Deck 且 scope=mirror\|layout | 按模板契约命名 Master/Layout + 每页 Layout 指派 + 槽位 |

> 模板详情页承诺「导出保留母版/版式」仅 structured 成立；纯 Style/Brand 组合导出是 flat。E2 模板工坊宣传文案需按此对齐。

## 4. Strategist 两阶段确认（Generate 的门禁语义）

ppt-master 的 Generate 门禁是**两次独立确认**（2.3 原文「一处门禁」不准确，已按此修正）：

| 阶段 | 内容 | 字段组 | 产物 |
|---|---|---|---|
| **Stage 1** | 沟通契约 + 模板选择（一次提交绑定两项） | 7 个 prose 字段（audience/communication_intent/audience_outcome/core_message/delivery_context/artifact_afterlife/content_divergence，均可留空）+ primary_language + canvas + 模板 free_design/templates 模式与四类下拉 | `result.json`(stage1) + `template_selection.json` 同时写入 |
| 【间隙】 | agent 自动执行模板安装（§6.3），无需用户参与；UI 页面保持打开轮询 | — | `template_handoff.json` |
| **Stage 2** | 完整方案 + 生产机制 | reading_mode / mode / visual_style / page_count / **design_directions**（3 个完整设计候选，选中+可改）/ 六角色色板 / 字体+字号 / icons / image_usage（多选：ai/web/provided/placeholder/none）/ image_ai_path / proactive 三布尔（备注/动画/旁白）/ generation_mode（continuous/split）/ refine_spec / template_application（模板模式） | `result.json`(stage=final) + 页面自动关闭 |

- **Stage 2 依赖 Stage 1**：progression guard 校验文件新旧顺序（handoff 必须新于 stage1 selection；stage2 recommendation 必须新于 handoff）。
- **confirmed 值即合同**：`result.json`(final) 是 Strategist 写 `design_spec.md` 的唯一输入契约，后续阶段不得静默削弱（fail-closed，见 §9）。
- **surface 决策**：confirm_ui.md 规定「最近一次显式指示」决定页面/chat 分支；**无指示默认页面**。InkCube 永远走页面分支（§5.4）。
- **beautify 复用同一两阶段**（seed 自源身份、content_divergence locked），若未来暴露 beautify 可同机制接入。

## 5. confirm_ui 集成契约（E1 最关键接口）

### 5.1 文件契约五件套（`<project>/confirm_ui/`）

| 文件 | 写入者 | 时机 | 要点 |
|---|---|---|---|
| `template_options.json` | agent（服务端每次 UI run 前 `--reset-template-selection` 后重写） | 启动前 | `{schema_version:1, phase:"template", lang, default_mode:"free_design"\|"templates", explicit_workspace_roots:[]}`；**库模板不写进来**，server 自己读四索引构建候选 |
| `recommendations.stage1.json` | agent | 启动前 | `stage:"stage1"` + 7 prose 字段（`recommend.canvas` 等）|
| `result.json` + `template_selection.json` | **server**（/api/confirm） | 用户提交 Stage 1 | 同时写；selection 含 `mode` + `selections[]`（source/kind/id/workspace_root）+ `options_sha256`/`selection_sha256` 绑定 |
| `template_handoff.json` | `--complete-template-selection` 命令 | 安装完成后 | `{status:"ready", mode, selection_sha256}`；**禁止手写** |
| `recommendations.stage2.json` | agent | handoff 之后（文件时间必须更新） | `stage:"stage2"` + 完整方案字段 |
| `result.json`（final） | **server** | 用户提交 Stage 2 | `stage:"final", status:"confirmed"` + 全字段；写后页面自动关闭 |

### 5.2 server CLI 全表（`scripts/confirm_ui/server.py`）

| 命令/参数 | 语义 | InkCube 用法 |
|---|---|---|
| `<project> --daemon` | 后台启动 Flask，健康检查后打印 `http://127.0.0.1:<port>` | InkCube 系统拉起（S1 2026-10-28）：sync_progress 门禁置位/重启恢复 awaiting 时探活幂等拉起，agent 不再手动启动 |
| `--wait-only --wait-stage stage1` | 阻塞等待 Stage 1 回执（默认预算 **590s**，`--wait-timeout` 可调） | **不要用**：InkCube 用产物轮询代替阻塞（长任务不能挂在 wait 上）|
| `--wait-only` | 等待 Stage 2 | 同上不用 |
| `--complete-template-selection` | 校验 sidecar + 写 handoff（模板模式要求项目内已有 `templates/design_spec.<kind>.<id>.md`） | 安装后由 agent 调 |
| `--reset-template-selection` | 清除三份模板 sidecar（不动 result.json） | 每次 UI run 前自动执行 |
| `--shutdown` | 幂等关停（优雅 /api/shutdown → 杀 pid → 清锁） | 门禁结束关停：页面提交前端自动 POST /api/shutdown + 泵终态/取消/delete/恢复落位系统兜底（释放 5050 段端口给 live-preview） |
| `--port N` | 精确端口（默认 5050 起第一个空闲） | InkCube 可不传，读输出实际端口 |
| `--no-browser` | 禁止自动开浏览器 | **必须传**：InkCube 由前端内嵌打开 |
| `--timeout 0` | 禁用空闲自动关停（默认 900s idle） | 建议 0（InkCube 用户可能在门禁停留很久），关停由系统在门禁结束/任务终态时保证 |

锁：`<project>/.confirm_ui.lock`（重复启动拒绝、死 pid 覆盖）。

### 5.3 HTTP API（InkCube 前端可直连）

| 端点 | 方法 | 用途 |
|---|---|---|
| `/api/health` | GET | 就绪探测（server 校验自身、项目、子进程标识） |
| `/api/session` | GET | `phase: "strategist" \| "waiting_agent"`（Stage 1 提交后 → waiting_agent，直到 handoff + stage2 文件就绪）|
| `/api/recommendations` | GET（no-store） | 当前 stage 渲染载荷；**Stage 1 响应内嵌 server 构建的候选目录**（library 四组 + explicit + preselected_keys + options_sha256） |

| `/api/catalogs` | GET | 四语言选项全集（canvas/modes/visual_styles/icons/image_usage/…） |
| `/api/shutdown` | POST | 优雅退出 |

依赖：**flask**（pip）；前端零依赖（自带 app.js/index.html，四语言）。

### 5.4 InkCube 集成方案（两案对比，**推荐 A**）

| 方案 | 做法 | 优点 | 代价/风险 |
|---|---|---|---|
| **A. 内嵌原生页面（推荐）** | 后端 spawn `server.py --daemon --no-browser --timeout 0` → 读实际端口 → 前端在详情页 `<webview>/iframe` 加载 `http://127.0.0.1:<port>`；ppts 状态机仅消费 `confirm_ui/` 文件出现顺序做 awaiting_input→running 流转 | **零协议实现**：sha256 校验链、四语言、catalog 渲染、 Stage1→Stage2 轮询全部复用官方 UI；ppt-master 升级零适配 | UI 风格与 InkCube 不完全一致；webview 需要 Electron 权限配置 |
| B. InkCube 自渲染卡片 + 代提交 | 门禁卡片读 `/api/recommendations` 渲染 → 用户操作后服务端代 POST `/api/confirm` | UI 完全统一（2.3 原型即此形态） | 必须完整跟 implement sha256/options 漂移校验、design_directions 编辑态、四语言——**成本高且易漂移**；Stage 2 字段极多（色板/字体/directions 编辑器） |

> **决策记录**：E1 采用 A（内嵌），门禁卡片 UI（2.3 原型形态）降级为「状态摘要条 + 打开确认页按钮」，不再自渲染全部字段。2.3 §3.4 原文「门禁卡片直接渲染 confirm_ui JSON」按此修正——渲染载荷可以读，但**交互提交一律走原生页面**。
> 若用户坚持视觉统一走 B，则 E1 工期需按 +3~5 天估计（仅 Stage 1 + Stage 2 只读预览、复杂编辑回落原生页的混合形态）。

### 5.5 `result.json`（final）关键字段速查

| 字段 | 形态 | 说明 |
|---|---|---|
| `primary_language` | BCP-47（zh-CN…） | 服务端规范化，拒绝 und |
| `canvas` | `ppt169` 等 8 种（§8.4） | config.py CANVAS_FORMATS 为唯一权威 |
| `page_count` | `"12-15"` 区间或数字 | Strategist 解析为精确 roster |

## 6. 模板体系契约（四类型 / 索引 / 安装 / 创建）

### 6.1 四类型权威定义（templates/README.md 原文）

| Kind | 拥有 | 不拥有 | 索引文件 |
|---|---|---|---|
| Brand | 身份：色板、字体、logo、语音/语气、图标风格 | 页面结构、SVG roster | `brands/brands_index.json` |
| Style | 方向/方法：可复用沟通方法、视觉语言、构图节奏、信息表达默认值 | 官方身份、页面结构、SVG roster | `styles/styles_index.json` |
| Layout | 品牌中立结构：画布、Master/Layout 图、页型、槽位、SVG roster | 品牌身份、固定应用场景 | `layouts/layouts_index.json` |
| Deck | 复用演示族：应用契约 + 集成身份 + 结构 | — | `decks/decks_index.json` |

**四轴正交**（禁止当同义词用）：kind（brand/style/layout/deck）× source（library/explicit）× 创建策略（standard/fidelity/mirror，内部值）× 应用计划（template_reuse_scope：literal/structural/style-only，Strategist 派生）。

**索引 schema 实测**（两形态并存，均以 template_id 为 key）：

```json
// styles_index.json（方法型：无结构字段）
{ "academic-research": { "summary": "...", "keywords": ["academic", "..."] } }
// decks_index.json（结构型：带画布/页数/主色）
{ "中国电信": { "summary": "...", "canvas_format": "ppt169", "page_count": 5, "primary_color": "#C00000" } }
```

> InkCube 模板管理分区详情卡可按 kind 展示差异字段；register_template 的完成卡片（`_print_completion_card`）即字段来源参考。

### 6.2 workspace 契约（library 与 project 两形态）

```text
<template_workspace>/            # library 根：templates/<kind_dir>/<id>/
├── templates/design_spec.md     # 库形态单一 spec（容器已含 kind+id）
├── templates/                   # 结构型（Layout/Deck）另有页面原型 SVG（NNN_<page_type>.svg）；mirror 另有 native_payloads.json.gz + template_execution_manifest.json
├── images/                      # 可选位图
├── icons/imported/              # 可选导入矢量
└── exports/                     # Review PPTX（永不作为模板输入）

<project>/templates/             # 项目形态：扁平，一个 kind 一份
├── design_spec.<kind>.<id>.md   # 安装产物，kind/id 必须与 frontmatter 一致
```

- Style workspace **只有** `templates/design_spec.md`（实测 academic-research 仅此一文件 10.9KB）——无 SVG/资产；「Style 模板详情」可展示的内容 = spec 文本 + 索引 summary/keywords。
- Layout/Deck 详情可展示（实测 decks/中国电信）：`templates/*.svg` 页面原型渲染图（`01_cover.svg`~`05_ending.svg`）、design_spec frontmatter（画布/摘要/关键词/主色）+ 正文（色板/字体/页面清单）、`images/` 包内资产、Review PPTX（多 Master 必生成/单 Master 按需）。注意 `manifest.json`/`native_structure.json`/`svg/master_*.svg` 属 pptx_template_import 临时分析工作区，**不进模板包**。
- 结构校验权威命令：`python3 scripts/svg_quality_checker.py <root>/templates --template-mode`（错误即拒绝安装）。

### 6.3 安装机制（apply-template-workspace，Stage 1 与 Stage 2 之间的自动环节）

1. **输入归一**：库根（=索引推导路径）标记 `library`；显式根标记 `explicit`。每 kind 至多一个根；Layout+Deck 可共存，Layout 结构优先。
2. **预检**：svg_quality_checker 校验 spec/schema；Layout/Deck 另做结构化预检（root Master/Layout 键、槽位拓扑）。
3. **原子安装**（一次性写，禁止递归拷贝兜底）：spec → `design_spec.<kind>.<id>.md`（头部插入一行 provenance）；结构 owner（Layout 优先）的 SVG roster + 包内 images/icons 各拷一次；**exports/ 永不拷**。
4. **段落所有权**（读取时消解，非安装时合并）：身份 = Brand>Deck；结构 = Layout>Deck；应用语境 = Deck；方法 = Style。
5. **项目本地边界**：安装后所有消费方只读 `<project>/templates/`，不再回读库根。
6. agent 运行 `--complete-template-selection` 写 handoff（§5.1）。

> InkCube 的「模板选用记录」（ppts 表/详情页）直接读安装产物 `design_spec.<kind>.<id>.md` 文件名即可获得 kind/id/provenance。

## 7. 导出链契约（Step 7 三命令 + svg_to_pptx CLI）

### 7.1 串行三命令

## 8. 资源与环境依赖

### 8.1 凭据注入：.env 机制（config.py 实测）

查找顺序（第一个存在者生效）：**`Path.cwd()/.env`** → `<skill根>/.env` → `<REPO_ROOT>/.env` → `~/.ppt-master/.env`。

### 8.2 图片生成后端（image_gen.py，14 家）

**InkCube 现实**：用户已配置 LLM 提供商；E1 建议 `IMAGE_BACKEND=openai`（OPENAI_BASE_URL 可指向兼容网关）复用现有凭据体系；未配置图片凭据时向导 `image_usage` 应收窄为 provided/placeholder/none 并提示。

### 8.3 图片搜索 / TTS

- 搜索：`image_search.py` + providers（openverse/pexels/pixabay/wikimedia）；`IMAGE_SEARCH_*` 前缀；`web` 路径需要网络且 results 需 review（web-image-review stage）。

### 12.2 md 的层次模型（2.3.2 精简版）

ppt-master 的 md 不是平级资料，而是**按强制加载序组织的运行时程序**：`SKILL.md` → attribution_guard 协议墙 → `routing.md`（唯一路由权威）→ 唯一路由权威 → 显式触发的支撑文档（stages/角色/技术规范）。11 层结构与逐层清单、五种关系边、交叉引用枢纽（generate-pptx.md 27 入引 / shared-standards-core.md 22 / image-generator.md 15）、E1/E2/E3 阅读路径见 2.3.2。

### 12.3 py 的组织模型（2.3.3 精简版）

顶层 73 个散布脚本（48,882 行）+ 14 个 py 子包（108,403 行）；每个工作流一个顶层薄壳入口、重逻辑进子包；`config.py` 是全部环境变量的解析源头；E1/E2/E3 调用序列与排除集见 2.3.3 §4。

### 12.4 三个全局事实（实施前提）

1. **协议墙**：attribution_guard 校验 SKILL.md + LICENSE + 12 核心脚本哈希，任何包内修改 = 运行即停；InkCube 姿态 = 包内零修改 + 外部驱动（§10）。
2. **权重分布**：`svg_to_pptx/` 子包独占 47,198 行（全包 30%）+ 质检门 9,324 行——导出正确性边界；md 侧 svg-effects（980 行）与 shared-standards-core（703 行）是 SVG 创作质量边界。E1 的质量风险集中在「SVG 创作质量 × 导出保真」这条轴上。
3. **唯一遗留疑点**：`references/image-palettes/`（15 个 md）零文档引用，疑似遗留目录——E1 研读 image 链时验证，若确认废弃可作为打包裁剪候选（唯一可裁项，其余孤儿均为设计使然）。
