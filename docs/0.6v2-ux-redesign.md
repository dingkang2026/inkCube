# 0.6 V2 信息架构重设计 — 四支柱版图（情报 · 生命周期 · 知识册 · 产出）

> 墨方 InkCube V2 版 UI/UX 总设计。信息架构按「招商/投资经理的四份工作」重新摆盘：情报升一级导航、项目页四 Tab、知识册阅读优先、产出合并。「不新增功能」限制已解除（用户拍板 2026-10-23），V2 新增两个器官——**线索池**（焊住「找→跟」漏斗断点）与**组合泳道**（纯前端快赢）；组合周报 / 知识册导出列 V2.1 候选。
> 状态标注：**现状** = 代码实际行为；**目标** = 本文设计。未标注者为通用设计约束。

## 1. 产品定位与四支柱

### 1.1 客户工作模型（设计依据）

两类客户日常工作同构（工作全景表见 2026-10-23 设计评审记录），每份工作都有明确承载面：

| 招商经理 | 投资经理 | 本质（支柱） | V2 承载 |
|---|---|---|---|
| 扒线索 / 盯竞品园区 | 扫赛道 / 盯竞品基金 | ① 情报（撒网+盯梢） | 情报中心（一级导航：情报流 / 线索池 / 订阅管理）+ 首页情报卡片区 |
| 推项目节点 / 盯已落地企业 | 推进尽调交割 / 盯条款投后 | ② 项目生命周期 | 项目·事务 Tab + 脉搏带 + 首页投资组合卡片墙 / 泳道 |
| 摸底尽调 / 读月报对数 | 尽调比对 / 读被投企业月报 | ③ 知识册（去伪存真、可阅读） | 项目·知识 Tab（阅读优先重构） |
| 周报月报 / 填系统表 / 汇报 PPT | 投决材料 / LP 季报 / 董事会 PPT | ④ 产出效率 | 项目·产出 Tab（报告+填表+PPT）+ 任务模板 |

价值链：**找（情报）→ 跟（生命周期）→ 懂（知识册）→ 交（产出）**，一切围绕项目展开：
情报是项目的输入，知识册是项目的记忆，交付物是项目的输出，生命周期是主线。

### 1.2 情报中心与任务的关系（关键澄清）

一句话：**任务是「派活」，情报是「委托」；订阅 = 任务 × 周期节奏，情报中心 = 订阅产出的阅读与管理面。**

| 关系 | 内容 | 状态 |
|---|---|---|
| 生产（任务→情报） | 每条期次 = 一次后台任务的产出（影子任务）；订阅 = 模板 prompt + 周期 + 去向；期次「执行过程」回放 = 任务工作区 | 已有 |
| 孵化（模板→订阅） | 订阅创建向导第①步模板列表 = **情报白名单**（§3.2）：内置 7 条（舆情/竞品→企业、产业舆情/产业事件/招商线索/产业政策→产业、区域招商政策→区域），选中自动映射分类 | 白名单为 V2 决议（2026-10-23；产业舆情 2026-10-24 增补）；任务级「设为定时」退役（§7）——情报与任务的分界 = **周期性盯梢**（基础/摸底/报告/办公是一次性任务，非情报） |
| 消费（情报→任务） | 线索「转跟进任务」（复用 `tasks:create` + 预填）；期次产物自动沉淀绑定项目 | 转任务为 V2 新增交互（已拍板）；沉淀已有 |
| 沉淀（期次→线索） | 期次「存为线索」入线索池经营；线索「立项」转项目（带来源）；线索「升级为订阅」转长期盯梢 | V2 新增（线索池，§4.1，已拍板） |
| 边界 | 情报中心不做任务管理（运行看板在任务 Tab/首页进行中区）；任务页不做期次阅读；线索池刻意保持薄卡（不做 CRM：无联系人/商机组）；两个 Tab 共享同一执行引擎、模板库、活动中心 | 设计约束 |

心智：同一台引擎，手动挡（任务）与自动挡（情报）两个驾驶舱。

## 3. 分面重设计（现状 → 目标）

### 3.0 V2 视觉语言（全局，2026-10-23：从「工程仪表盘」到「高级晨报」）

用户裁决：现状整体「太工程化」——等权重卡片阵列 + 框线分区 + BI 数字卡是病根，**不止首页，是全应用**。V2 全局升级设计语言，六原则：

| # | 原则 | 规格 |
|---|---|---|
| 1 | 焦点优先 | 每页一个视觉英雄：首页=晨会英雄区（大字日期问候 + 晨报句 + 行内 KPI，§3.1①）；情报中心=大标题页头；项目页=脉搏带升格排版 |
| 2 | 去框化 | 卡片去边框，改极浅底色差 + 柔和投影悬浮面；区块间 24px 留白 + 8% 透明度 1px 分隔线；禁止等距框线网格 |
| 3 | 编辑排版 | 列表类内容「1 大 + N 小」层级化（最新/最重要占大卡带正文预览，其余紧凑行）；消灭等大卡阵列 |
| 4 | 排版层级拉开 | 字阶对比加大（display 28~32 / title 18 / body 14 / caption 12 + 大字距标签）；大数字展示级排版（tabular-nums） |
| 5 | 色彩纪律 | 中性色阶为底 + 单一品牌强调色（关键数字/主动作/进度条）；语义色只给状态（红失败/黄警告/绿成功）；无第三种杂色 |
| 6 | 克制微动效 | 入场淡入上移（120ms）、hover 统一抬升 2px、进度条渐变、未读点光晕；无装饰性动画 |

各页落点：首页 §3.1；情报中心 §3.2；项目页 §3.4-3.5；任务页 §3.6。token 具体值（阴影/色阶/字阶/动效时长）E1 实施时落 [0.3](0.3ux-design.md)。不变量：六原则只动呈现层（样式与展示结构），数据流/通道/文案语义零变化（§6.3 规则 11）。

**E1b 落地登记（2026-10-24）**：token 增量（`--text-display/--text-title/--tracking-label/--hairline/--motion-enter/--motion-base` + 全局 `@keyframes fade-up`）已落 global.css 并同步 0.3 §5（Token 表/卡片语言/区块标题/交互反馈规则改写，豁免表删统计大数字行、增身份层暗底叠加行）；**E1b 落地范围 = 首页全量样板间（§3.1 落点表）+ 身份层/首启向导**，存量其余页面去框化随各页 E 期改造套用（同「存量文档下次修订补齐」惯例）。

### 3.2 情报中心（新一级页）

**情报的定义与分类（2026-10-23 决议）**：情报 = 订阅周期性盯梢的产出——判定标准是**周期性**（订阅 = 任务 × 周期节奏，[2.11](2.11scheduled-task-design.md) 概念模型），不是内容对象；企业基础/深度摸底（查一次即完）、报告/办公（一次性交付）均为任务而非情报。分类按盯梢对象四分：**企业**（corporate，盯一家公司的持续动态：舆情/竞品）/ **产业**（industry，盯一条赛道：产业舆情/产业事件/招商线索/**产业政策**）/ **区域**（region，V2 新增值，盯一个地区/园区：区域招商/人才/扶持政策、园区动态、区域竞争——招商工作的核心对象，2026-10-23 补）/ **通用**（general，其他周期主题）。政策是内容主题非分类（产业政策盯赛道归产业、区域政策盯区域归区域）。category 列 TEXT 无枚举约束，加 region 为值域超集，零 DDL 零迁移，旧订阅零影响。

- 结构：页头（标题 + 「新建订阅」主钮——**新增订阅唯一入口**，任务级「设为定时」退役（§7））+ 子 Tab（**情报流** / **线索池** / **订阅管理**）。
- **情报流**：类别筛选 chips（`全部 / 企业 / 产业 / 区域 / 通用`，由订阅行 category **直读**，值域 `corporate/industry/region/general`，i18n）+ 跨订阅期次卡片流（排序 = **未读优先 ⇄ 最新** 切换、独立于类别筛选，未读优先组内 finished_at 倒序；`limit/offset/has_more/total` 分页 + 加载更多）。卡片：要点标题（`run.summary[0]`）+ 订阅名 + 类别 + 相对时间 + 状态点（running 呼吸 / failed 红）+ 未读点 + **产业类卡「提取线索」快捷钮**（直达阅读页并自动展开提取动线，§3.3）；done/failed 点击 → 阅读页；running → 订阅管理。
- **线索池**（V2 新增，§4.1）：线索卡片列表（状态分组：新线索 / 接触中 / 评估中 / 搁置；立项后置灰入「已立项」区可跳项目）+ 状态推进 + 备注；卡片动作：**立项**（`knowledge:createProject` 创建项目并回填来源）、**升级为订阅**（以盯梢模板组装 prompt → 现有 `schedules:create`，零新通道）；入口动线：期次卡 / 阅读页「存为线索」+ 手动录入。
- **订阅管理**：现 `SubscriptionAdminView` 整体迁入（订阅列表 / 新建编辑模态 / 运行历史 / 归档重建 / 熔断态），**组件级复用非重写**。新建向导第①步模板列表 = **情报白名单**（任务侧反向分家，零重叠）：内置 7 条：企业舆情扫描、竞品动态（→企业）、**产业舆情扫描**（→产业，2026-10-24 新增——盯一条赛道：行业要闻/重点企业动态/风险信号）、产业投资事件、招商线索扫描、**产业政策扫描**（占位符 `{产业}`，→产业，2026-10-23 新增）、**区域招商政策扫描**（占位符 `{区域}`，→区域，2026-10-23 新增），选中即自动填充分类无需手选；列表项 = 图标 + 标题 + 一句话描述，选中内置模板即展示「你将获得」产出结构要点（2026-10-24 直观化，自定义模板无此键跳过）；基础信息/深度摸底/尽调/商业模式/文件整理/数据汇总 6 条内置模板为纯任务模板、只出现在任务欢迎页（§3.6）；自定义模板两边都放、订阅侧按 category 映射带分类（info/mon→corporate、ind→industry、reg→region、rep/off→general）；自由输入手选四分类（管理台页签「全部/产业/企业/区域/通用」加区域项，与情报流 chips 同词汇）。一次性盯梢需求 = 建订阅 + 立即执行（run-now），不再有任务侧捷径——同模板双路径产出契约不一致（OUTPUT_CONTRACT 仅订阅创建拼接）随分家消解。
- 徽章：`schedules:summary.total` 未读数（挂载 + 终态边沿，零新增轮询）。

### 3.3 情报阅读页（ReadView 增强）

保留全部现状能力（摘要卡 / Markdown 全文含来源节 / Ctrl+F 块级查找 / 执行过程回放 / 订阅设置 / 沉淀跳转 / 失败重跑），新增（**操作全量开放，分类只驱动突出度**，§6.3-12）：

- **「转跟进任务」按钮**（头部动作条）：

### 3.9 免培训原则（用户语言 + 决策点信息充分性，2026-10-23 定稿；2026-10-24 增补维度②）

全局要求：**免培训、自然上手**，两维度同权重：
1. **用户语言**：用户可见文案一律用户语言，工程词不出现在 UI——工程概念（编译/Lint/Schema/熔断/page_type 等）只存在于组件名/通道名/表列名/内部文档；知识册是重灾区（工程词密度最高），翻译表定稿：
2. **决策点信息充分性（2026-10-24 增补，实证 = 订阅模板弹窗事件）**：用户在任何决策点（选模板/选操作/填占位符/确认弹层）必须无需培训或试错即可理解「选的是什么、会发生什么、会得到什么」——系统内已有的解释性信息（desc/示例/产出结构）必须在决策点消费呈现，禁止「数据存在、UI 不展示」；凡「选择后生成内容」的入口（模板/骨架/预设），选中态须展示产出结构要点（落地：ScheduleFormModal 列表项 = 图标+标题+desc、选中内置模板展示「你将获得」清单，2026-10-24）；占位符/空态示例文案承担解释职责，不得留裸变量名。开发侧硬性检查见 coding-habits §2.10、review 第 6 维度。
> 维度②缘起：订阅模板 desc 早已在 i18n、产出结构完整写在 prompt 内，新建订阅弹窗却只渲染名称——用户只能试错一期才知道「会得到什么」；随本次直观化修正并沉淀为规范。

## 4. 表结构（三要素①）

### 4.1 新增表 `leads`（线索池，V2 唯一新表）

定位：情报（发现）与项目（落地）之间的**蓄水池**；刻意薄卡，不做 CRM。存量数据零负担（新表启动幂等建表，无迁移；建表失败向上抛阻断启动，对齐 `db/database.py` 惯例）。

```sql
CREATE TABLE IF NOT EXISTS leads (
    id          TEXT PRIMARY KEY,               -- 'lead_<uuid>'
    name        TEXT NOT NULL,                  -- 企业/项目名称
    source_type TEXT NOT NULL DEFAULT 'manual', -- 'run' | 'manual'
    source_run_id  TEXT,                        -- 来源期次（溯源；期次删除置 NULL）
    source_schedule_name TEXT DEFAULT '',       -- 来源订阅名快照（期次删除后仍可读）
    status      TEXT NOT NULL DEFAULT 'new',    -- new/contacting/evaluating/hold/converted
    note        TEXT DEFAULT '',                -- 备注/下一步
    project_id  TEXT,                           -- 立项后指向项目（converted 必填）
    created_at  TEXT NOT NULL,
    updated_at  TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_leads_status ON leads(status, updated_at);
```

读写行为：状态推进 / 备注编辑 = 单行 PATCH；**立项** = `knowledge:createProject` 成功后回填 `project_id` + `status='converted'`（项目创建失败不推进，可重试）。引用清理三链（外键手动等价 SET NULL，线索行与状态保留）：期次/订阅删除置 `source_run_id` = NULL（订阅名快照兜底可读溯源，`detach_leads_for_run/for_schedule`）；项目删除置 `project_id` = NULL（converted 保留，前端 project_id 空即不渲染「查看项目」，`detach_leads_for_project`，2026-10-24 CodeReview 补）。

### 6.3 关键交互规则与不变量

1. 打开期次即已读（现状规则 10 保留，仅 done 态）。
2. 转跟进任务：创建失败 toast 留原页；成功跳任务页并预填、**不自动发送**（模板=半成品原则）。
3. 情报流排序独立于筛选（2026-10-23 定案）：默认「未读优先」（未读在前、组内 finished_at 倒序），可切「最新」（finished_at 倒序）；类别 chips 只过滤不改排序；分页契约 `limit/offset/has_more/total`（[0.1](0.1dev-guide.md) §16）。
4. 项目四 Tab 顺序不变量：事务恒第一；产出含「报告/填表」两分区，PPT 留报告分区。
5. 目录「跟踪」组以 `is_ledger` 为唯一判定（3.1 §3.4 同源）；分组只改呈现不改 page_type 语义。
6. 整理层四面板为现组件收纳，逻辑不重写；`wikiFocus`（lint/compile）直达路由不回归。
7. 全部新文案双语 i18n；0.3 token 体系沿用；**零新增轮询**（徽章=挂载+终态边沿，同 IntelDigest 现模式）。
8. 线索池薄卡不变量：只有名称/来源/状态/备注/立项指向，禁止长出联系人、商机组、金额阶段等 CRM 器官；溯源靠 `source_run_id` + 订阅名快照，期次删除不悬空。
9. 组合泳道纯派生不变量：泳道数据 = projects/dueData/healthByProject 现有快照重组，零新请求、零新状态字段；阶段列序 = STAGE_COLUMNS 通用看板列（前期/中期/后期/其他），混型同列、卡上 chip 区分类型（与 §3.7 同口径）。
10. 转任务、存为线索、提取候选都不自动补完语义（线索名可改、任务 prompt 不自动发送、提取候选必须勾选确认零自动入池）——系统只搬运，用户做判断。
11. 视觉语言升级（§3.0 六原则 + §3.1 首页落点）只动呈现层（样式与展示结构），不改数据流、通道与文案语义；保留区（进行中/今日待办/日历/组合墙）结构不变、视觉去框化；「与现状逐字一致」约束由 2026-10-23 用户裁决推翻——例外仅英雄区与情报区排版（§3.1 布局决议二次修订），其余区块验收基准仍为现状组件源码的结构与数据。
12. 操作全量开放不变量：沉淀（档案）/ 提取线索 / 转跟进任务对所有期次可用；分类（企业/产业/区域/通用）只驱动入口突出度（产业类卡直达提取 + 阅读页主位）与情报流筛选，不裁剪操作集——分类标错不断动线（企业舆情里发现园区招商信号同样可提取）。
13. 执行时间基准不变量：订阅执行 prompt 必含本期执行时刻/期数/上期时刻与「仅报新增、历史标注原日期」约束（执行侧每期拼接不存库，时间基准逐期变化，与「存最终 prompt」原则不冲突——OUTPUT_CONTRACT 是静态契约才存库）。
14. 用户语言不变量（§3.9 免培训原则）：用户可见文案（按钮/空态/toast/标签/分组名）一律用户词，工程词（编译/Lint/Schema/熔断/page_type 等）只存在于组件名/通道名/表列名/内部文档；各 E 期 i18n 实施按 §3.9 翻译表审查。
