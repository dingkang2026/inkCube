> 墨方 InkCube V2 版 UI/UX 总设计。信息架构按「招商/投资经理的四份工作」重新摆盘：情报升一级导航、项目页四 Tab、知识册阅读优先、产出合并。「不新增功能」限制已解除（用户拍板 2026-10-23），V2 新增两个器官——**线索池**（焊住「找→跟」漏斗断点）与**组合泳道**（纯前端快赢）；聚合简报 / 知识册导出列 V2.1 候选。
> 状态标注：**现状** = 代码实际行为；**目标** = 本文设计。未标注者为通用设计约束。

## 1. 产品定位与四支柱

### 1.1 客户工作模型（设计依据）

两类客户日常工作同构（工作全景表见 2026-10-23 设计评审记录），每份工作都有明确承载面：

| 招商经理 | 投资经理 | 本质（支柱） | V2 承载 |
|---|---|---|---|
| 扒线索 / 盯竞品园区 | 扫赛道 / 盯竞品基金 | ① 情报（撒网+盯梢） | 情报中心（一级导航：订阅管理 / 线索池，2026-10-25 两 Tab 收敛）+ 首页情报卡片区 |
| 推项目节点 / 盯已落地企业 | 推进尽调交割 / 盯条款投后 | ② 项目生命周期 | 项目·事务 Tab + 脉搏带 + 首页投资组合卡片墙 / 泳道 |
| 摸底尽调 / 读月报对数 | 尽调比对 / 读被投企业月报 | ③ 知识册（去伪存真、可阅读） | 项目·知识 Tab（阅读优先重构） |
| 周报月报 / 填系统表 / 汇报 PPT | 投决材料 / LP 季报 / 董事会 PPT | ④ 产出效率 | 项目·产出 Tab（报告+填表+PPT）+ 任务模板 |

价值链：**找（情报）→ 跟（生命周期）→ 懂（知识册）→ 交（产出）**，一切围绕项目展开：
情报是项目的输入，知识册是项目的记忆，交付物是项目的输出，生命周期是主线。

### 1.2 情报中心与任务的关系（关键澄清）

一句话：**任务是「派活」，情报是「委托」；订阅 = 任务 × 周期节奏，情报中心 = 订阅产出的阅读与管理面。**

| 关系 | 内容 | 状态 |
|---|---|---|
| 生产（任务→情报） | 每条期次 = 一次后台任务的产出（影子任务）；订阅 = 模板 prompt + 周期 + 去向；期次「执行过程」回放 = 任务工作区 | 已有 |
| 孵化（模板→订阅） | 订阅创建向导第①步模板列表 = **情报白名单**（§3.2）：内置 7 条（舆情/企业动态→企业、产业舆情/产业事件/招商线索/产业政策→产业、区域招商政策→区域），选中自动映射分类 | 白名单为 V2 决议（2026-10-23；产业舆情 2026-10-24 增补；竞品动态 2026-10-25 去预设更名「企业动态跟踪」）；任务级「设为定时」退役（§7）——情报与任务的分界 = **周期性盯梢**（基础/摸底/报告/办公是一次性任务，非情报） |
| 消费（情报→任务） | 期次产物自动沉淀绑定项目（线索「转跟进任务」2026-10-25 退役——行动出口收敛为线索链与订阅，§3.3/§7） | 沉淀已有；转任务删除链同变更清理 |
| 沉淀（期次→线索） | 期次「提取线索」唯一入口（AI 候选提取 + 勾选入池，人确认；「存为线索」2026-10-25 退役，§3.3）；线索「立项」= AI 按项目五字段从来源报告重新提取预填（人确认/修改）；线索「升级为订阅」转长期跟踪 | V2 新增（线索池，§4.1）；AI 预填人工确认为 2026-10-25 修订（§6.3-15 智能体优先） |
| 边界 | 情报中心不做任务管理（运行看板在任务 Tab/首页进行中区）；任务页不做期次阅读；线索池刻意保持薄卡（不做 CRM：无联系人/商机组）；两个 Tab 共享同一执行引擎、模板库、活动中心 | 设计约束 |

心智：同一台引擎，手动挡（任务）与自动挡（情报）两个驾驶舱。

## 3. 分面重设计（现状 → 目标）

### 3.0 V2 视觉语言（全局，2026-10-23：从「工程仪表盘」到「高级晨报」）

用户裁决：现状整体「太工程化」——等权重卡片阵列 + 框线分区 + BI 数字卡是病根，**不止首页，是全应用**。V2 全局升级设计语言，六原则：

| # | 原则 | 规格 |
|---|---|---|
| 1 | 焦点优先 | 每页一个视觉英雄：首页=晨会英雄区（大字日期问候 + 晨报句 + 行内 KPI，§3.1①）；情报中心=大标题页头；项目页=脉搏带升格排版 |
| 2 | 去框化 | 卡片去边框，改极浅底色差 + 柔和投影悬浮面；区块间 24px 留白 + 8% 透明度 1px 分隔线；禁止等距框线网格 |
| 3 | 编辑排版 | 列表类内容「1 大 + N 小」层级化（最新/最重要占大卡带正文预览，其余紧凑行）；消灭等大卡阵列 |
| 4 | 排版层级拉开 | 字阶对比加大（display 28~32 / title 18 / body 14 / caption 12 + 大字距标签）；大数字展示级排版（tabular-nums） |
| 5 | 色彩纪律 | 中性色阶为底 + 单一品牌强调色（关键数字/主动作/进度条）；语义色只给状态（红失败/黄警告/绿成功）；无第三种杂色 |
| 6 | 克制微动效 | 入场淡入上移（120ms）、hover 统一抬升 2px、进度条渐变、未读点光晕；无装饰性动画 |

各页落点：首页 §3.1；情报中心 §3.2；项目页 §3.4-3.5；任务页 §3.6。token 具体值（阴影/色阶/字阶/动效时长）E1 实施时落 [0.3](0.3ux-design.md)。不变量：六原则只动呈现层（样式与展示结构），数据流/通道/文案语义零变化（§6.3 规则 11）。

**E1b 落地登记（2026-10-24）**：token 增量（`--text-display/--text-title/--tracking-label/--hairline/--motion-enter/--motion-base` + 全局 `@keyframes fade-up`）已落 global.css 并同步 0.3 §5（Token 表/卡片语言/区块标题/交互反馈规则改写，豁免表删统计大数字行、增身份层暗底叠加行）；**E1b 落地范围 = 首页全量样板间（§3.1 落点表）+ 身份层/首启向导**，存量其余页面去框化随各页 E 期改造套用（同「存量文档下次修订补齐」惯例）。

### 3.2 情报中心（新一级页）

**情报的定义与分类（2026-10-23 决议）**：情报 = 订阅周期性盯梢的产出——判定标准是**周期性**（订阅 = 任务 × 周期节奏，[2.11](2.11scheduled-task-design.md) 概念模型），不是内容对象；企业基础/深度摸底（查一次即完）、报告/办公（一次性交付）均为任务而非情报。分类按盯梢对象四分：**企业**（corporate，盯一家公司的持续动态：舆情/动态）/ **产业**（industry，盯一条赛道：产业舆情/产业事件/招商线索/**产业政策**）/ **区域**（region，V2 新增值，盯一个地区/园区：区域招商/人才/扶持政策、园区动态、区域竞争——招商工作的核心对象，2026-10-23 补）/ **通用**（general，其他周期主题）。政策是内容主题非分类（产业政策盯赛道归产业、区域政策盯区域归区域）。category 列 TEXT 无枚举约束，加 region 为值域超集，零 DDL 零迁移，旧订阅零影响。

- 结构：页头（标题；原「新建订阅」页头主钮随两 Tab 收敛退役——新建入口回归管理台左列「＋新建订阅 / ＋新建聚合简报」双钮，任务级「设为定时」退役（§7）不变）+ 子 Tab（**订阅管理**（默认）/ **线索池**；原「情报流」Tab 2026-10-25 退役，§7）。
- **情报流 → 退役（2026-10-25 两 Tab 收敛）**：inbox 卡片流与订阅管理右列收件箱同接 `schedules:inbox`、数据同源双呈现属未收敛残影；能力全部迁入**收件箱**（订阅管理右列默认视图）：排序切换（**未读优先 ⇄ 最新**，`intel.sort.*`，独立于筛选）+ 左列分类页签联动过滤（`category` 直读，同订阅列表参数）+ `limit/offset/has_more/total` 分页 + schedule 活动终态边沿重拉（§6.3-3）；**产业类卡「提取线索」快捷钮随退**（线索唯一入口 = 阅读页头部按钮，§3.3）；组件/样式/测试全链删除见 §7。
- **线索池**（V2 新增，§4.1）：线索卡片列表（状态分组：新线索 / 接触中 / 评估中 / 搁置；立项后置灰入「已立项」区可跳项目）+ 状态推进 + 备注；卡片动作：**立项**（`knowledge:createProject` 创建项目并回填来源；可选勾选同时创建盯梢订阅，§3.3）、**升级为订阅**（App 级新建订阅弹层模板化预填：预选「企业动态跟踪」模板 + {企业名} 占位符预填线索名，落模板页签产出要点自解释 → 现有 `schedules:create`，零新通道；2026-10-25 修订——原隐形模板串自由输入态退役，免培训 §3.9-②）；入口动线：阅读页「提取线索」勾选入池 + 手动录入（「存为线索」2026-10-25 退役，§3.3；原期次卡「提取线索」快捷钮随情报流退役，本日收口）。

### 3.3 情报阅读页（ReadView 增强）

保留全部现状能力（摘要卡 / Markdown 全文含来源节 / Ctrl+F 块级查找 / 执行过程回放 / 订阅设置 / 沉淀跳转 / 失败重跑），新增（**操作全量开放，分类只驱动突出度**，§6.3-12）：

- **「转跟进任务」退役（2026-10-25 用户裁决）**：行动出口收敛为线索链（提取→立项→项目过程）与订阅（升级订阅）；转任务与线索链职责重叠且预填半成品 prompt 让用户从零补话，违背「智能体优先」交互原则（§6.3-15）。删除链见 §7。
- **「存为线索」退役（2026-10-25 用户裁决，与提取线索合并）**：原零 AI 快捷存（要点首段塞线索名 + note 空串）存在 name 槽位信息错位（事件句占项目名候选位、信号摘要丢失）；AI 化补救后与「提取线索」只差单条/批量粒度，两入口同源不同粒度违背免培训原则（§3.9-②制造试错型决策点）。能力由「提取线索」全覆盖：单主体报告提取出 1 条勾选即存（仅多一次点击）。删除链见 §7；`leads:saveExtract` 端点不再建设。
- **「提取线索」按钮**（头部动作条，线索唯一入口——「存为线索」退役后单主体/多主体报告统一走本入口；产业类期次主位突出，其余类次位不隐藏）：LLM 读本期报告全文产出**候选清单**（线索名 + 信号摘要 + 原文依据）→ 用户**勾选** → 批量 `leads:create`（status=new、note=信号摘要、source_run_id=本期）→ toast「已入池 N 条」可跳线索池。**线索名定义收窄（2026-10-25）**：name = 企业名称或其规范简称（招商/投资对象本身）——园区、政策、事件、机会等抽象对象不占 name 槽位（可入 signal）。提取源零成本（报告本就是 OUTPUT_CONTRACT 结构化文本）；候选对 `source_run_id` 已入池条目标「已在池」，跨期同名软提示不硬拦（同企业新动态可能是新线索）；running 期次无报告不可提取。通道 `leads:extract`（run_id → 候选清单，同步 invoke + 按钮 loading，不进活动注册表）。
- **线索立项 = AI 按项目字段重新提取（2026-10-25 修订）**：立项模态扩五字段（名称/描述/类型三选/企业全称/信用代码，与项目标准创建表单对齐）；有 `source_run_id` 的线索打开模态即调 `leads:convertExtract`——AI 从来源报告按字段语义提取 `{name, description, companyName, creditCode, suggestedType}` 预填（零自动提交，人确认/修改）；无来源（manual）或提取失败 → 空白手填不阻断。根修参数错位（原 `onConvertProject(name, type)` 第二参错落 description 形参——类型被写进项目描述、type 恒 general，连带 playbook 铺种/基础库自动关联/Wiki 用途预填三联动全错）。`suggestedType` 预填类型三选。
- **立项模态增可选勾选「同时创建企业动态跟踪订阅」（2026-10-25）**：默认不勾——订阅为周期性持续消耗（每期一次 LLM 任务），不可静默代做；企业全称非空才可用（订阅需盯梢对象，空态 hint 解释禁用原因，免培训 §3.9-②）。勾选后建项目成功即静默 `schedules:create`（零新通道）：企业动态跟踪模板固化 prompt（{企业名}=企业全称，占位符名语言无关提取）、daily 09:00 可改、`target_type='project'` + 自动沉淀——期次产出汇入项目知识（「情报是项目的输入」价值链闭环）；失败仅提示不阻断（项目已建成，同 patchFailed 部分失败语义）。**设计裁决（2026-10-25 扩展）**：项目列表空白新建模态提供同款勾选（ProjectList，companyName 非空才可用，默认同样不勾——是否订阅交用户决策，系统不代做）；两条动线共享 `quickCreateTrackingSub` 实现（features/schedule/quickCreateSub.ts），payload 契约单一来源。

### 3.9 免培训原则（用户语言 + 决策点信息充分性，2026-10-23 定稿；2026-10-24 增补维度②）

全局要求：**免培训、自然上手**，两维度同权重：
1. **用户语言**：用户可见文案一律用户语言，工程词不出现在 UI——工程概念（编译/Lint/Schema/熔断/page_type 等）只存在于组件名/通道名/表列名/内部文档；知识册是重灾区（工程词密度最高），翻译表定稿：
2. **决策点信息充分性（2026-10-24 增补，实证 = 订阅模板弹窗事件）**：用户在任何决策点（选模板/选操作/填占位符/确认弹层）必须无需培训或试错即可理解「选的是什么、会发生什么、会得到什么」——系统内已有的解释性信息（desc/示例/产出结构）必须在决策点消费呈现，禁止「数据存在、UI 不展示」；凡「选择后生成内容」的入口（模板/骨架/预设），选中态须展示产出结构要点（落地：ScheduleFormModal 列表项 = 图标+标题+desc、选中内置模板展示「你将获得」清单，2026-10-24）；占位符/空态示例文案承担解释职责，不得留裸变量名。开发侧硬性检查见 coding-habits §2.10、review 第 6 维度。
> 维度②缘起：订阅模板 desc 早已在 i18n、产出结构完整写在 prompt 内，新建订阅弹窗却只渲染名称——用户只能试错一期才知道「会得到什么」；随本次直观化修正并沉淀为规范。

| 内部机制（保留） | UI 显示（用户词） | 隐喻一致性（一本书 + 幕后编辑部） |
|---|---|---|
| 编译 / compile | **汇编**（「汇编成册」按钮） | 编辑部把素材汇编成篇 |
| 健康检查 / Lint 治理工作台 | **知识体检** | 找出矛盾、缺口、待完善处 |
| 结构页 / Schema 管理 | **知识框架** | 书的骨架 |
| 待编译 | **待汇编** | |
| 结构完成度环 | **成册进度环** | 这本书写到几成 |
| 目录分组：跟踪/结构/实体/概念/主题/来源 | **跟踪台账 / 知识框架 / 企业实体 / 概念 / 主题 / 资料来源** | |

其余页面随各 E 期 i18n 审查同步执行，已知待翻词：订阅管理「熔断态」→「连续失败已自动暂停」、「归档重建」→「重建档案」；审查范围 = 用户可见字符串（按钮/空态/toast/标签/分组名），内部日志与文档术语不变。

## 4. 表结构（三要素①）

### 4.1 新增表 `leads`（线索池，V2 唯一新表）

定位：情报（发现）与项目（落地）之间的**蓄水池**；刻意薄卡，不做 CRM。存量数据零负担（新表启动幂等建表，无迁移；建表失败向上抛阻断启动，对齐 `db/database.py` 惯例）。

```sql
CREATE TABLE IF NOT EXISTS leads (
    id          TEXT PRIMARY KEY,               -- 'lead_<uuid>'
    name        TEXT NOT NULL,                  -- 企业/项目名称
    source_type TEXT NOT NULL DEFAULT 'manual', -- 'run' | 'manual'
    source_run_id  TEXT,                        -- 来源期次（溯源；期次删除置 NULL）
    source_schedule_name TEXT DEFAULT '',       -- 来源订阅名快照（期次删除后仍可读）
    status      TEXT NOT NULL DEFAULT 'new',    -- new/contacting/evaluating/hold/converted
    note        TEXT DEFAULT '',                -- 备注/下一步
    project_id  TEXT,                           -- 立项后指向项目（converted 必填）
    created_at  TEXT NOT NULL,
    updated_at  TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_leads_status ON leads(status, updated_at);
```

读写行为：状态推进 / 备注编辑 = 单行 PATCH；**立项** = `knowledge:createProject` 成功后回填 `project_id` + `status='converted'`（项目创建失败不推进，可重试）。引用清理三链（外键手动等价 SET NULL，线索行与状态保留）：期次/订阅删除置 `source_run_id` = NULL（订阅名快照兜底可读溯源，`detach_leads_for_run/for_schedule`）；项目删除置 `project_id` = NULL（converted 保留，前端 project_id 空即不渲染「查看项目」，`detach_leads_for_project`，2026-10-24 CodeReview 补）。

2. 转跟进任务：~~创建失败 toast 留原页；成功跳任务页并预填、不自动发送~~（**2026-10-25 退役**：出口收敛为线索链与订阅，删除链见 §7）。

11. 视觉语言升级（§3.0 六原则 + §3.1 首页落点）只动呈现层（样式与展示结构），不改数据流、通道与文案语义；保留区（进行中/今日待办/日历/组合墙）结构不变、视觉去框化；「与现状逐字一致」约束由 2026-10-23 用户裁决推翻——例外仅英雄区与情报区排版（§3.1 布局决议二次修订），其余区块验收基准仍为现状组件源码的结构与数据。
12. 操作全量开放不变量：沉淀（档案）/ 提取线索对所有期次可用（「存为线索」2026-10-25 退役，提取为线索唯一入口）；分类（企业/产业/区域/通用）只驱动入口突出度（阅读页主位）与收件箱筛选，不裁剪操作集——分类标错不断动线（企业舆情里发现园区招商信号同样可提取）。
13. 执行时间基准不变量：订阅执行 prompt 必含本期执行时刻/期数/上期时刻与「仅报新增、历史标注原日期」约束（执行侧每期拼接不存库，时间基准逐期变化，与「存最终 prompt」原则不冲突——OUTPUT_CONTRACT 是静态契约才存库）。
14. 用户语言不变量（§3.9 免培训原则）：用户可见文案（按钮/空态/toast/标签/分组名）一律用户词，工程词（编译/Lint/Schema/熔断/page_type 等）只存在于组件名/通道名/表列名/内部文档；各 E 期 i18n 实施按 §3.9 翻译表审查。
15. 智能体优先不变量（2026-10-25 用户裁决）：凡用户决策点涉及信息填写，尽量由 AI 基于系统内已有数据预提取/预填充，人的职责是确认/修改而非从零输入；人工输入仅作兑底（无数据来源可提取时，如手动录入）。实证：提取线索（AI 批量提取 + 勾选入池）、立项（来源报告五字段提取预填）、「存为线索」曾列实证后随退役移出（同日合并裁决）、产业画像（Wiki 编译后提取产业链/细分领域预填订阅 `{产业}`，头部可修正，2026-10-25 新增，链路见 [2.1 §4.5](2.1project-design.md)）。
16. **主从面板型列表 toggle 选中不变量（2026-10-25 用户裁决，全系统适用；2026-10-26 边界修订）**：主从面板（左列列表 + 右列详情，如订阅管理台）的列表行点击 = toggle 选中——首击选中出详情，再击同行取消选中收回默认视图；**列表默认不选中任何行**（详情区呈现默认态而非首行详情）。边界：仅适用有持久选中态的主从列表；**纯导航型点击不适用**（阅读页入口、首页卡片/待办行、通知行等点击 = 切换场景，无「取消选中」语义，行为保持现状）。侧栏主从列表同属本规范：项目列表（[0.5](0.5product-redesign.md) E1 T5 首落地，toggle → null + 显式取消守卫 `useExplicitDeselect` 防自动选中回顶）、任务列表（**2026-10-26 补齐**：点已选任务取消选中回「发送即建任务」欢迎态；任务无自动选中 effect，无需守卫位）。落地首例（本条款原生场景，管理台左列+右列详情形态）：SubscriptionAdminView 订阅行（取消选中 → 右列回收件箱）。
17. **期次三态抽屉不变量（2026-10-25 用户裁决，第二步）**：期次阅读/执行过程/档案统一以 App 级右侧遮罩抽屉承载（ScheduleDrawer），禁止回归整页 peer 替换——宿主页不卸载是「上下文保持」的产品承诺（管理台订阅选中、首页滚动位置在抽屉开关间不动，原 from/restoreScheduleId 恢复锚机制永久退役不得复活）；关闭三通道等价（头部返回钮/Esc/点遮罩），Esc 输入框聚焦豁免（FindBar 两段式关闭）；抽屉内 read↔replay 互切不关抽屉；全局导航动作（通知点击/跳容器/线索查看）同步关抽屉；首页与情报中心共用同一抽屉入口。
