# 纪要中心（Meeting Notes Hub）设计

> 项目内「拜访/会议记录」独立功能（2.13 纪要向导的承接形态）：纪要从素材面板迁出为项目详情页独立 Tab——待处理草稿区 + 已归档纪要时间线 + 新建入口；纪要与素材的关系从「保存即入库」改为「默认入库、可选不入库、事后可加入/移出」（对齐素材文件增删语义）。

## 1. 决策记录（2026-10-28 brainstorm 收敛）

| 议题 | 结论 | 否决的替代方案与理由 |
|---|---|---|
| 功能形态 | **独立「纪要」Tab**（项目详情页，与素材/事务并列） | 继续寄生素材面板：素材语义是「项目资料文档」，纪要是「经营活动记录」，混杂语义已在验收中反复暴露（草稿提示条占行、集中查看缺失） |
| 正文入库时机 | confirm 时**默认入库素材，可勾选退出**（NoteConfirm 新增 `save_to_materials: bool = True`） | 保存时一次性选定即终局（用户否决：「补救入口肯定是需要的，事后仍可以加到素材中去」） |
| 事后增删素材 | **纪要详情内 toggle**：加入（materialize）/移出（dematerialize），对齐现有素材更新/删除语义 | 无补救入口；单独重建上传链路 |
| confirm 终态 | 完整后**不删行，置 `archived`**（历史纪要回溯视角，正文留存于纪要行） | 维持删行（历史记录无处可查，已保存产物成了孤儿引用——用户提出「有没有可以集中查看会议纪要」即此缺口） |
| archived 行操作 | **可删 + 正文可编辑（偏差 7，2026-10-28 实测裁决）+ 其余只读** | 初版「完全只读」（改了失真）被实测推翻：正文事实源在行内 draft_md，编辑经内容比对同步素材（删旧传新），无双源不一致；输入字段与行动项仍不可改 |
| 删除纪要的范围 | **级联删行专属产物（偏差 9，2026-10-28 实测裁决推翻「仅删行」）**：素材 md（refs.file_id 完整级联）+ 现场图片（未被其他纪要行引用时一并删，共享图片保护）；**已建事务保留**（事务面板管理）；确认弹窗明示级联范围 | 初版「仅删行」被实测推翻：删除纪要应提醒将删除素材包括图片——产物遗留成无主孤儿违背生命周期闭环（§2.4 四问之「谁清理」）；事务是交付给事务面板的独立产物保留 |
| 行动项 | **逻辑不变**（勾选建 material 事务、saved_refs.task_ids 幂等） | — |
| 新建入口 | 从素材面板迁出（headerAction 槽删除，**死代码全链清理**） | 双入口并存：同一功能两个入口必然状态不同步 |

## 2. 表结构

`meeting_notes`（DDL 不变，见 [2.13 §2](2.13meeting-notes-design.md)）：

| 变更 | 内容 | 迁移 |
|---|---|---|
| `_MEETING_NOTE_STATUSES` | `("draft", "structuring", "structured", "archived")` 追加枚举值 | status 为 TEXT 列，**零 DDL 零数据迁移**；存量 confirm 已删行的历史纪要不回填（行已不存在，素材 md 与事务仍在各自面板，列表自上线起积累——预期行为） |
| `saved_refs` 语义 | `file_id` 新增合法值 `null`（= 正文未入素材；默认 true 时为 file_id 字符串） | 无列变更；存量行 file_id 均为字符串，天然兼容 |
| `list_meeting_notes_archived` | 新增 db 函数：`WHERE project_id=? AND status='archived' ORDER BY COALESCE(occurred_at, date(created_at)) DESC, rowid DESC`（拜访日期为业务主序） | — |

读写行为与生命周期闭环：

| 操作 | 行为 |
|---|---|
| 创建/编辑/结构化 | 不变（draft 流转，见 2.13 §2） |
| confirm 完整 | `status='archived'`（原为删行）；`save_to_materials=False` 时跳过 md 上传，`saved_refs.file_id` 保持 null |
| archived PATCH | **409 守卫**（新增：历史记录不可编辑；现有 update_note 无 status 守卫，draft/structuring/structured 维持可改） |
| archived DELETE | 级联删行专属产物（偏差 9）：refs.file_id 素材 md 完整级联 + image_file_ids 未被其他行引用的现场图片；已建事务保留；确认弹窗明示「素材文件与现场图片将一并删除（含检索索引），已建待办保留」 |
| 启动清扫 | `reset_interrupted_meeting_notes` 只动 structuring，不误伤 archived（现有 SQL 无需改） |
| 活动心跳 | `fetch_active` 只查 structuring，archived 不进活动（现有 SQL 无需改） |
| 项目级联 | `delete_meeting_notes_for_project` 现有级联覆盖 archived 行（按 project_id 删，无需改）；已入库素材文件走素材现有级联 |

## 3. 数据流

```
[Python FastAPI]  routers/meeting_notes.py（挂 /projects/{project_id}/notes）
  POST   /projects/{p}/notes                          创建草稿（不变）
  GET    /projects/{p}/notes                          未完成列表（不变，不含 archived）
  GET    /projects/{p}/notes/archived                 归档列表（新增，分页契约 limit/offset/has_more/total，limit=0 全量）
  PATCH  /projects/{p}/notes/{id}                     编辑输入（archived → 409 新守卫）
  PATCH  /projects/{p}/notes/{id}/content            正文保存（偏差 7 新增、偏差 9 放宽：structured 暂存 / archived 确认修改；内容比对删旧传新联动素材并回写 draft_md，未变幂等）
  DELETE /projects/{p}/notes/{id}                     删除纪要（偏差 9：任何状态；级联素材 md+未共享现场图片，事务保留；confirm 进行中 409）
  POST   /projects/{p}/notes/{id}/structure           发起结构化（不变）
  POST   /projects/{p}/notes/{id}/confirm             确认保存（变更：save_to_materials + archived 终态）
  POST   /projects/{p}/notes/{id}/materialize         正文补入素材（新增：复用 confirm 步骤 1 上传链，幂等——已有 file_id 直接返回）
  DELETE /projects/{p}/notes/{id}/material            移出素材（新增：cleanup_file_data 完整级联删文件 + saved_refs.file_id 置 null，幂等）
```

**confirm 变更**（`save_to_materials: bool = True`，其余分步幂等逻辑不变；步骤 1 经偏差 7 重构为内容比对语义、偏差 20 定稿为**同步目标态语义**，详见 [2.13 §3 步骤 2](2.13meeting-notes-design.md)）：`save_to_materials=True`（目标「在素材」）内容变删旧传新、file_id 缺失（上传失败后重试）补传；`=False`（目标「不在素材」）已入素材一律删旧置 null（内容未变也删）；载荷与行内不一致（正文或行动项）**回写 draft_md**。全同则整步跳过（重试幂等）
2. 步骤 2（逐建事务）不变
3. 步骤 3 判定不变（全部选中项 title 已记，含全不选合法态；幂等键 = 条目 title，详见 [2.13 偏差 21](2.13meeting-notes-design.md)）→ `update_meeting_note(note_id, {"status": "archived"})` 替代删行；返回体 `"archived": 实际状态`（偏差 21 修正原恒 True 契约污染）

**materialize 路径**：`GET owned` → status 必须 `archived`（409）→ `saved_refs.file_id` 已存在则幂等返回现有 file_id → 无则取 `draft_md.content_md` 写「纪要-YYYYMMDD-标题.md」复用 `_upload_core` 上传链（解析入队进 RAG，与 confirm 同款）→ `saved_refs` 落库 → 返回 `{file_id}`。`draft_md` 缺失 422。

**dematerialize 路径**：`GET owned` → `saved_refs.file_id` 为 null 幂等返回 ok → 有则 `cleanup_file_data(db, vs, fts, file_id, project_id, data_dir, remove_file_record=True)`（chunks/向量/FTS/Wiki 衍生/磁盘目录/DB file 行全清，单次调用完整级联，同素材删除链）→ `saved_refs.file_id` 置 null → 返回 `{ok: True}`。

**updateContent 路径**（偏差 7 新增、偏差 9 放宽）：`GET owned` → status ∈ {`structured`, `archived`}（其余 409；structured = 格式化态「暂存」：人工修改存回行内保持待确认，不入素材不建事务不归档，重试残留 file_id 行照常联动）→ content_md 空白 422 → confirm 共用占坑串行化 → 与行内 draft_md 正文比对：未变幂等返回 `{ok: true, file_id: 现值}`；已入素材删旧传新（同 confirm 步骤 1 语义）并回写 draft_md（行动项保留原 draft_md 的）→ 返回 `{ok: true, file_id}`。

**IPC 通道**（四新增，同变更内落地前端消费，§2.9）：`meetingNotes:listArchived` / `meetingNotes:materialize` / `meetingNotes:dematerialize` / `meetingNotes:updateContent`。

**活动语义**：四通道均为页面级明细查询/短操作，非「排队→执行→终态」长时活动，不进 Activity 注册表（§2.7）；materialize 触发的 md 解析走现有 files 活动心跳。
