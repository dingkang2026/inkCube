# PPT 生成与模板解析 · 云端 SaaS 方案（ppt-master）

> 状态：**讨论稿**（2026-10-27，与用户逐轮对齐后成文）。
> 定位声明：本文档描述一个**独立的云端 SaaS 产品**的架构方案，与 InkCube 桌面应用无直接关系；仅复用 InkCube 对 ppt-master（MIT, v4.8.0, Hugo He）的集成认知（实测契约见 [2.3.1](2.3.1ppt-master-integration-reference.md)）。
> 已对齐前提：① 部署形态为 SaaS 多租户；② 云端已有 agent skill 框架（队列 + 回合制执行 + awaiting_input 状态机已存在）；③ 隔离单元为 task_id；④ block 确认采用「回合终止 + 控制面门禁」模式（见 §5）。

## 1. 核心洞察与方案主线

**ppt-master 本身是云中立的**：它是「给 LLM 读的工作流说明书（markdown）+ 无状态确定性脚本库（svg_to_pptx 等约 5.6 万行）」，既不需要本地文件系统也不需要 GUI。桌面绑定点全部在承载层，云端逐项替换：

| 桌面绑定点 | 云端替换 | 性质 |
|---|---|---|
| 本地 workspace 文件树 | 对象存储 + worker ephemeral 盘快照同步 | 核心改造件（§4） |
| agent 经 shell 跑脚本 | 容器内原样保留，按不可信代码隔离 | 零改造 + 安全加固 |
| confirm_ui 起在 127.0.0.1 | 控制面移植 4 端点 + 官方静态 UI 托管 CDN | 核心改造件（§5） |
| mermaid 重绘依赖 headless Electron | 镜像内置 chromium 或独立渲染微服务 | 常规替换 |
| 本地 bge-m3 向量缩池 | embedding API / 托管向量库 | 常规替换 |
| SQLite + 目录式模板库 | Postgres + 对象存储（§6/§7） | 常规替换 |
| skill 随包分发 + seed 指纹拷贝 | 镜像/对象存储分发，**seed 机制整体消失** | 反而变简单 |
| 用户自带 API key（env 注入） | 平台 secret 管理注入，契约不变 | 常规替换 |

方案主线：**worker 容器内保留 agent + shell + ppt-master 脚本原样（skill 零修改、协议墙零触碰），外围（队列 / 状态 / 存储 / 门禁 / 模板库）云原生化**。不走「服务化拆分重写交互面」路线——那会使 ppt-master 脱离上游升级轨道，包内零修改策略作废。

## 2. 总体架构（四层）

```
┌─ 前端 ────────────────────────────────────────────────────┐
│ 任务向导 / 进度卡片 / 门禁页(官方 confirm_ui 托管 CDN)      │
└──────────────┬────────────────────────────────────────────┘
┌─ 控制面 ──────▼────────────────────────────────────────────┐
│ 任务 API · 状态机 · 租约管理 · 预算配额 · 门禁 API(移植4端点)│
│ 模板库服务 · 收录事务 · 进度事件汇聚 · 凭据注入              │
└──────┬─────────────────────────────────┬───────────────────┘
┌─ 数据面▼────────┐             ┌─ 存储层 ▼──────────────────┐
│ worker 池       │◀───队列─────│ 对象存储: tasks/{id}/workspace│
│ (每 task 一沙箱)│             │  tenants/{tid}/ppt-library   │
│ agent+shell+    │             │  skills/{name}/{ver}         │
│ ppt-master 脚本 │             │ Postgres: §7 全部表          │
└─────────────────┘             └─────────────────────────────┘
```

分工：**控制面管「状态与决策」，worker 管「跑 skill」，存储是两者唯一交接面**。控制面与 worker 之间无长连接耦合，全部经队列 + 对象存储交接。

## 3. 任务模型与回合编排

### 3.1 任务类型（对齐 ppt-master 三路由）

| 类型 | 输入 | 输出 | 门禁 |
|---|---|---|---|
| `ppt.generate` | 内容源（md/自由主题）+ 图片集 + 模板引用（可选，kind:id 串）+ 风格意向 + 备注 | PPTX + 页面 SVG 预览 | Stage 1 + Stage 2（原生页） |
| `ppt.template.create` | 模板类型四选一（brand/style/layout/deck）+ 参考素材 | 模板包 → 晋升租户库（§6） | brief 确认（通用卡片） |
| `ppt.enhance` | 源 PPTX + 增强范围（notes/audio/timings/transitions） | enhanced PPTX | 计划确认 + 音频配置（通用卡片） |

隔离：task_id 贯穿五层——沙箱只挂本任务 workspace、对象存储前缀 `tasks/{task_id}/`、任务级 IAM 临时凭证、门禁页按 task 寻址、全部表带 task_id 外键。

### 3.2 generate 回合序列

```
回合1(intake)    project init → import-sources(报告 md + 图片 + 模板包拉取)
                 → icon_sync → 写 template_options + recommendations.stage1
                 → 结束回合 → awaiting_input(stage1)，worker 销毁
  ⬇ [用户在门禁页提交 Stage 1 → 控制面校验写回执 → 重新入队]
回合2(装模板)    读回执 → svg_quality_checker 模板校验 → 安装模板
                 → --complete-template-selection（写 handoff）
                 → 写 recommendations.stage2 → 结束 → awaiting_input(stage2)
  ⬇ [用户提交 Stage 2 → 重新入队]
回合3(authoring) 读回执 → design_spec/spec_lock → 逐页 SVG
                 （单 worker 会话连跑多轮：页级快照 + 心跳 + 预算检查）
                 → total_md_split → finalize_svg → 质检门
                 → svg_to_pptx → 交付检查 → completed，产物入对象存储
```

- template.create / enhance 同模型，回合数更少（brief 确认门 / 两处确认门由控制面按产物文件状态机判定）。
- **agent 全程不感知云环境**：它看到的仍是本地盘 + shell + 文件；快照同步对它透明，skill 零修改。

### 3.3 worker 生命周期与租约

- **worker 生命周期 = 回合**：门禁期零资源占用（这是云上对桌面版最大的成本优化）。
- 领任务获**租约（lease）**，心跳续租；租约过期控制面回收重投。重投的新 worker 从「任务状态 + workspace 快照 + ppt-master 自带 design_spec/spec_lock 恢复锚」续跑——ppt-master 的恢复锚设计与回合制天然同构。
- authoring 长会话（40 分钟级）内：每页完成推增量快照，崩溃损失 ≤ 1 页。
- 预算软着陆：per-task 预算剩 `max(3, max_iter//10)` 轮时注入收束提醒（保存半成品进 workspace），耗尽 → paused；SaaS 语义下 paused 是 upsell 点（用户加预算续跑触发计费），不是终点。

### 3.4 上下文有效性边界（skill 原生防漂移，平台零干预）

ppt-master `executor-base.md` §2.1 以三态判定执行上下文：**Valid**（完整 design_spec + spec_lock 在未压缩活跃上下文 → 每页复用不重读）/ **Invalid**（全新、恢复、重启、压缩摘要式恢复 → 完整重读 design_spec.md → spec_lock.md + 触发引用，deck 中途恢复另读最新完成 SVG 与图片元数据）/ **Uncertain**（先查 retained lock 再读 spec 片段，冲突时 Design Spec 为上游权威）。配套**五页轻量锁重读**（仅 Default Generate）：完成 P05、P10、P15… 且仍有后续页时，下一页前完整读一次 spec_lock.md——纯上下文再锚定，防长上下文下的规格漂移。

对云端的含义：

- **回合接棒 = Invalid 态**：worker 销毁-重生后的接棒语义由工作流原文规定（完整重读后从最后完好产物续跑），平台零额外设计——§3.3「恢复锚设计与回合制天然同构」的具体出处即此；
- **五页重读发生在 worker 会话内**：回合 3 单会话连跑，重读自然发生，平台零干预；
- **架构红线——禁止上下文保温**：平台不得为省 token / 加速恢复而跨回合缓存复用 LLM 会话历史（让新 worker「继承」旧上下文）。上下文是否 Valid 的判定权在工作流；平台保温 = 让 skill 误判 Valid 跳过完整重读 = 平台侧绕穿其防漂移设计。恢复必须 = 「新鲜/摘要上下文 + Invalid 完整重读」，慢是正确性代价。

## 4. workspace 快照协议（技术核心件）

| 时点 | 动作 |
|---|---|
| worker 启动 | ① 拉任务 workspace → ephemeral 盘；② 按 task 锁定版本拉 skill 包解压到只读路径（`attribution_guard` 哈希校验照常执行）；③ 拉任务引用的模板包物化到 `/workspace/templates/<kind>/<id>/` |
| authoring 中 | 每页完成推增量（`svg_output/page_NN.svg`） |
| 回合结束 | 全量推送 + manifest（文件清单 + hash + **sequence**）→ 释放租约 |

- 体积评估：12 页 deck + 高清图约几百 MB；增量同步 + 压缩可控；对象存储生命周期策略（终态任务 30 天转冷存，见 §12）。
- 凭据注入：控制面从 secret 管理注入任务环境变量（`IMAGE_BACKEND`、`OPENAI_BASE_URL`、TTS key 等）——与桌面版「进程 env 优先级最高」契约一致，skill 零感知。

## 5. block 确认（门禁）机制

「block 确认」拆三层，各自解法：

| 层 | 问题 | 解法 |
|---|---|---|
| 进程层 | agent 执行到决策点要不要阻塞等待 | **永不阻塞**：写完门禁请求 JSON → 结束回合。官方 `--wait-only`（590s 预算）直接禁用 |
| 状态机层 | 怎么记「等输入」、怎么醒 | 框架已有：awaiting_input + 应答注入 resume；唤醒 = 控制面写回执 → 重新入队 → 新 worker 接棒 |
| UI 层 | 用户在哪里确认、重表单怎么承载 | 见下 |

### 5.1 UI 分流

| 门禁 | 形态 | 承载 |
|---|---|---|
| Generate Stage 1 / Stage 2 | 重表单（7 prose 字段 + 六角色色板 + 字体 + 3 个可编辑 design_directions + image_usage 多选） | **官方 confirm_ui 前端原样托管 CDN**（只改 base URL），不重造 UI |
| Create Template brief 确认 | 自然语言逐句修正 | 框架通用 awaiting_input 卡片 |
| Enhance 计划 + 音频配置 | 字段少（模块开关/音色候选/语速） | 同上通用卡片 |

### 5.2 server 移植（唯一有实质工程量的点）

confirm_ui 的 Flask server 与 agent 之间**零 API 耦合，全部经 workspace 内 JSON 五件套交接**；server 本身无业务逻辑，只做「读（候选目录构建）+ 校验（sha256 链）+ 写（回执）」三件事。因此：

- **4 个端点在控制面等价实现**：`GET /api/session`、`GET /api/recommendations`、`POST /api/confirm`、`GET /api/catalogs`；数据层从沙箱本地文件换成对象存储 `tasks/{task_id}/confirm_ui/*.json`。
- agent 行为零变化：照旧写本地 `confirm_ui/`、照旧跑 `--complete-template-selection` / `--reset-template-selection` CLI（都在沙箱本地盘，随快照同步）。
- **sequence 替换 mtime（唯一语义改动点）**：官方 progression guard 靠文件时间戳先后（handoff 新于 stage1 selection、stage2 新于 handoff）；云上对象存储 mtime 不可靠 → 控制面维护任务级单调 `sequence`（任务表字段，每次回合快照登记或控制面写入时递增），guard 改为 sequence 数值比较。回合制下事件顺序天然满足 guard 语义。
- sha256 校验链（`options_sha256` / `selection_sha256` 绑定）原样移植，防篡改不变。
- 鉴权：网关层 JWT + 任务归属校验（官方页面无鉴权逻辑，localhost 信任边界 → 云上由网关承担）；页面 URL `/t/{task_id}/gate`。
- 门禁无超时（用户可一周后回来）；另设**运营性过期**（如 14 天 → expired + 通知），是运营策略非技术约束。
- 候选目录构建需读 skill 包内四索引（brands/styles/layouts/decks）：skill 发布时提取索引存库或控制面从 skill 仓库按版本读取，随版本缓存。

### 5.3 一次完整门禁时序

```
回合N 结束 → 推快照(seq=1: stage1 rec) → awaiting_input → worker 销毁
用户打开 /t/{id}/gate → 页面轮询 session → 渲染 Stage 1 → 提交
控制面校验 sha256 链 → 写 result.json + template_selection.json(seq=2) → 重新入队
回合N+1 worker → agent 读回执装模板 → handoff(seq=3) → stage2 rec(seq=4) → 结束
页面轮询到 stage2 可提交（3s 级，体感同本地）→ 填写提交(seq=5) → authoring 续跑
```

页面全程只打控制面，不占 worker 资源；同租户多任务并发 awaiting_input 按任务隔离，控制面提供「待你确认」聚合清单。

## 6. 模板库与收录

**双域**：

- 平台内置库：skill 包内模板（brand 21 / style 12 / layout 7 / deck 2 + 12 内置 style），只读，随 skill 版本走；
- 租户库：包文件 `tenants/{tid}/ppt-library/templates/{kind}/{id}/`，元数据落 Postgres（`template_packages` 表，§7）。

**收录 = 控制面事务**（替代桌面版文件系统 rename 原子性）：

```
worker 产出模板包(tasks/{task_id}/output/package/)
→ 控制面校验：spec 限定名 + 结构完整（结构型 Layout/Deck 须有 SVG 页面原型）
→ 通过：拷入租户库前缀 + 落行，一个事务提交（替代 .collecting/ 暂存切名）
→ 失败：任务 failed 带原因；提供幂等「重试收录」（纯 IO，不跑 agent 不耗模型）
```

**模板引用**：创建 generate 任务选模板（kind:id 串）→ 控制面校验存在性（同 kind 重复/不存在即 400）→ worker 启动物化模板包进沙箱 → 首条消息写 explicit root（`explicit_workspace_roots` 契约，含路径穿越终检）。

## 7. 表结构（Postgres）

```sql
-- 任务登记簿：执行态权威（云上 worker 无本地 DB，状态全部落此表）
CREATE TABLE ppt_tasks (
    id TEXT PRIMARY KEY,                   -- task_id，全链路隔离主键
    tenant_id TEXT NOT NULL,
    type TEXT NOT NULL,                    -- ppt.generate / ppt.template.create / ppt.enhance
    status TEXT NOT NULL DEFAULT 'queued',
        -- queued / running / awaiting_input / paused / completed / failed / cancelled / expired
    gate_stage TEXT,                       -- awaiting_input 时非空：stage1/stage2/brief/plan/audio
    skill_name TEXT NOT NULL DEFAULT 'ppt-master',
    skill_version TEXT NOT NULL,           -- 创建时锁定，升级只影响新任务
    title TEXT NOT NULL,
    input_json TEXT NOT NULL,              -- 内容源/模板引用/图片选择/风格/备注等结构化输入
    budget_json TEXT,                      -- {token_limit, wall_clock_limit, spent_tokens, ...}
    sequence INTEGER NOT NULL DEFAULT 0,   -- confirm_ui 五件套全局单调序号（§5.2）
    workspace_prefix TEXT NOT NULL,        -- tasks/{id}/workspace/
    output_json TEXT,                      -- 终态产物指针（exports 相对路径等）
    error TEXT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_tasks_tenant ON ppt_tasks(tenant_id, created_at DESC);
CREATE INDEX idx_tasks_active ON ppt_tasks(tenant_id) WHERE status IN
    ('queued','running','awaiting_input');

-- 模板包登记（双域：内置行 tenant_id='__platform__'，包文件在对象存储）
CREATE TABLE template_packages (
    id TEXT PRIMARY KEY,
    tenant_id TEXT NOT NULL,
    kind TEXT NOT NULL,                    -- brand / style / layout / deck
    name TEXT NOT NULL,
    source_task_id TEXT,                   -- 模板工坊来源任务（内置为 NULL）
    storage_prefix TEXT NOT NULL,          -- 库内包根前缀
    summary TEXT, canvas TEXT,
    colors_json TEXT, keywords_json TEXT, page_types_json TEXT,
    status TEXT NOT NULL DEFAULT 'active', -- active / deleted
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (tenant_id, kind, name)
);

-- 进度事件流（append-only；任务表冗余最新值供列表直读）
CREATE TABLE task_progress_events (
    id BIGSERIAL PRIMARY KEY,
    task_id TEXT NOT NULL,
    stage TEXT,                            -- intake/strategy/authoring/export
    page_done INTEGER, page_count INTEGER,
    gate_stage TEXT, message TEXT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_progress_task ON task_progress_events(task_id, id DESC);
```

读写行为：

| 表 | 写入者 | 时机 |
|---|---|---|
| ppt_tasks | 控制面 | 创建 / 回合状态回写（worker 经回调 API 上报，控制面持租约校验后落库）/ 门禁回执 / 预算扣减 |
| template_packages | 控制面 | 收录事务 / 删除（软删） |
| task_progress_events | worker 经控制面回调 | 页级推进 / 阶段推进 / 门禁置位 |

**生命周期闭环**（谁创建、谁清理、何时清理）：workspace 快照与产物由任务创建、终态 30 天转冷存 + 租户显式删除级联清；模板包由收录事务创建、租户删除软删（前缀异步物理清理）；进度事件随任务删除级联清；expired 终态由运营过期任务（14 天）写入。

## 8. 数据流（端到端路径）

```
创建:  前端 POST /api/ppt-tasks ──▶ 控制面校验(标题/模板引用/配额)
       ──▶ 锁 skill 版本 + 建前缀 + 落行 ──▶ 入队
执行:  队列 ──▶ worker 领任务(租约) ──▶ 拉快照/skill/模板包
       ──▶ agent 回合(shell 跑 skill 脚本) ──▶ 推快照+状态回调 ──▶ 退出/续回合
门禁:  前端 GET /t/{task_id}/gate/api/* ──▶ 控制面(读对象存储五件套,sequence 判定)
       ──▶ POST confirm 校验 sha256 链 ──▶ 写回执(sequence+1) ──▶ 重新入队
进度:  worker ──回调──▶ 控制面(落 progress 表+更新任务行) ──▶ 前端(SSE/轮询)
收录:  worker 产出 package ──▶ 控制面校验 ──▶ 事务(拷前缀+落 template_packages)
产物:  下载 GET /api/tasks/{id}/artifact ──▶ 控制面签发对象存储临时 URL
```

## 9. 前端交互

### 9.1 消费组件清单

| 组件 | 数据 | 呈现 |
|---|---|---|
| 任务列表卡片 | 任务列表（分页）+ 进度 SSE/轮询 | 状态徽标 / 进度条 / 「第 N/M 页」/ 待确认红点 |
| 创建向导 | 内容源选择 + 图片集 + 模板选择器（双域：内置带徽标 + 租户库）+ 风格/备注 | 分步表单；模板选中态展示摘要/主色/关键词（免培训：决策点呈现既有解释信息） |
| 任务详情 | 任务详情 + 进度事件流 + 页面 SVG（对象存储临时 URL 逐页拉取） | 阶段进度 + 页预览网格 + 时间线 + 门禁摘要条（打开确认页按钮）+ 产物下载 |
| 门禁页（Generate） | 4 个移植端点 | **官方 confirm_ui 页面原样渲染**（CDN 加载，iframe/同域挂载），sha256 链与 Stage1→Stage2 轮询全部复用官方实现 |
| 确认卡片（Template/Enhance） | awaiting_input 载荷 | 结构化轻表单：确认 / 填写修改意见 / 重做 |
| 模板管理页 | template_packages 列表 + 详情 + 任务卡 | 四类分组双域列表（内置徽标 / 租户可删）+ 详情（摘要/主色/页面原型网格/包内清单/Review PPTX 下载）+ 收录失败重试 |

### 9.2 状态-界面映射

| status | 界面 |
|---|---|
| queued | 卡片「排队中」 |
| running | 进度条 + 阶段标签 + 页计数 |
| awaiting_input | 卡片高亮「待你确认」+ 详情/通知中心入口（Generate=打开确认页；其余=确认卡片） |
| paused | 「已暂停」+ 继续按钮（含加预算续跑，商业化入口） |
| completed | 封面 + 下载 PPTX + 页预览 + 「发起增强」（deck 类型） |
| failed | 错误摘要 + 重试（续跑从 DB 历史 + 快照重建）；模板任务另有幂等重试收录 |
| cancelled / expired | 终态展示，expired 附过期说明 |

### 9.3 关键交互规则与不变量

- 门禁页只能操作归属自己的任务（JWT + 归属校验在网关，页面不感知）。
- 同一租户同一源 PPTX 同时只允许一个进行中 enhance（控制面唯一性校验，409 拒绝）。
- 门禁无超时；awaiting_input 不计入任何预算墙钟。
- 内置模板不可删（平台域只读）；租户模板删除为软删 + 异步物理清理。
- 列表一律分页契约（limit/offset/has_more），活跃任务段恒全量。

## 10. 安全与凭据

- 沙箱：每任务一容器/microVM，镜像只读 + ephemeral 写盘，CPU/内存/墙钟限额；
- 网络：出向白名单（LLM 网关 / 图搜 / TTS / 对象存储），禁横向；多租户下 LLM 生成的 shell 命令**按不可信处理**——桌面版「可信脚本清单静默执行」前提不成立；
- 凭据：secret 管理统一注入，不落盘、不进日志；
- 合规：skill 包零修改分发，MIT 协议墙（attribution_guard）哈希校验云上照常成立；「内置 skill 不可改」从打包约束升级为镜像只读的物理事实。

## 11. 进度与可观测

- worker 内置 reporter：监听页文件出现 + 门禁状态 → 结构化事件回调控制面；
- 诊断：ppt-master 自带 `validation/workflow.log`（命令账本 JSONL）随快照留存，按 task 下载排查；
- 关键告警：租约过期回收率、回合失败率、预算耗尽转 paused 率、门禁平均等待时长。

## 12. 成本与商业化

- 门禁期零成本（worker 销毁）是结构性优势；
- per-task 预算（token + 墙钟 + 金额估算）→ 超限优雅收束转 paused → 加预算续跑计费；
- 租户配额：并发任务数 / 日任务数 / 页数上限；
- 存储生命周期：workspace 与产物终态 30 天转冷存，租户可手动提前清理。

## 13. 里程碑

| 阶段 | 内容 | 验收 |
|---|---|---|
| M0 可行性桩 | 单容器跑通 generate 全流程（门禁临时端口转发），证明 skill 云上可跑 | 真实任务产出可编辑 PPTX |
| M1 执行链 | 队列 worker + 快照协议 + 租约 + 回合编排 + 预算软着陆 | worker 被杀后任务自动恢复续跑 |

## 14. 风险与对策

| 风险 | 对策 |
|---|---|
| server 移植层随 ppt-master 升级漂移 | skill 版本按任务钉死；官方页面对移植后端的 E2E 契约测试进 CI；回执 schema 版本号写入五件套，worker 回合开始校验兼容 |
